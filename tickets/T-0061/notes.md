## 症状与归因（2026-09 用户实测）

进第一个 ADV 场景 → 存档 → 槽文件写出成功（SAVE70.DAT）→ 但**读档后停在存档界面**。

### 归因 ①：存档没有按引擎口径退栈
- 引擎写入内核 sub_40CD10 case 3（raw 17058-17065）：\10 = _this[166963]; if (v10 < 0) v10 = _this[95776];\
  —— \_this[166963]\ 就是 **0x1AD（\i1ad\，sub_4196F0 raw 24806：\storedCur = cur\）**。
- 脚本侧惯例：每个 ADV 脚本在进主循环前 \i1ad\（\src/\\.txt:44-46\：\call 场景初始化\ → \i1ad\ → \jmp 主循环\；
  语料 **1100 处 / 337 个脚本**）⇒ 玩家从**存档菜单**存盘时 \cur\ 是菜单帧、内存里那格仍是 ADV 帧
  ⇒ **引擎存的是 ADV 帧**（= 玩家说的『自动退栈』）。
- emulator 修前：\state.cur = e.cur\（菜单帧）+ 帧记录只写『有脚本的帧』（丢帧号）。
⇒ 读档把 \cur\ 还原成菜单帧。

- 引擎 sub_410160 的 a6=1 段（raw 19464-19476）：\Engine[383120] = 1\ + **\cur = 0\** + 装载存档记录的脚本
  ⇒ SAVE.BIN 那类界面脚本不会继续被派发。

用新增的槽分支 \
pm run save:dump -- <槽文件>\ 直接看用户存出来的槽（overlay 里那份 2,062,356 B）：

本工程状态块：cur=3 帧记录 14 条（key=0x0）
  帧 (无 index ⇒ 数组序): 0x0 SYSTEM4.BIN ip=372 / 0x5268 NOVEL.BIN ip=124 / 0x74 SN0000.BIN ip=443 返回栈 2 层
                          / 0x33 SAVE.BIN ip=828 返回栈 3 层 / … (共 14 条，含 8 个预装帧 ip=0)
  ★这是修 T-0061 之前写的槽：帧号/返回帧链缺失

- **\cur=3\ 正是 SAVE.BIN（存档菜单）那个帧** ⇒ 读档当然停在菜单上：归因①被用户自己的档证实。
- 真正该存的帧是列表里那条 **SN0000.BIN（ADV 场景，ip=443）** —— 也就是 \i1ad\ 记的那一帧。
- 帧记录还是**过滤过的**（只写有脚本的帧）⇒ 读侧按数组序归位必然整体错位（\SBUNKI\/\\\\ 这些预装帧被搬到别的帧号上）。
- 池：int=87318（Map 里的条目数）float=20 string=9345；游玩秒数=29。

⇒ 结论：**用户那份 SAVE70 是「旧代码 + 忽略 i1ad」的产物，属性上就无法正确续档**（\cur\ 指向菜单帧）。
修复后的版本存出来的槽会带 \cur=2\（SN0000）+ 每条帧记录的 \index\/\caller\ ⇒ 读档落回 ADV 场景。
旧档不必抢救：用新版本**重新存一次**即可（读旧档时也会打一行日志说明为什么落点不对）。
