# T-0185 · 调查笔记

## 1. 症状（首次尝试失败）

`.agents/skills/amayui-remote-debug/scripts/load-slot.mjs` 在**刚起来的实例**上第一次跑，经常在 ① 步失败：

```
✗ 点了 Load Data 但没进 SAVE.BIN          ← 20s 内 cur 没变成 SAVE.BIN（退出码 1）
```

而**原样再跑一次就成功**（同实例、同槽、同参数、无任何环境改动）。

### 实测记录（2026-09-26）

| # | 实例 | 槽 | 第 1 次 | 第 2 次 | 备注 |
|---|---|---|---|---|---|
| 1 | 新建实例（boot 到 TITLE 后 < 30s） | 78 | ✗ ① 步 20s 超时 | ✔ `[slot-load]` | 失败文案指向「槽为空/页码不对/目录不对」，三条都不是 |
| 2 | 同上（T-0182 取证） | 78 | ✗ ① 步 20s 超时 | ✔ `[slot-load]` | — |
| 3 | 同上（T-0103 轮 17/18 取证） | 78 | ✗ ① 步 20s 超时 | ✔ `[slot-load]` | — |

⇒ 3/3 都是「首跑失败、次跑成功」。**没有**一次是首跑成功的（样本小，但方向一致）。

## 2. 误导性在哪

失败文案（load-slot.mjs 第 169 行）把原因指向三类**用户侧**问题：

```
✗ 点了 Load Data 但没进 SAVE.BIN      ← 随后代码注释/日志把怀疑方向引到「槽为空？页码不对？槽文件不在实例可见目录？」
```

而这三类都不成立（第 2 次完全相同的操作为成功）⇒ 对 agent 来说，这条失败信息会把人送往错误的排查方向
（去查 `SAVE78.DAT` 是否 stage 进实例目录、页码是不是 `tens` 算错），浪费一轮往返。

## 3. 最可能的原因（待实测钉死）

首跑时实例刚 boot 完：标题画面还在**淡入/输入门未开**的阶段，第一次 `click Load Data` 落在动画中（或落在门未开的帧上）⇒ 点击被吞。
次跑时画面早已稳定 ⇒ 点击有效。**所以正确的修法未必是"盲重试"**：`debug-query` 已有 `wait`（等 `bin=TITLE` / `gate=free`），
点击前等就绪才是根因级修法；重试只是兜底（且必须只在首次尝试失败时发生一次）。

## 4. 判据（验收③）

重试路径要落盘：两次 `cur` + `frame`/`global` 读数 + 实例启动龄 ⇒ 若证据显示是「未就绪」，
就把「点击前等就绪」写进脚本与 `amayui-remote-debug` 技能（§5 坑 13），而不是把 flake 藏进重试里。
