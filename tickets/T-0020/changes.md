# T-0020 · 变更记录

## 第 1 次变更（2026-09-23）：**重新定义本票的落点** —— 从"全量统一"改为"基线棘轮 + 只许收敛"

### 1. 为什么改口径（读代码读出来的，不是拍脑袋）

本票原文写的是「`mk()` **17** 变体统一到 `test/harness.ts`」。实测现状：

| 项 | 现状 |
|---|---|
| 自造 `mk()` / `ctx` / `mkEngine()` / `makeCtx()` 的测试文件 | **42** 个（不是 17） |
| 自造帧循环（`clock += 1000/60` 或 `for (let f…` 那类） | **13** 个文件 |

而 `test/harness.ts` 的**文件头自己写着**：

> ★`test/` 里还有 17 处各自的 `mk()` 变体（**差异是真实需求**）⇒ 这个函数只服务**新增**的守卫，
> 不强行统一既有那些。

差异确实是真实需求：save 族要 `fsLike`、adv 族要 msgwin 桩、render 族要容器、opcode 族要假 handler……
**强行合并会把"差异"降级成隐藏参数**，可读性反而下降（这正是 `harness.ts` 当初的结论）。
⇒ 「逐文件迁移 42 个变体」既不该做、也不可能在本票内做完。

### 2. 那本票真正缺的是什么

**机械联系**。在此之前，"测试通过"与"产品路径一致"之间**没有任何守卫**：谁再抄一份 `mk()`、
谁再手搓一个帧循环，都不会有人知道。本票补的就是它。

### 3. 落地物

| 物 | 作用 |
|---|---|
| `test/harness-convergence.baseline.json` | 冻结现状：`mkVariants`（42 个文件）、`selfFrameLoops`（13 个文件） |
| `test/harnessScan.ts` | **扫描口径的唯一实现**（守卫与收缩入口共用，避免两处各写一份） |
| `test/harness-convergence.test.ts` | 守卫（3 例）：**新增即红**（并给出"改用 harness / 登记基线并写理由"两条出路）；基线只许收缩；基线登记的文件必须还在 |
| `npm run test:org -- --shrink-harness` | 收缩入口：把基线重算到当前现状（**只许收缩**由守卫反向断言把关） |
