## 轮 12 续：判据 4（「阿瓦罗的名字变青色，预期橘色」）—— 通道顺序**判死**

### 1. 引擎写入口的位运算，与 emulator 逐位等价

`src/vm/handlers/msgwin.ts:57` 的 `bgrToRgb` 注释逐字引了引擎那一行（`sub_466000` raw 79666）：

```
*(_DWORD *)(_this + 1360) = BYTE2(a5) + ((BYTE1(a5) + ((unsigned __int8)a5 << 8)) << 8);
```

令 `a5` 低三字节 = b0/b1/b2，右边 = `b2 + (b1<<8) + (b0<<16)`，即**把输入当 COLORREF
（`0x00BBGGRR`：b0=R、b1=G、b2=B）读，写成 `0xRRGGBB`**。emulator 的
`((v&0xff)<<16) | (((v>>8)&0xff)<<8) | ((v>>16)&0xff)` 与它**逐位相同**。
⇒ 通道顺序**不是**症状来源：同一次交换作用在整张调色板上。

为什么"正文看着正常、只有角色名偏"恰好符合这个结论：调色板前 4 条是白（`ffffff`），
而正文用的是**暖白/近似中性色**（T-0042 实测真机文字核心 (233,230,228)）——中性色交换前后
几乎无视觉差异；只有**饱和色**（角色名）才会一眼看出橘↔青。**若是通道错，正文也该偏。**

### 2. 调色板的青与橘，是**相邻的下标**

真机 `SAVE.DAT` 的 `adcd`（`LOADCONFIG.txt:34-49`：`for i in 0..0x3e8` 循环里
`lookup-array … adcd … i` + `load-int (local-ptr 0)` ⇒ 1000 条逐个从 overlay 读入）交换后：

| 下标 | 原值（BGR） | 渲染（交换后） |
|---|---|---|
| 0-3 | `ffffff` | `#FFFFFF` |
| **4** | `ffe100` | **`#00E1FF` 青** |
| **5** | `84b1ff` | **`#FFB184` 浅橘** |
| 6 | `dcdcc6` | `#C6DCDC` |
| **7** | `71d8ff` | **`#FFD871` 金橘** |
| 8 | `00d3c3` | `#C3D300` |
| 9 | `4dbf67` | `#67BF4D` 绿 |
| **10** | `2c9bdd` | **`#DD9B2C` 橘** |
| 11 | `d15e4b` | `#4B5ED1` 蓝紫 |
| 12 | `ff90b6` | `#B690FF` 紫（= 判据 3 的残留色） |

⇒ **青（下标 4）与橘（下标 5/7/10）在同一张真机调色板里相邻。** 「青 vs 橘」的候选因此是
**取了下标 4 还是下标 5/7/10**，即 `14acda`（角色号）的派生 —— 不是通道顺序。

### 2. H2 为什么不是"少画一帧"的小事

屏障（`PixiBackend.texturesIdle` → `TextureCache.waitIdle`）后面紧跟的可能不是"画一笔"，
而是 `0x208`（`sub_4302E0` 读纹理尺寸并**写回操作数**）这类 getter：在载入完成前放行 ⇒
脚本按 `0×0` 走**与引擎不同**的分支，而且**不会回头再看**（唯一的自愈是脚本再跑一次同一段
= 用户实测的"开合侧边栏才对"）。引擎的 `set-texture` 是同步的（`sub_422CB0` 当场读 AGF + 解码），
**压根没有"超时"这一说** ⇒ 500 ms 这个"兜底"才是分叉源。

### 3. 修法（把"静默截断"换成"显式兜底 + 可见的等待"）

- `textureCache.ts` 新增三个共享常量：`BARRIER_GIVEUP_MS = 30_000`（安全兜底，理由写给后人：
  冷启动读大 AGF 有实测超过 500 ms 的情形，30 s 覆盖得住、又能防 IPC 真死时挂死）、
  `BARRIER_WARN_MS = 1_000`、`BARRIER_POLL_MS = 64`。
- `waitIdle(timeoutMs?)`：**省略参数 = 安全兜底**（不再是 500 ms）；轮询粒度 64 ms，因此
  每秒能打一行 `纹理屏障仍在等待 …ms（在途 N 张：0x…）`；到上限时打 **★** 行并**点名在途 imgid**
  （`#inflightNames()`），同时写清"此刻读尺寸的操作数可能已按 0×0 分支"。
- `l2dTextures.waitIdle` 同一份语义（复用同一常量；L2D 纹理也是"新绑的贴图必须同帧可见"）。
- `pixiBackend.texturesIdle()` **不必改**（它本来就是无参调用 —— 改的是默认值）。
