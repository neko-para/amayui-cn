## 甲、白底（判据②）：取证结论 + 本批修复

### 甲-1 ★ADV 那块「半透明黑底」不是消息窗画的，是**脚本往纹理槽画的**（已确证）

- ADV 包装：`src/NOVEL.txt:44-55`
- `SC0000` 逐字同型：`src/SC0000.txt:1036-1047`（全库 `i20b 48` 共 **183** 处）

```
create-texture 48 500 2d0 0                 ← 1280×720 空白槽
i20b 48 0 0 500 2d0 ff 808080               ← 填 50% 灰、α=255
draw-texture 186a0 48 0 0 500 2d0 0 0       ← 层序 0x186A0 = 100000 贴出
```

叠在深色实景上 = 观感上的「半透明黑底」。⇒ **窗底色字段不是这条路**。

### 甲-2 ★两处争议点已用 `.lst` 定死（订正了我方注释）

| 项 | 结论 | 证据 |
|---|---|---|
| `sub_43B070` | **= `ddSetColor` / `SetColorKey`**（参 `8` = `DDCKEY_SRCBLT`），**不是填底色** | `.lst:97104` 起；错误串 `"関数：ddSetColor エラー：不正なsurface"`；尾调用 `mov eax,[ecx+74h]` = 表面 vtable+0x74 |
| 填面函数 | `sub_43E260` = **`ddFillSurface`** | `.lst:102245` 起；错误串 `ddFillSurface` |
| `Scene+1560` | **像素格式的 R/G/B 掩码**（`sub_43B260` 写 `0x00FF0000/0x0000FF00/0x000000FF` 到 `+1556/+1560/+1564`），**不是"窗底色缓存"** | `.lst:97339`；`sub_45D660` `.lst:153416` 的 `rep movsd 8` → 块内 +20 |

⇒ **引擎根本没有"窗自己的底色字段"**：`0x70`/`0x71` 落点里那个填面实参是掩码，不是颜色。
⇒ **我方两处注释是凭空点，本批已订正**：`app/amayui-emulator/src/vm/msgwin.ts` 的 `WinGeom.background`
（原写「← `sub_43B070`…用窗口底色填面」）与 `src/renderer/text/raster.ts` 的填面分支（原写「引擎 dd 路径
`ddFillSurface(surfaces[20+win], 底色)`」）。订正后两处都写明：**该字段恒 `null`、全 `src/` 无写入点，
分支是死码**；用户看到的那块底在槽路径上。

### 甲-3 ★本批修复：异步图像载入的**陈旧回写**（这是"刷新一下才对"的唯一可自证机制）

引擎的 `set-texture`(0x1F9) 是**同步**的（`sub_422CB0` 当场读 AGF + 解码）；重写侧走
`window.api.image()`（IPC + 主进程解码）**异步**。于是：

```
① set-texture X 48 （X 未缓存 ⇒ 发起异步载入）
② create-texture 48 + 0x20B 填色        ⇒ 屏上应当是②的表面
③ ①的载入完成 ⇒ 旧代码**无条件** slotTex.set(48, X) ⇒ 把②换掉
```

表现 = **该槽要的内容没上来，脚本"再跑一次"同一段（例如开合一次侧边栏）才正确** —— 与用户原话
「展开/收起侧边栏菜单似乎刷新了界面导致其正确变成了半透明黑色」**形状一致**。
（`waitIdle` 的帧屏障救不了它：屏障只保证"合成前载入完成"，而问题恰恰是"载入完成后把②换掉"。）

**修法**（`TextureCache`）：新增**槽表面世代** `#slotEpoch`（`create-texture` / `release-texture` 各 +1），
`bind` 的异步回写必须**同时**满足「世代未变」且「绑定仍是这次发起的那张图」才落盘；否则只进
`#imgCache`（下次绑定即命中）并记一条 `回写丢弃` 日志（E4 靠它归因）。
为可测性把解码口抽成 `protected decodeImage`（Node 里没有 `ImageData`/`createImageBitmap`/DOM，
这条竞态必须在合成对象上**确定性复现**，不能靠真界面偶发观察）。

**守卫** `app/amayui-emulator/test/texture-bind-race.test.ts`（5 条）：①基线（无干扰照常落盘）
②脚本随后 `create-texture` ⇒ 丢弃 ③槽被 `release` ⇒ 丢弃 ④改绑到别的 imgid ⇒ 乱序到达的旧图不得覆盖新图
⑤同一 imgid 绑两个槽互不干扰。
**辨别力已机械证明**：撤销判据（`.tmp/t0102/revert-bind-guard.mjs off`）⇒ ②③④ **红**（pass 2 / fail 3）；
还原 ⇒ 5/5 绿且 `textureCache.ts` **sha256 逐字节回到原值** `428754f0…`。

★**诚实标注**：这条修复的**证据强度 = 中**（机制确证、且是唯一能解释"刷新才对"的已知竞态），
但"用户那一次白底**就是**它"尚**未**由 E4 复验确认 ⇒ 本轮**不关单**，等用户复验（见丙）。
