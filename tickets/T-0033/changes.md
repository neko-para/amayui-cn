## 第 1 次变更（2026-09）：ADV 逐字期间的点击 ⇒ 立刻整页贴完（不推进、消费该次点击）

### 复现（真实语料 E3，`.tmp/t33-repro.mts`）

链路：GAME START → … → SN0000 首句（win8），逐帧跑到「逐字中」（`MessageSpeed=5` ⇒ 52 字约 0.87s），
在**热点外**点一次左键（避免走 labelC 派发，只测"贴完整页"这一半）：

| | 修前 | 修后 |
|---|---|---|
| 点击后 1 帧 `shown`（点前 0/52） | **1/52**（点击被忽略，文字继续一个个显） | **52/52（整页立刻贴完）** |
| `active` / `reveal8` | 1（还在逐字） | 0 |
| 12 帧后 ip / pages | ip 不变、仍在逐字 | ip 不变、pages 不变（点击被消费，没攒成推进） |
| 第二次点击后 | ip 917 → 1028（那次陈旧的点击在显完后被当成推进） | ip 917 → 1028（**这才是**推进） |
| bit30（▼） | 1 | **1**（贴完不清 bit30 —— 引擎用普通泵，不是 `sub_45A940(..., -2, 0)`） |

即：修前"逐字期间的点击"要么被吞、要么攒到显完之后变成推进；修后与引擎一致 ——
**点一下贴完整页、再点一下才推进、第三下跳过下一句的逐字**。

### 定因（引擎真值）

1. 主循环分支顺序（raw 21176-21181）：`if (v35 & 0x20000000) { sub_409400(); … }` —— **逐字期间文本泵每帧被调**，
   且这一支不派发脚本；等待泵 `sub_411BC0`（`v35 < 0` 那支）此时**不会**被调。
2. 文本泵 `sub_409400` 的第二半（raw 13931-13946）就是**逐字期间的输入出口**：
   消费刷取掩码 → 左键 `mask & 0x10`（**只认左键**，等待泵才是 `0x50`）/滚轮键位命中/滚轮累加器下滚
   ⇒ 清 `0x20000000`、置 `Engine[388212] = 1`、`do sub_45BE20(Font, 当前窗) while (!完成)` **自旋到整页贴完**，
   并把掩码清 0（**这次点击被消费**）；**不清 bit31**（等待门仍在 ⇒ 页不推进）、**不动 bit30**（▼ 继续闪）。
   `Engine[388212]` 在下一次调用里还会顺带清等待门计时器 + 置强制冻结（raw 13910-13915，条件 `DrawMode == 1`）。
3. emulator 缺陷：帧驱动把 `textRevealing` 分支排在推进分支之前，而 `serviceTextReveal` **完全不看输入**
   ⇒ 逐字期间既不贴完也不消费 ⇒ 点击留在输入边沿里，等文字自然显完后被等待泵当成推进。
   直接把等待泵接上去也不对：它在派发前会 `finishCharReveal()`（清 bit30）**并继续派发** —— 一次点击干两件事。
