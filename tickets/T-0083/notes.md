## ★2026-09 轮 5：按**源码**判定（用户要求：不依赖真机表现）

**问题**：装载点之后，上一个画面那些绘制项在引擎里到底还在不在？（`ownerFrame` 近似该不该留）

**判定（全部以体为准，锚点已核）**

1. **装载点不清任何绘制容器**：`sub_410160` 的 27 个 callee 里没有任何清容器调用；唯一的整批释放是 raw 19378-19389 的两段**配置门**（`Get(set:CreateObject)&2` / `&2`），而引擎默认 `set:CreateObject=1`、`set:AutoFreeTexture=0`（raw 111733/111742）⇒ **两段都不执行**。
2. **唯一"整层消失"的机制 = 复位两个「仮想ディスプレイ」容器**：raw 19913-19915 各一次 `sub_403EF0`，体（raw 9958-9971）= `_this[258]=0`（`+0x408`=1032 的项数/表头）+ `_this[959]=-1` + `[960]=0` + `[7464]/[7466]/[7467]/[7468]`。两个容器基址 = **`Engine+51904`** 与 **`Engine+21976`**（已登记第一层：`Engine 0xCAC0 virtual_display_a` / `0x55D8 virtual_display_b`）⇒ **只有注册在那两个容器里的项**会消失；**主 Scene（`Engine+80708`）的项不受装载点影响**。
3. **主 Scene 的项由脚本自己按显式 handle 区间删**：`CALLBACK_LOAD.BIN`（装载点回调，raw 19916）逐条是 —— `i19b`（ADV 退出）→ `i20d -1`（渲染目标回后台缓冲）→ **`detach-texture 1adb0 7d0`**（立绘层）→ `i244`（清转场记录表）→ `detach-texture 19640 2` + **`detach-texture 19834 19`** → `call-script 51c3 // LOADCHARM`（只做 `load-int` ×9：把存档里的 9 个全局读回）→ `call-script 46 // DRAWCHARM`（**重建**那批项）→ `label_00001248`：`detach-texture 19708 6` + 按需重建（侧栏）。
4. **`DRAWCHARM.BIN` 的坐标算法与读档后模型逐项吻合**（这排除了一条怀疑）：`draw-texture <0x19834+k> 0x11 (0x350+行*0x52) (0x31A+列*0x31) 50 2f 49c (0x72+i*0x32)`（行=(v-1)/10、列=(v-1)%10、v=表 `global 13b0[i]`）⇒ 落点 `x=0x49C=1180`、`y=114+50i`、尺寸 `0x50×0x2F`；而读档后模型里正是 `pos=[1180,114/164/…]`、`src=[848,794,80,47]…`。
   ⇒ **那 25 片是"右侧栏 charm 面板"，几何正确**（不是背景，也不是错乱源）。它们的存在恰好证明"`CALLBACK_LOAD`+`LOADCHARM`+`DRAWCHARM` 这条重建链在 emulator 里是对的"。

**⇒ 结论（改写了本票的提法）**

- emulator 的 `ownerFrame`（丢"被放弃调用链画的项"）在引擎里**没有对应物**：引擎的去留规则是「**容器归属**（两个仮想ディスプレイ在装载点复位）+ **脚本显式 `detach-texture` 区间**」。所以"祖先帧的项该不该在"这个提法要换成"**它在哪个容器里 / 有没有被脚本 detach 掉**"。
- **TITLE 的项（`TITLE.txt` 里成片的 `draw-texture 6e/c8/12c…`，即层 110..119/200..241/300..308）不在 `CALLBACK_LOAD` 的四个 detach 区间内** ⇒ 若它们在主 Scene，**引擎也会留着它们**；它们在真机上不显眼只能是因为**层序上被后画的项盖住**（引擎按 key 升序画；SN0000 的项 key 大得多）。
- ⇒ **下一个源码问题不是"丢哪些项"，而是"SN0000 该拿什么盖住它们"**：即续跑后（落点 ip 794）**SN0000 自己的背景项有没有出画、在什么 key 上**。这是可判定的（读 SN0000 的 737-794 段 + 落点之后的路径），也是下面"下一步"的第一条。

**下一步（源码级，按顺序）**

1. 读出**两个仮想ディスプレイ容器装的是谁画的项**（哪条 opcode / 哪个脚本段）：从「谁往 `+1032` 插项」入手（`sub_40C910`/`sub_40C310` 的调用者 + `sub_404E20` 的 UI 元素派发链）。定了之后 emulator 可以把 `ownerFrame` 换成**真容器归属**。
