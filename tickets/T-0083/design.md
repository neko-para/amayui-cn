## 2026-09-19（目标轮 25）冷启动 vs 热启动：把 `T-0066` 的因果缩小到可判定的两种情形

b5E 的实拍里，除了 `TITLE.BIN` 那层（51 项 / 25 可绘制），还有一块**橄榄灰的大矩形**和几块橙色调的板。
对着 `NOVEL.txt` 的体看，它们恰好是**引擎自己的"没有缓存图"分支**：`NOVEL.txt:42-55`
```text
sub (local-int 0) 30d40 18a88 ; detach-texture 18a88 (local-int 0)
jcc (global-int 708ad6) label_0000043c      ; 有缓存 ⇒ 直接跳过整段
jcc (global-int 708ada) label_00000398
set-texture (global-int 708ada) 48 (local-int 0)      ; 有图 id ⇒ set-texture 48
jmp label_000003f8
label_00000398: create-texture 48 500 2d0 0 ; i20b 48 0 0 500 2d0 ff 808080   ; ★否则：建 1280×720 空纹理 + 填 #808080
label_000003f8: draw-texture 186a0 48 0 0 500 2d0 0 0                        ; 再把它画成满屏背景项
```
而 `global 708ada`/`708ad6` 是**池外下标**（`tickets/T-0071`：实测 7,375,578 / 1,018,952，而真槽的 int 池
只有 1,015,792 项）⇒ **槽里根本存不下它们**。于是：
- **冷启动读档**（从 TITLE 进来，本会话的 `shot --load 79` 就是这条）：进程里那两个全局是 0 ⇒ 引擎走
  `create-texture + i20b #808080` 分支 ⇒ 画出来的一块**灰色占位背景**是**引擎行为**，不是我们的 bug
  （b5E 里那块橄榄灰板正是它）；`TITLE` 那层在引擎里被这块满屏占位盖住，而 emulator 这条路的层序/平面
  关系还没建模 ⇒ 露出 TITLE。
- **热启动读档**（在 SN0000 里存档 → 就地从菜单读档）：全局有值 + `set-texture 48 <背景 id>` + **上一屏
  留下的绘制项**（我们 (B) 步保留的那条链之外的祖先层）指向刚被 ②b 重建的槽 ⇒ 引擎与 emulator 都应该
  直接给出正确背景 —— 这正是 (B)/(C) 已经锁住的那条路。

⇒ **可判定的下一步**（不需要平面模型就能分出对错）：
1. 请在真界面里走**热路径**复验：进 SN0000 首句 → 打开菜单存档 → 从菜单里读回该槽。若画面正确，
   说明 (A)(B)(C) 已经解决了用户可见的读档画面问题，剩下的只是冷启动时"占位背景盖不住 TITLE 层"
   （= 平面/层序模型，`T-0066`）。
2. 若热路径也不对，则问题在"祖先层的项是否真的被保留"（(C) 的 A/B 守卫只覆盖了合成脚本，没有覆盖
   `NOVEL`/`SN0000` 这条真脚本链）——下一轮就把 (C) 的 A/B 守卫换成**真脚本**版本（同一份 SN0000：
   正常跑到第 794 句 vs 从槽 79 读档到它，比较 drawItems/msgWins/texSlots）。
