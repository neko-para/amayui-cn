## 轮 9：第三批迁移（字符串核心族 9 + 字符串表族 4）与"白名单该不该留"的机械判据

### 1. 计划层补了一个真缺口：`index(n)`

字符串表族（`0x1A2` save-int / `0x1A3` load-int / `0x1A9` save-string / `0x1AA` load-string）
的操作数**不是当值用，是当槽号用**（引擎 `sub_418A30(n)` / `sub_418AE0(n)`，键 =
`wsprintfA("%c%8.8x", 哨兵, idx)`）。计划层原来只有 `int/float/str/ptr`（都读**槽里的值**），
所以这四条此前根本没法纳入计划层。

⇒ 新增访问器 **`index(n)`**：读**槽号本身**。`int(n)` 与 `index(n)` 的区别是本质的，
注释里写明了（`load-int` 用的正是"读槽号作键 → 把值写回同一个槽"⇒ 方向是 `rw`）。

### 3. 白名单那 9 条：不是陈旧条目，是**承重**条目 —— 现在撤掉了承重物

判据 1 要"白名单里其余条目逐条核体"。本批核到 9 条（`0x192/0x193/0x1a9/0x1aa/0x2c7/0x2c8/0x1b2/0x1c8/0x2eb`）

`{type:0x9}`（int 本地槽）造实参，而这些指令会调 `writeStringOperand` ⇒ **直接抛**
"dest 非字符串型" ⇒ 那一格永远算"没被碰" ⇒ 只能豁免。

`0x192：writeStringOperand: dest 非字符串型 0x9 for opcode 0x192`（0x193/0x1c8/0x2c7/0x2c8 同）

★这条判据以后可以复用：**白名单条目要能说出"哪一行守卫输入逼得它必须豁免"**；
说得出的是承重条目（要么改守卫输入、要么留着并写明），说不出的才是该删的陈旧条目。

## 轮 18：控制流 + 队列族 **15 条**（205 条计划）+ 守卫第 4 次输入质量修正（两遍合成执行）

### 1. 先结清 round 17 留下的**label 口径**疑点（用证据，不靠猜）

疑点：控制流的 label 操作数是否走 `operandArg().raw`（label 表按原始值索引），
若如此则计划层 `int()`（DEC 解码后的值）会**静默改语义**。核过的结论：

- `0x8C` jmp：`const t = readIntOperand(..., 1); if (t === -1) return; labelPos(frame, t)`
  ⇒ 用的就是 `readIntOperand`，哨兵是**解码后**的 `-1`；
- `0xA0` jcc：注释写明"分支目标(2/3)也经 `readIntOperand` 取值（**可为变量 label**）"
  ⇒ 变量 label 存的是 ENC 过的值，**必须解码**；
- `0x8F` call：原来用 `operandArg(c.instr, 1).raw` 判 `0xFFFFFFFF` 哨兵 —— 立即数时与解码等价，
  但变量 label 时 `.raw` 是错的 ⇒ **本批顺带订正**成计划层读取（哨兵统一为 `-1`，与 jmp 同口径）。

⇒ 计划层 `int(n)` 就是控制流 label 的正确读法，本族**不需要** raw 访问器，也不用策略排除。

### 2. `0x1a7`（comment）按策略排除

它的体就是 nop，且 handler 是**零参数**（`() => undefined`）⇒ "计划声明它读 op1"与现实不符
（该条本来就在 `opcode-operands` 的白名单里写着"引擎体就是 nop"）。与 A 类（engine-internal）同性质：
**引擎不消费操作数**的条目不进计划层。本批 15 条 = 16 条 backlog 减去它。

### 3. 守卫第 4 次"输入质量"修正：**两遍合成执行**

「计划 ⟷ 实现」本轮点名 `0xa0 计划声明要读的位 2 没被碰` —— 不是实现错，而是 `jcc` 是
**按值分支读**：条件为假只读 op3（假分支 label）、为真只读 op2（真分支 label）
⇒ **单遍合成输入必然漏一支**。

修法：把合成执行做**两遍**（各 int 槽先 seed 0、再 seed 1），并集"碰过的位"。
判据**不放松**（声明的读位仍须全被碰），而"按值分支"这一整类都自动覆盖
（包括选择器 0 非法 / 1 合法的配置族，那条在另一守卫里还留着豁免条目）。

★守卫输入的 4 次修正，已经是同一主题的反复出现：
① `str` 位要给字符串实参；② `ptr` 位要初始化引用槽；③ 合成输入的**合法抛错**只忽略异常；
④ **按值分支**要两遍 seed。都记在 notes 的"迁移常规流程"里。

### 4. 迁移器又踩一个坑（补进流程说明）

`op_dev_ukn` 是**表达式体**的箭头函数（`= () => undefined;`，没有 `{}`）⇒ 括号配平扫描器
从"下一个 `{`"开始找，结果**吃进了后面的 class 体**，插出一行非法的 `const plan = …`。
症状是 `TS1248 A class member cannot have the 'const' keyword`。
⇒ 迁移器规则加一条：**跳过表达式体（无花括号）/ 零参数 handler**，这类手工处理。

- **`0x308`**（输入触摸注册）：引擎读 op1 调 `sub_407B20`；emulator 是 `op_stub_unhandled` 桩
  （白名单原话"op1/Engine[1954] 未建模"）。
⇒ 加上 `0x33F`（混合/效果通路未建模），C = 3。**这三条都不是"实现偷懒"，是"引擎有通路、我们还没建"**
—— 已在票里留了回链（`0x33F`→T-0017；`0x308`→输入子系统；`0x14D`→AGERC 宿主缝）。

### 3. 守卫又一次点名 → 修好一处**读序**问题

`0x14C`（set-agerc-export）：handler 原来**先读 op2 再校验**，而"模块未加载"会在读到 op1 之前**抛错**
⇒ 合成指令下 op1 永远读不到，守卫如实点名 `0x14C 计划声明要读的位 1 没被碰`。
修法 = **按引擎顺序把操作数读满再校验**（引擎每个 handler 体开头 `sub_41BF50` ×N）。
这已是第三次同类修正（`0x1C9` 音频、`0x1A0` 读槽头、本轮 `0x14C`）⇒ 纪律一句话：
**读是纯的，必须发生在任何分支/抛错之前。**

另外：`0x2DA` 的 op2..op8 由 `for (let k = 2; k <= 8; k++)` **循环读**，机械形状提取器误判成"只读 op1"
（同 `0x73`/`0x90`/`0x25C`）⇒ 又一次印证"**形状不能只看正则，关键条目要读体**"。

### 4. `0x1A7` 从"策略排除"退回"可声明"

体是 nop ⇒ op1 用 `unused` 如实声明（handler 零参数、不读任何位，与判据一致）。
与上批的 `0x1A1` 一样：**模型变丰富（`unused` 方向）后，排除面自然缩小**。
