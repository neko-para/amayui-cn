## 1. 主循环里 `0x400` 分支的真身（raw 21109-21153）

```c
if ( (v35 & 0x400) == 0 ) break;                                  // 21109  位没置 ⇒ 不重要
if ( sub_407E20((_DWORD *)(_this + 322832)) || v95 ) {            // 21111  池挂起 || 影片标志
   ... if (输入命中/滚轮) {                                        // 21113-21129
        *(_DWORD *)(_this + 699204) &= ~0x400u;                   // 21134  ★玩家可跳过：清门
        sub_407EA0(_this + 322832);                               // 21135  置强制冻结 46512=1
        sub_4B4040(...); sub_4B51E0(...); sub_4BBA90(...); ...     // 21136-21146 立即 present/刷队列
   }
   goto LABEL_186;                                                // 21149  否则本帧什么都不派发
}
*(_DWORD *)(_this + 699204) &= ~0x400u;                            // 21151  ★池不挂起 ⇒ 清门放行
Sleep(0);
```

要点：
1. **门是"引擎自己每帧轮询"的**，不是"动画回调"；`0x21C` 只负责置位（`sub_41A260` raw 25290：`_this[174801] |= 0x400`）。
2. 放行条件 = `sub_407E20(pool) == 0 && v95 == 0`（`v95` = 影片/播放标志）。
3. ★**玩家输入可以直接跳过门**（21113-21135）：清位并置 `46512 = 1`（强制冻结）后立刻 present。
   emulator 目前**没有**这条路径（等待期间点键无效）—— 一并登记在本单。

## 2. `sub_407E20` = 池挂起位 + 等待计时器（raw 12762-12786）

```c
int __thiscall sub_407E20(_DWORD *_this) {      // _this = 池基 322832
  v1 = _this[11631];                            // 时长（字节 322832+46524 = 369356）
  if ( !v1 ) goto LABEL_7;                      // 没装计时器 ⇒ 直接看挂起位
  v2 = _this[11630] == 0;                       // 起点（369352）为 0 = 未起步
  result = 1;  _this[11627] = 1;
  if ( v2 ) _this[11630] = _this[11625];        // 起步：起点 ← 现在（11625 = 字节 369332 = Engine[92333] = timeGetTime()）
  if ( 现在 > 起点 + 时长 || _this[11628] == 1 ) {   // 11628 = 369344 = 强制结束
     _this[11630] = 0; _this[11631] = 0;        // 计时器到期（清零后下次不再生效）
LABEL_7:
     return _this[11629];                       // 挂起位（369348；= 引擎基 46516）
  }
  return 1;                                     // ★计时器未到点 ⇒ 一律"还在等"
}
```

- `369348 = 322832 + 46516` ⇒ **"池挂起位"就是 draw pass 里那个 `46516`**：
  - 每帧 present 开头清零（raw 130421-130434 的重置块，含 130428 `46516 = 0`）；
  - 绘制中若某元素还有窗在跑就置 1（raw 134944；同类还有 136695 / 136701）；
  - ⇒ 它是**逐帧瞬时**量（"上一遍绘制时还有东西在动"），不是"某个窗跑完才清"。
- 计时器两格 `369352`(起点) / `369356`(时长)。

## 3. 谁装载计时器 = `0x238`（这才是"等几秒"的来源）

`0x238`（`sub_4248C0` raw 32303-32312）只有两条写：

```c
*(_DWORD *)(_this + 92338) = 0;        // 起点清零（= 字节 369352）
*(_DWORD *)(_this + 92339) = op1;      // 时长   （= 字节 369356）
```

即 **`i238 N` 后紧跟 `wait`（`0x21C`）= "等 N 毫秒"**。语料统计（`src/*.txt`）支持这一点：

| `i238` 取值 | 十进制 | 出现次数 |
|---|---|---|
| `64` | 100 | 672 |
| `7d0` | 2000 | 286 |
| `3e8` | 1000 | 179 |
| `9c4` | 2500 | 138 |
| `320` | 800 | 118 |
| `4b0` | 1200 | 89 |
| `bb8` | 3000 | 42 |
| `1f4` | 500 | 34 |

全是整毫秒；"画布尺寸"不会有这种分布（也不会 2056 处都紧跟 `wait`）。
旧文档 `copyright-effect.md` 里"0x400 等待 ~5s 静态显示的精确时长驱动者**尚未收敛**"这一项，
**就是缺了这个计时器**。

## 4. 为什么"把 5 个窗都算进门"是错的（实测）

`src/SN0000.txt:1043`（`wait` 在 `:1048`）：

```
1043: i220 (global-int f8023) 0 13880 (local-int 0) (local-int 1) 0
```

`0x220` = 平移动画窗（`sub_423DE0` raw 31889；op2=delay、**op3=dur**）⇒ 背景 `101000` 拿到
**dur = 0x13880 = 80 000 ms** 的平移窗（位移 y=+1，典型的"整场慢推"）——它显然**不是**脚本想等的东西。

E4 A/B（`.tmp/t8-ab.mjs`，同一份 `emulator.config.json`，src 文件按字节还原/还原后校验）：

| | before = HEAD | 5 窗门口径（错误） | 拆开判据后（现状） |
|---|---|---|---|
| `gate 0x400 cleared` | 11 | 3 | 11 |
| 结局 | 进 SN0000 正文（`[reveal] …/58` 连续推进） | `wait=0x400` 连 20 s 不动、`0x19258:255/#000000` 三帧完全一致 | 进 SN0000 正文（316 行 `[reveal]`，末 31/58） |

⇒ **门不得扫所有窗**（至少平移窗必须排除）。至于颜色/缩放/旋转/flipbook 各自该不该算，
本单不靠猜：按 §2-§3 的计时器 + 瞬时挂起位语义实现，"等几秒"交给 `i238`。

## 5. 实现建议（给动手的那一轮）

1. `Engine` 增两格：`gateWaitStart`（对应 92338）、`gateWaitMs`（对应 92339）；
   `op_set_canvas_size`（`gfx-state.ts`）改成写它们，并把名字/注释订正为"等待计时器"。
2. `0x21C wait` 不动（仍是 `waitFlags |= 0x400`）。
3. 门放行条件改成引擎式：
   `sub_407E20 = (gateWaitMs > 0) ? (now > gateWaitStart + gateWaitMs ? pending : true) : pending`，
   其中 `pending` = "上一遍合成时还有元素在动"（逐帧瞬时量）⇒ 用 `scAnimationsPending(clock)` 的
   **上一帧结果**即可，不要在门里现算。
4. 顺手补 21113-21135 的"**点键跳过门**"（清门 + 置强制冻结位，冻结位语义 = 让所有窗立刻算"已结束"）。
5. 判据：① `i238 N` + `wait` 的驻留 ≈ N ms（headless 虚拟钟可断言）；② 80 000 ms 平移窗不影响放行时刻；
   ③ E4 目视版权页/序章的停留时长与 `i238` 一致。

## 6. 实现记录与残余缺口（2026-09 落地）

### 6.1 落地的四件事（逐条对 §5 的建议）

1. `Engine` 增四格：`gateWaitStart`/`gateWaitMs`（= `Scene+46520/46524` = `Engine[92338]/[92339]`）、
   `scenePending`（池挂起位 `46516`）、`sceneFreeze`（强制冻结 `46512`）；方法 `gatePending`（= `sub_407E20` 逐行）、
   `serviceWaitGate`（主循环 raw 21109-21152 的门）、`skipWaitGate`（= `sub_407EA0`）。
2. `0x238` handler 由 `op_set_canvas_size` 改名 `op_load_wait_timer`：写上面两格（`engineValues` 里同两格照旧写）。
3. 门判据**不再有"扫几个窗"的口径**：驱动在每帧 `advanceModel` 之后锁存
   `e.scenePending = !e.sceneFreeze && host.poolPending()`（宿主报 `scPoolPending`），随后按 raw 130427 清冻结位；
   门 = 本位 + 计时器。旧的 `scGateAnimationsDone`（"只看窗 0"）**已删除**。
4. ★**80 000 ms 慢推不钉住门的真正原因**（本单最重要的订正）：不是"门不看平移窗"，而是脚本
   `src/SN0000.txt:1045` 的 **`i242 f8023 1`**（`DrawItem+720` bit0）把那一项**排除出池挂起位**
   （`sub_49AA30` raw 117843-117844）；同一格还让它豁免"跳过"的强制冻结（raw 117440-117442）。

### 6.2 E3 实测（真实语料 GAME START 链路；`runGameStartChain` 新增的 `gateWaits` 观测）

```
LOGO.BIN:41       timer=0     waited=5000      ← 版权页 5 s：由 LOGO.txt:44 的 mesh 颜色窗（delay 4500 + dur 500）
TITLE.BIN:564     timer=0     waited=800
```

⇒ ① **凡是装了 `i238` 的门，「驻留 == 脚本值」逐条成立**（5500/100/2000/200 ms，帧粒度下正好相等）；
② 序章那道 100 ms 的门旁边就是 80 000 ms 慢推，说明慢推确实不参与；
③ 版权页的 ~5 s 与计时器无关（`timer=0`，是 mesh 颜色窗）—— §3 里"旧文档的 ~5 s 就是缺这个计时器"这句**不成立**，
   两者是并存的两条机制（本页 §4 的 A/B 表说的"门不得扫所有窗"因此也只对了一半：正确的说法是"被 `i242` 排除的项不算"）。

### 6.3 仍未建模（缺口，不许沉默）

1. `Scene+46516` 另有置位来源：立即变换 setter（`sub_49A870`/`sub_49A9C0`/`sub_49A8E0` raw 117177/117234/117215）

   emulator 只按"窗是否在跑"推本位（几何口径）⇒ 这些场景下门可能**早放行一遍绘制**（≤1 帧）。

4. **门等待期间玩家输入跳过**（raw 21113-21135：命中/滚轮 + `Config("System:EffectSkip…")` 门 ⇒ 清 `0x400`
   + `sub_407EA0` + 刷 present）：`skipWaitGate()` 已就位，但**输入判定没接** ⇒ 等待期间点键仍然无效

5. 冻结的"绘制期收尾"（raw 134941/135806/136182 的 `|| freeze==1`）与 `+720` 的冻结豁免没有作用在窗状态上，
   只折进了池挂起位的锁存（后果是冻结后窗仍在跑 ⇒ 继续合成，不是逻辑错误）。
