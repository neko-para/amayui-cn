### 5.3 真缺口与落地改动（按文件给出）

**G1 — `46512` 冻结没有传进窗模型（唯一的功能性缺口）**

* 引擎：冻结 ⇒ 转场窗立刻收尾（134941/135806/136182）、绘制项窗立刻收尾（117449 `|| v112 == 1`）、mesh 窗立刻收尾（133517 `< … && !v5`）、等待计时器立刻到期（12776）。
* emulator：`sceneFreeze` 只在 `gatePending`（`vm/engine.ts:549`）与帧末锁存（`frame/loop.ts:367`）被用；**窗模型完全看不到它**：`scAdvance(s, clock)`（`ops.ts:717`）、`scAnimationsPending`（`:743`）、`scTransitionTick(s, clock)`（`transition.ts:545`，其中 `scTransitionWindow(rec, clock, rt.start, false)` 第 4 参 `immediateFinish` **硬编码 false**，`transition.ts:557`）。
* 后果：玩家跳过等待门（或 ADV 每帧）后，引擎会让所有窗**当帧跳到终态**并让池挂起归零；emulator 里窗继续按墙钟跑完（画面差异 + `needsRender` 多亮若干帧；因为 `sceneFreeze` 同帧被 `loop.ts:368` 清掉，根本没有机会传到窗）。
* 改动（最小缝，四处同步 + 两宿主）：
  1. `frame/host.ts`：`advanceModel?(nowMs: number, opts?: { freeze?: boolean }): void;`
  2. `frame/loop.ts:362`：`host.advanceModel?.(nowMs, { freeze: e.sceneFreeze });`
  3. 共享层：`scAdvance(s, clock, freeze = false)`、`scAnimationsPending(s, clock, freeze = false)`（freeze ⇒ 直接返回 false）、`scTransitionTick(s, clock, freeze = false)` → 把 `freeze` 透给 `scTransitionWindow` 的第 4 参（函数已支持）。
  4. 两宿主：`headlessScene.ts:746-754`、`pixiBackend.ts:1300-1318` 接 opts 并转发。
* 守卫（场景级不变量，E2）：在 `test/wait-gate-timer.test.ts` 里加"先起一个 3000 ms 的窗 → `skipWaitGate()` → 同一帧 `advanceModel(now, {freeze:true})` 后：`poolPending()===false`、`scAnimationsPending===false`、`scTransitionsPending===false`、取快照后 `needsRender()===false`；并且窗的 work 值 = 目标值"。
  * E3 加档（真语料）：`SN0000` 的 `i238 64` + `wait` + 键跳过路径（`src/SN0000.txt:1043-1048` 那条）——合成指令层已有 `0x400`/`0x238` 的守卫，可直接扩。

**G2 — 转场表清空的门错位（`46516 == 0` 被实现成"没有活动转场"）**

* 引擎 136840 / 137181：`if ( Scene+46516 == 0 ) sub_4A9BE0(Scene+1048);` —— `46516` 是**全场景**的池挂起位（含绘制项/mesh 窗 + 离屏槽占用，136695/136701）。
* emulator `transition.ts:574`：`if (r4.transitions.size > 0 && active.length === 0) { clear }` —— 只看转场自己。
* 后果：转场到期那一帧若**别的**动画窗仍在途，引擎会保留死记录再多过一遍，emulator 立刻清表。可见差异极小（死记录惰性、下次同 id 写入会把 `[1]` 重写为 0 重新锁存），但这是"两宿主/两实现的判据分叉"，属于本项目最忌讳的那类漂移。
* 改法：`scTransitionTick(s, clock, freeze)` 里把 `active.length === 0` 改成 `active.length === 0 && !scPoolPending(s, clock)`（注意调用次序：应在 `scAdvance` 之后，与驱动一致）。
* 守卫（E2）：`test/sc-transition-window.test.ts` 加例：转场（dur 100）+ 一个 1000 ms 的 mesh 窗 ⇒ 转场到期那帧**表不能清**，mesh 窗结束后下一帧才清。

**G3 — 帧末回置 `46508` 的"逐字"选项（可选，非必须）**

* 若要与引擎逐字对齐，可在共享层提供 `scFrameEnd(s, clock)`：`if (sceneFreeze || scPoolPending(s, clock)) s.dirty = true;`，并由两宿主在 `advanceModel` 末尾调用。**但**这与 G1/G2 修好后的 `sceneNeedsRender` 三项是重复语义（一个置脏、一个即时求值），二者并存会让"取快照即消费"的棘轮（`headless-needs-render.test.ts`）难以表述。
