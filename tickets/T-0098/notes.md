### 轮 8 追加：`0x308` 的**体证据**（来自 T-0100 诊断；待你裁定并入与否）

主 agent 之前问过你「那条 `unhandled 0x308` 要不要并入本票（GUI 可见 + 硬中断）」。现在有体证据了：

- **体**：`0x308` = `sub_426B20`（raw 12579-12618 / 相邻 33808-33815）：调用 `RegisterTouchWindow` / `UnregisterTouchWindow`（`USER32.DLL`，含 `LoadLibrary`+`GetProcAddress` 形态），并写 `_this[1954]`（raw **12605/12610/12615** 三处写，**全库 0 处读**）。
- ⇒ 它对 VM/画面**不可观测**（`_this[1954]` 无读者；触摸窗口是 OS 级设施，emulator 无窗口触摸子系统）⇒ 属**「缺消费端」的有据 no-op 候选**，与 `0x10c`（VK→掩码位表）/`0x30a`（键位注册）同族。
- **现状**：它现在是 `STUB_NATIVE_OPS` 的 unhandled 桩，命中时**只打一行 `unhandled 0x308` 日志**（用户实测日志 7968 就是它），既不算"有据 no-op"、也不算"未实现"⇒ 台账口径上是个灰区。
- **我的建议（待你点头）**：把它**登记为 `engine-internal` 有据 no-op**（写清「USER32 触摸窗口 + `_this[1954]` 3 写 0 读 ⇒ 无消费者」，并在 `opcode-table.md` 补一行），这样缺口台账与 `STUB_NATIVE_OPS` 的口径就一致了；**不必**为它做"控制面板 + 硬中断"（那条裁定适用的是 `0x107`/`0x10B`/`0xFE` 的**越界位号**，不是本条）。
- ★注意：`opcode-table.md` 目前**没有 `0x308` 的行**（诊断报告 §7④ 也提到 `0xDD` 缺行）—— 若采纳，要同时补表行。
