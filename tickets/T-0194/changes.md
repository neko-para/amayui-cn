## 3. 独立审计的四条结论（`evidence/A4-dispatch-sites.md`，只读 raw）

1. 配置 getter（`Engine+697620` vtable[1] = `sub_4904D0`，raw 110691-110701）**对缺失键返回 0**（`sub_428E00` 未命中 ⇒ `return 0`）；该键本来就不缺（构造期注入默认 0 = raw 111541-111543；真机 INI `…/Eushully/天結いキャッスルマイスター.overlay/SYS4REG.INI` 里有 `ControlDisibleCursor=0`）⇒ **20247 / 20336 确实会调 `sub_4051A0`**。
2. **没有任何站点能同时满足「清 bit31 / 派 ENTER label / 不清 bit30」**：raw 里每条清 bit31 的路径都在同路径上清/零 bit30（13731→13734-13738、14004 / 17959 / 18983 / 20370 / 20873 / 43688 整字零、20197→20198、20250 前置 20247、20276→20282 内联、20334→20336、20432→20433、24510 整字零）；唯二例外是**整字恢复**类（`0x05 ret` raw 25718-25723 从 `Engine+429732` 弹回、`0x7C` raw 25810）。
3. ★**清 bit30 不写格节拍计时器**：`Engine+430600` 的 `[2]/[5]` 只由 `sub_453A90`/`sub_453A60` 写（调用点 28553 / 29339 / 28620 / 33362），清位只是让 raw 20887 的跳动闸门短暂为假，`sub_453AF0` 用**绝对时间差**判拍 ⇒ 那一拍只是**晚到**，相位与 `[2]/[5]` 不动。⇒ 「计时器没回落 + 格号相位连续」与「`sub_4051A0` 跑过」**完全相容**。
4. `i093` 全语料 4954 处，只有 668 处在 `i090` 的 ENTER label 里（其余在普通流程/CLICK label，如 `SN0000:209/230`）⇒「`Engine[12957]`(shown) 1→0 ⇒ 一定是悬停 ENTER 派发」这条推断**不成立**。

⇒ 真机采样里出现的 `0x40000400`（bit30=1 且 bit31=0）**只能**是「清过之后被 `ret` 弹回旧值」或「250 ms 采样漏窗」。

## 4. 为什么上一轮的「收口」被撤回

`T-0187/recheck.md` §5.10 曾据两轮 250 ms 采样下结论「悬停不清 bit30、不重启节拍、格号相位连续」；§5.11 撤回：
能做实的只有「**`i072` 从未在 bit30 为 0 时执行过**」，它**区分不了**「没被清」与「被清了但没重新武装」——
而按 §3 第 3 条，后者根本不会留下「计时器回落/相位断」的痕迹。250 ms 对**瞬态**清位太粗。

## 6. 候选分叉（结论 =「悬停不清位」时按这个顺序找）

1. 该键的**真机生效值**（配置注册表/`[set]` 段的实际读取路径是否与我们读到的 INI 同一份）；
