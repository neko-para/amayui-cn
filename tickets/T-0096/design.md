## 1. `sub_4A07F0` 完整语义

### 1.1 签名与四个参数（raw 121131；lst 265202 的 `__thiscall` 判据）


| 形参 | 真身 | 判据 |
|---|---|---|

### 1.3 时钟与「起点锁存」（raw 121257-121265）


⇒ **`record+24` 是「绝对起点时刻」(ms)，不是倒计时**；窗指令（0x34B/0x34C/0x34D）每次都把它写 0

### 1.4 窗求值（4 个块同构，以窗2 缩放为例 raw 121329-121443）

```c
v23 = *((int *)a2 + 13);                  // dur2 = +52
if ( v23 > 0 ) {
  v27 = *((_DWORD *)a2 + 8);              // delay2 = +32
  v28 = *((_DWORD *)a2 + 6);              // start  = +24
  v29 = *((_DWORD *)v5 + 11625);          // now
  if ( v29 >= v28 + v27 + v23 || LODWORD(v105) == 1 ) {
     // ① 跑完 ⇒ 吸附到终值：from ← to、to ← 单位阵、delay/dur ← 0
     a2[8] = 0.0; a2[13] = 0.0;
     qmemcpy(a2 + 20, a2 + 36, 0x40u);    // 121343  M_scale_from ← M_scale_to
     ...置 a2[36]=1,a2[41]=1,a2[46]=1,a2[51]=1,其余 0   // 121344-121361  M_scale_to := I
     qmemcpy(v109, a2 + 20, sizeof(v109)); // 121362 输出 = from(=旧 to)
  } else {
     if ( v29 > v27 + v28 ) {             // ② 窗内
        v30 = now - delay - start;        // elapsed（float）
        v107 = start + dur + delay - now; // remaining（int→float）
        v103[i] = a2[36+i] * elapsed;     // to · elapsed
        v102[i] = a2[20+i] * remaining;   // from · remaining
        v102[i] = v60 + v103[i];          // 逐元素加
        v106 = 1.0 / dur;
        v103[i] = v102[i] * v106;         // ⇒ v109 = (from·remaining + to·elapsed)/dur
        qmemcpy(v109, v103, 64);
     }
     v107 = 1;                            // ③ 窗未开 / 窗内 ⇒ "还有窗在跑"
  }
}
```

- 权重口径：**from 权 = remaining/dur、to 权 = elapsed/dur**（`elapsed = now − start − delay`）。
- 触发吸附的条件 `now >= start+delay+dur` ⇒ **窗末冻在终值**（票面验收第 3 条要的正是这条）。
- 窗内**不夹取** `elapsed`（`elapsed` 可能 > dur？不会：条件已判 `now < start+delay+dur`；`now > start+delay` 才进窗内）⇒ 权重 ∈ (0,1)。
- `v107`（121262 起为 0）= 「本轮还有窗在跑」标志：4 个块里，**吸附分支不置 1，窗内/未开分支置 1**。
- 收尾（121634-121646）：`if (*(float *)&v107 == 0.0)` ⇒ 全窗跑完 ⇒ `record[0] &= ~2`、`record[+504] &= ~1`、`record[+24] = 0`、`M[11627] = 1`；否则 `if ((record[+504] & 1) == 0) M[11629] = 1;`、`M[11627] = 1`。

### 1.5 窗1（颜色）与窗3（旋转）的**非**矩阵特例

- **窗1 颜色**（121311-121327）：**逐字节线性插值**（不是矩阵）：
  ```
  byte0 ← lerp(from+68, to+72)   byte1 ← lerp(from+69, to+73)
  byte2 ← lerp(from+70, to+74)   byte3 ← lerp(from+71, to+75)
  权重同 (remaining, elapsed)/dur；结果整 dword 写 *a4
  ```
  吸附分支（121301-121308）：`color_from ← color_to; color_to = NAN; delay=dur=0; *a4 = color_from`。
  ★`a2[18] = NAN;`（121306）我只读到这一行文本，**没有去 `.lst` 核那个立即数**（见 §6 风险 5）。
- **窗3 旋转**（121488-121521）：窗内**不用 `+52`/`+68` 两个矩阵插值**，而是**对轴与角插值后重算矩阵**：
  ```c
  axis[0..2] = (axis_from*remaining + axis_to*elapsed) / dur;   // 121496-121513，★不归一化
  angle      = (angle_to*elapsed + angle_from*remaining) / dur * dbl_526C98 / dbl_5263F0; // 度→弧度
  D3DXMatrixRotationAxis(v110, axis, angle);                     // 121517 整体覆盖 v110
  ```
  非窗内时 `v110` = 顶部从 `+52`（`0x348` 写的 RotationAxis）拷来的矩阵；吸附时从 `+68`（`0x34C` 写的）拷来
  （121467 `qmemcpy(a2 + 52, a2 + 68, 0x40u)`）⇒ 三条路径都自洽。
  `dbl_526C98 / dbl_5263F0 = π/180`（同式出现在 `sub_4AFE90` raw 134095，而 `D3DXMatrixRotationAxis` 收弧度）。

### 1.6 组合序（★左乘/右乘判据 = 汇编 push 序，不是推断）

```c
// 入口 raw 121242-121252
v59 = a2[2]; v58 = a2[3]; v57 = a2[4];          // pivot p = +8/+12/+16
j_D3DXMatrixTranslation(v112, -p.x, -p.y, -p.z);
j_D3DXMatrixMultiply(a3, a3, v112);             // a3 = a3 · T(-p)

// 尾部 raw 121648-121654
j_D3DXMatrixMultiply(a3, a3, a2 + 127);         // · M_base   (+508)
j_D3DXMatrixMultiply(a3, a3, v109);             // · M_scale
j_D3DXMatrixMultiply(a3, a3, v110);             // · M_rot
j_D3DXMatrixMultiply(a3, a3, v111);             // · M_trans
j_D3DXMatrixTranslation(v112, p.x, p.y, p.z);
return j_D3DXMatrixMultiply(a3, a3, v112);      // · T(+p)
```

**判据（`.lst` 266233-266235）**：
```
266233: push esi        ; pM1
266234: push esi        ; pOut   ← 同一个 a3
266235: call j_D3DXMatrixMultiply
```
`push` 次序 = 右→左 ⇒ 实参 `(pOut=a3, pM1=a3, pM2=<矩阵>)`；`D3DXMatrixMultiply` 语义 `pOut = pM1 · pM2`
⇒ **右乘 / 追加（append）**，`a3` 是纯累加器。D3DX 用**行向量**约定（`v' = v · M`，平移在第 4 行）
⇒ 组合式：

```
a3_out = a3_in · T(−p) · M_base · M_scale · M_rot · M_trans · T(+p)
```

- **父子继承**：只有「把结果乘到调用方给的累加器上」这一种继承；`a3_in` 由唯一调用方
  （`sub_4B0360` raw 134322-134340）**预置为单位阵**，所以实际链路里没有节点级父链（见 §2 无 parent 字段）。
- 行向量 ⇒ 应用次序：`a3_in` → `−p` → `M_base` → 缩放 → 旋转 → 平移窗 → `+p`。
  即 **pivot 是「缩/旋中心」且括号把平移窗也括在里面**（`+p` 在所有线性变换之后加回，所以平移窗的 t 不被旋转）。
  对模型点 `q0`（z = 0，见 §3.4）：**`q = (q0 − p)·(M_scale·M_rot) + p + t`**。
- 写回：`a2` 被原地改写（delay/dur 清零、from←to、`+24` 清零、`+504` 清 bit0 等），
  调用方 raw 134392 `qmemcpy(v16, v29, 0x23Cu)` **把改写结果写回 `Scene+1096` 表** ⇒ 跨帧状态有效。

### 3.2 矩阵进了哪里

进 **D3D 世界矩阵**（`SetTransform(D3DTS_WORLD)`，vtable +=176，raw 134355/134372/134387），
在 `D3DXMatrixOrthoLH(显示宽, −显示高, …)`（raw 134354）这一级 2D 正交投影之下；

### 3.3 与 `src/live2d/deform.ts` 的关系

- `deform.ts` = **模型内部**（Cubism 2.x 的 BDAffine/BDBoxGrid/pivot），把网格点从局部变到**画布坐标**；
- `sub_4A07F0` = **模型外部**的一次 2D 仿射（画布坐标 → 画布坐标），作用在整个模型画布上；
- 二者是**串联的两级**：emulator 现在把节点变换写成 `px = mx*nt.scale + nt.tx + dx`（`render.ts:202-203`），
  即已经默认「节点变换 = 画布坐标上的各向同性缩放 + 平移」——**位置对、表达力不够**。
- 现成工具已在同文件：`deform.ts:49` `Affine = [a,b,c,d,tx,ty]`（列向量 2×3）、`affineApply(m, x, y)`（deform.ts:66）、
  `affineMul`（deform.ts:54）。⇒ 落地只需把 `l2dNodeTransform` 的返回类型换成 `Affine` 并用 `affineApply`。
- **坐标约定陷阱**：引擎是**行向量**（平移在 4x4 第 4 行），`Affine` 是**列向量**（`x' = a*x + c*y + tx`）
  ⇒ `a = M11, b = M12, c = M21, d = M22, tx = t.x, ty = t.y`（D3D 下标 → emulator），**取转置**，别直接抄。

### 3.4 z 分量

模型顶点流每点 12 字节 = `{x, y, alpha}`（本工程已确证，见 `render.ts:33` 头注释），z ≡ 0
⇒ 合成的 4x4 里**只有左上 2×2 + 平移**影响画面（第三列不参与），`sz`/`tz` 与轴的 z 分量只在
「轴不纯 z」时通过 2×2 交叉项进来。`Affine`（2×3）**足够**，不需要升 4×4。

必须**逐句对齐**的 7 件事（顺序即引擎顺序）：
1. `if (!(flags & 2)) return { I, color: from, alpha }`（121259）；

### 6.2 未确证（**不要编**，实现时按「照抄 raw 行为」处理并留注释）

1. **窗1（颜色窗）的设置端**：`0x342`-`0x352` 里**没有任何一条**写 `+28/+48/+68/+72`（grep `+ 28) =` / `+ 48) =`
