# amayui-inspector 技术方案（已确认选型版）

> 目标：一个**桌面应用**，识别 AGE 主进程，提取并可视化其**内部状态机**数据。
> **已确认选型**：
> - 技术栈 **C# / .NET 10 + WPF**
> - 刷新 **仅手动快照**（点"刷新"读一次；不做实时轮询）
> - 范围 **先只读查看器**（定位 `this`、读全局变量/帧栈/opcode 表并可视化；hook/写留后续）
>
> 所有"已确认"的引擎结构与偏移均来自 `docs/re/engine/04/05/07/08` 与 `engine/engine.hpp`。
> 已有可复用工具：`scripts/re/extract_global_data.ps1`（+ Add-Type 内嵌 C#）、`dispatch_signature.json`（其 C# `GD` 类可直接平移）。

---

## 1. 目标与范围

**识别并挂接**运行中的 AGE 引擎进程（`AGE.EXE` / `天結_unpacked.exe`，x86 32 位），
**读取并实时呈现**其 VM 解释器 `this` 对象背后的状态机数据（全局变量、脚本帧/调用栈、
局部变量池、opcode 调度表、掉落/静态数据区）。

**数据来源（全部已确认，见 docs/re）**：
| 数据 | 位置（this + 偏移） | 说明 | 参考 |
|---|---|---|---|
| `this` 定位 | — | dispatch 表 RVA 指纹扫描（Approach B） | `07` §6 |
| 全局变量数组 | `+0x5D800`(int) `+0x5D808`(float) `+0x5D810`(string) `+0x5D818`(ptr) `+0x5D820`(fptr) | 各基址即运行时数组起始；值经 `DEC`(key) 解码 | `05`/`07` |
| 解混淆 key | `+0x5EC8C` | DEC/ENC 用的异或+移位 key | `05` |
| 控制流寄存器 | `+0x5D880/884/888/88C` | cur_script / call_ret / call_link / call_flag（帧下标或哨兵） | `08` |
| 脚本帧数组 | `+0x5D894`，40 帧 × 0x78（帧基址 = `this+0x5D894 + 0x78*cur`） | `ScriptContext frames[40]` | `08` |
| ↳ 帧内字段 | （**帧内偏移**，相对帧基址 `this+0x5D894 + 0x78*cur`；以 `engine/engine.hpp` 的 `ScriptContext` 为准）`+0x00` str_table(字符串表基址) `+0x04` ip(当前指令指针) `+0x20` local_int `+0x24` local_float `+0x28` local_string `+0x2C` local_ptr `+0x30` local_float_ptr `+0x38` caller(返回链接) `+0x3C` frame_arg(本帧传入参数/脚本 id) `+0x60` arity(指令长度) `+0x70` array_container(数组容器)；**其余为未标定零区**，见 `engine/engine.hpp` | 每帧完整 VM 上下文 | `engine/engine.hpp`、`08` |
| opcode→handler | `+0xA509C` 一维函数指针表（0x400） | 可用 `docs/re/engine/06` 映射 + `semantic_names.json` 命名 | `03`/`06` |
| 掉落数据区 | VM 索引 `0x53CD7C..0x53F48C` | item/rate 静态表（rate=概率刻度） | `src/03` |

## 2. 核心能力

1. **进程识别/挂接**：枚举进程，匹配 `AGE*`/`*unpacked*`/`天结*`；取 PID → `OpenProcess(PROCESS_QUERY_INFORMATION|PROCESS_VM_READ)` → 模块基址（`EnumProcessModules`+`GetModuleFileNameEx`）。
2. **`this` 定位**：按 dispatch 表 RVA 指纹（`module_base + RVA`)扫描提交/可读区，命中一次即得 `this`。
3. **状态提取**：读全局数组（DEC 解码）、控制寄存器、40 帧（字段 + 局部池）、dispatch 表、掉落区。
4. **实时刷新**：定时/手动重读，呈现状态随游戏进程变化的视图（战斗旗标、当前脚本帧、局部变量）。
5. **可视化**：DataGrid / 树形 / 十六进制等视图；全局值可搜索/过滤；帧栈展开。

## 3. 技术选型对比（核心讨论点）

引擎是 32 位 x86，本工具是 Windows 桌面内存读取器（类 Cheat Engine 的"查看器"）。

| 方案 | 语言/框架 | Win32 内存访问 | 性能(扫描+刷新) | 开发效率 | UI 现代度 | 依赖/分发 | 复用现有分析 |
|---|---|---|---|---|---|---|---|
| **A. C#/.NET 10 + WPF** | C#, .NET 10 | P/Invoke（简单、原生） | 好（真实编译） | 高 | 中上（DataGrid 够用） | .NET 运行时/自包含 | **最高**（现有 Add-Type C# 逻辑可直接搬） |
| **B. C++ + Qt Widgets** | C++, Qt | 原生 | 最好 | 低 | 中 | Qt DLL（重） | 中（可贴近引擎 C++） |
| **C. Electron/Tauri** | TS/Web + 原生桥 | 需 node-ffi/N-API 或 Rust(windows-rs) | 中 | 中 | **最好** | 重（Electron）/ 中（Tauri） | 低 |
| **D. Python + PySide6 + ctypes** | Python | ctypes | 中下（解释器热路径) | **最高**（复用 clang/脚本工具） | 中上 | 打包麻烦 | 高（现有 .py 直接复用） |

**已确认：A（C#/.NET 10 + WPF）。**
- 这是"进程内存查看器"的**标准做法**：P/Invoke 直接、跨位数（64 位宿主读 32 位目标）已验证可行；
- 现有 PowerShell 工具里内嵌的 **C#（`GD` 类：OpenProcess/ReadProcessMemory/VirtualQueryEx/DEC/ExportInt）可直接平移到 C# 工程**，风险最低；
- 扫描 `this` 指纹在真实编译下比 PowerShell 快一个数量级（230MB 进程秒级 vs 数十秒）；
- DataGrid/TreeView 足够呈现`全局表+帧栈`；快照用 `Task.Run` 后台读 + `Dispatcher` 回 UI；
- 自包含发布单 exe 便于分发。

**UI 框架已确认：WPF**（与 .NET 10 最稳、DataGrid 成熟）。

> 📝 框架修订说明（2026-xx 本机环境核查）：本机只装了 **.NET 8 预览版** SDK/运行时（8.0.0-preview.6），
> 正式版 .NET 8 未装、且默认 SDK 10 对 `net8.0` 目标需联网拉发布版引用包（无外网时还原失败）；
> 而 **.NET 10 SDK（10.0.400）+ 运行时（10.0.11）已装且离线可用**。故技术栈由 .NET 8 改为 **.NET 10**（其余选型不变）。

```

├─ AmayuiInspector.Core/            # 引擎读取核心（可独立测试/复用）
│  ├─ Process/   ProcessLocator(枚举/匹配/open) · ModuleInfo

│  ├─ Model/     Engine · ScriptContext · EngineString · SliceDescriptor · GlobalSlot
│  ├─ Decode/    Dec(ROL/ROR/key 解码) · Enc
│  └─ Scan/      MemoryScanner(VirtualQueryEx+Read 分块) · DropDataReader(0x53CD7C..)
├─ AmayuiInspector.App/            # WPF 桌面壳
│  ├─ ViewModels/ MainViewModel · EnginePanelVm · GlobalTableVm · FrameStackVm · DispatchVm
```

- **Core 与 UI 解耦**：Core 只依赖 Win32 P/Invoke + 纯逻辑；可用 xUnit 单测（DEC 往返、指纹匹配、偏移），也可被 CLI/脚本复用。
- **手动快照**：点「刷新/扫描」→ `Task.Run(EngineReader.Snapshot)` 后台读取（避免卡 UI）→ `Dispatcher` 回填 ViewModel（INotifyPropertyChanged）。**不做定时轮询**（当前阶段）；留出接口便于以后加实时刷新。

## 5. 关键技术点（必须在方案里定死）

1. **跨位数读取**：宿主 64 位、目标 32 位 → 用 x64 `MEMORY_BASIC_INFORMATION` + 32 位地址域；已验证（`07` §6）。
2. **`this` 指纹扫描**：30 条签名（`dispatch_signature.json`），期望指针=`module_base+RVA`；命中一次即停；扫描要**异步**（避免卡 UI），并缓存 `this` 直到进程退出/用户重扫。
3. **DEC/ENC**：`DEC(x)=ROR4(key ^ ROL4(x,11),25)`；`$M32=0xFFFFFFFFL`（别用 `[int64]0xFFFFFFFF`，会变 `-1` 破坏掩码）——这是踩过的坑。
4. **字符串(SSO)**：28 字节结构，`length<0x10` → 内联小串，否则 `heap` 指针；读长串需二次 `ReadProcessMemory`。
5. **帧模型**：40 帧×0x78（帧基址=`this+0x5D894+0x78*cur`）；字段与偏移以 `engine/engine.hpp` 的 `ScriptContext` 为准（`str_table`/`ip`/5 个局部池基址/`caller`/`frame_arg`/`arity`/`array_container`），其余为未标定零区。
6. **生命周期**：`OpenProcess` 句柄随进程退出失效 → 所有读取用 `try/catch` + 边界检测；`this` 失效需重扫。
7. **线程安全**：所有 `ReadProcessMemory` 放后台线程；UI 层只持有快照（不可变对象），刷新时替换。
8. **性能预算**：手动全表快照（~7.4M 槽）开销大 → 默认"筛选"视图（只显示非空、掉落区、指定范围），全量另设按钮。

## 7. 里程碑

- **M1 核心读取（无 UI）**：C# 类库重放 `extract_global_data.ps1` 逻辑 → 定位 `this`、读全局表（DEC）、读 40 帧字段。用 CLI 冒烟。
- **M2 最小 WPF**：进程选择 + Engine 面板 + 全局表（搜索/非空）——**手动快照**（`Task.Run` + `Dispatcher`）。
- **M3 帧栈/调用栈**：帧字段 + 局部池 + `frame_arg` 脚本 id；opcode 表命名对照。
- **M4 增强**：掉落区高亮、HexView、导出 CSV（复用现有格式）、`this` 失效自动重扫；预留实时刷新接口（后续可加）。
