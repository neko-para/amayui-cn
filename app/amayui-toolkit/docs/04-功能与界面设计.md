## 1. 数据抽象与通用渲染容器（核心）

**下半区是一个通用渲染容器**，只认“当前视图”的内容——一个**有序卡片列表**。后续可通过此抽象实现前后路由/查阅历史。

```ts
// types/nav.ts
export type CardKind = 'item' | 'unit' | 'building' | 'recipe' | 'message';
export type CardSpec =
  | { kind: 'item'; id: number }
  | { kind: 'unit'; id: number }
  | { kind: 'building'; id: number }
  | { kind: 'recipe'; productId: number }
  | { kind: 'message'; text: string };
export type View = CardSpec[];   // 下半区当前内容 = 有序卡片
```

- **渲染**：`<CardList cards={view}/>` 用 `switch(card.kind)` 映射到具体卡片组件（`ItemCard`/`UnitCard`/`BuildingCard`/`RecipeCard`/`MessageCard`）。容器与“数据内容”解耦。
- **跳转**：`navigate(expr, view)` 接受**内部 query 表达式** + 其结果视图；卡片内部可点引用（`RefChip`）用 `queryFromId` 构造单实体 query。一次搜索 = 一个视图 = 全部结果卡片。
- **历史**：内存维护 `HistoryRecord[]`（`{expr, view}`）栈 + 指针，`goBack`/`goForward`（AppBar 的 ←/→）。历史条目 key = 规范化表达式串（去重），点击回放该表达式。

## 2. 搜索区（表达式 query 模型）

**搜索 = 内部 query 表达式**，不面向用户输入/展示（后续会改成 tag 输入形式）。当前：

- **输入仅用于筛选候选**：`filterCandidates(ds.search, input)` 按 名称/hex 子串过滤，返回候选（每实体一条，已规范化排序去重），仅作 `Autocomplete` 下拉提示。
- **点选候选构造 query**：候选是**带类型的实体**，点击时构造内部表达式
  `queryFromEntry(entry) = [{ category: kind }, { nameExact: nameZh }]`；
  `buildResults(expr, ds)` 求值 = **该类型下同名实体的全部卡片**作为当前视图（同名的可多张）。
- 内部引用跳转（`RefChip`）用 `queryFromId(kind, id) = [{ category: kind }, { idExact: id }]`，求值 = 该指定实体的单张卡。
- **历史记录 record = 表达式（query）对象**，`key = expressionKey(expr)`（规范化去重），点击历史 = 重新对该表达式求值回放。

表达式子句类型（`src/types/search.ts`）：`nameSub`（`%kw%` 模糊）/ `nameExact`（精确）/ `idExact`（hex id）/ `category`（实体类型）。结果按「kind 固定序 → 序号」规范化排序，(kind,id) 去重。

- 候选显示 `名称(日) / 名称(中)` + 类型徽标；选中后把**全部结果**下放内容区（不是单卡）。
- 顶部交互仅是「输入 → 候选 → 点选构造 query」的最小改动，后续重设计为 tag 输入。

## 3. 卡片内容（关系反查，均支持跳转）

> **id / 地址徽标（统一约定）**：每张实体卡片标题行都带一枚徽标 `<类型> #<id> · <名串地址>`，
> **id 与地址一律 16 进制**（无 `0x` 前缀）。地址 = 该 id 空间基址 + id，与搜索框接受的 16 进制查询串**同形**，
> 因此徽标上的地址可直接粘回搜索框定位；反过来也便于把 UI 里看到的实体对回 `src/*.txt` 的 `set-string` 行。
> 各 id 空间基址与格式化函数集中在 `src/services/idspace.ts`（`ID_BASE` / `addrHex` / `idHex` / `entityTagLabel`），
> `dataset.ts` 的搜索项与所有卡片共用同一份，避免基址散落。
> 注意物品与建筑 **id 空间重叠**（如 id `33`：物品=城砦扩建图纸Ⅰ / 设施=小屋（黄）），靠地址或 `productRef` 区分。
> RecipeCard 因配方自身无名串，徽标标的是**产物**的 id 与地址（随 `productRef` 取对应 id 空间）。


| 卡片 | 展示 | 可点引用（→ 跳转目标） |
|---|---|---|
| **ItemCard** | 日/中名、id、`craftable` 徽标、来源 | 材料（→ 其 item 卡）、产品（→ 对应 item/building 卡）、掉落单位（→ unit 卡） |
| **UnitCard** | 日/中名、`title`/`titleZh`、id、掉落清单、**出现在地图** | 掉落物品（→ item 卡）、地图（→ map 卡，反查） |
| **BuildingCard** | 日/中名、id、其建筑配方材料 | 材料（→ item 卡） |
| **RecipeCard** | type、产品、材料| 材料/产品（→ 对应卡） |
| **MapCard** | 日/中名、`mapNo`、**数据表格：地图内单位**（坐标/等级范围/阵营/刷怪） | 单位（→ unit 卡） |
| **MessageCard** | 纯文本（空态/错误/来源未知提示） | — |

- ItemCard 关系块：**配方（作为产物）**、**作为材料（出现在哪些配方）**、**掉落来源（哪些单位掉它 + rate）**、**出现在哪些建筑配方**。
- UnitCard 掉落：`物品(rate)`，`rate` 带“率/权重（未定）”徽标；**出现在地图**用 `mapsWithUnit` 反向查询，列出该单位出现的全部地图（→ map 卡）。
- MapCard：**数据表格**直接列该地图内的单位槽，含 `坐标(列,行)`、`等级范围`、`阵营`、`刷怪`，单位可点（→ unit 卡）；**单位 → 地图 反向查询**由 `mapsWithUnit` 支持。
- 未知信息不误导：`rate`/recipe `metadata` 带“未定”徽标；`craftable=false` 标“不可合成”。

## 4. 状态管理（zustand）

```ts
interface AppStore {
  dataset: Metadata | null; loaded: boolean; error?: string;
  view: View; history: View[]; pos: number;      // 内存历史
  navigate(cards: View): void; goBack(): void; goForward(): void;
  theme: 'light'|'dark'|'system';
  setting: { showUnknown: boolean };
}
```

- `isReady`：`fetch('./data/metadata.json')` → 置 `dataset` + 建索引（`byItemId`/`byUnit`/`byBuilding`/`recipeByProduct`/`materialsIndex`/`dropsByItem`/搜索索引）。
- `navigate`：push 当前 view 至高亮历史，替换 `view`；首屏默认 `[{kind:'message', text:'请在上方搜索…'}]`。
- 加载中骨架屏、失败错误 + “重试”。
