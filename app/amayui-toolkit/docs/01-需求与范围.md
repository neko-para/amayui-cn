# 01 — 需求与范围

## 1. 项目定位

`Amayui Toolkit` 是一个**离线桌面工具**，为《天結いキャッスルマイスター》的玩家/考据者提供：

- **查询**：物品、建筑/设施、合成配方、单位掉落物 的快速检索与反查。
- **规划**：给定目标物品数量，递归展开合成依赖树，汇总基础材料，并标注每种材料的获取途径（配方再合成 / 单位掉落）。

数据由本 app 的提取脚本读**工程根 `src/`**（唯一权威数据源）归一化为**单一 `public/data/metadata.json`**（衍生物，`public/` gitignored；CI 在 deploy 分支构建生成）。**名称（物品/建筑/单位）直接采用 `src/` 里 ITINIT/PLINIT/EBINIT 的汉化结果**，保证与当前汉化一致，工具本身**不改动游戏、不写回数据**。

**部署形态**（一次构建、两产物）：
- **静态版（主路径）**：纯静态 Web 应用，可直接部署到 **GitHub Pages**（无宿主、无后端、无 IPC）。
- **桌面版（可选/后置）**：同一份静态产物经 **Windows 原生 WebView2 薄壳**加载，按 **ZIP 便携目录**分发（无安装包）；仅用于无法访问 GitHub 的场合，**非主路径、不提前介入**。

> **当前范围**：以**数据查看 / 检索 / 联动跳转**为主线；**规划器为后续独立模块**（不含背包/持有量状态，纯输入→输出）。

## 2. 用户与使用场景

| 用户 | 场景 |
|---|---|
| 玩家（单机） | 查某装备怎么合、需要哪些材料；查材料去哪刷（哪些怪掉、掉率）。 |
| 考据 / 汉化成员 | 快速反查「某材料出现在哪些配方 / 哪些单位掉落」，辅助校对。 |

**核心诉求**：离线可用、秒开、检索快、能把“配方 + 掉落”两张表串起来。

## 3. 功能范围（本期）

### 3.1 物品图鉴（查询）
- 按名称搜索：**日文名 + 中文名**（均与汉化一致）；日文子串/前缀、中文子串，可选模糊。
- 物品详情面板展示：
  - 基本信息（id、名称`日/中`、来源文件）。
  - **作为产物**：可制作它的配方。
  - **作为材料**：它出现在哪些配方（物品/建筑）。
  - **掉落来源**：哪些单位掉落它（含 rate）。
- 反查：由物品 id 反查名称（当前 `metadata` 已提供正/反映射）。

### 3.2 配方浏览器
- 两个页签：**物品配方**（marker=1）、**建筑/设施配方**（marker=2）。
- 筛选：按产品、按材料、按类型。
- 每行展示：产品 + 材料清单（`{name ×count}`）。
- 展开详情可查看该行的 `metadata`（语义未定，标注 `unknown`，见 03 文档）。

### 3.3 单位掉落图鉴
- 单位列表（按名称/掉落物过滤、分页/虚拟滚动）。
- 单位详情：`title`（副标题/阵营）、掉落清单（`物品 × rate`），名称均含 `日/中`。
- 反查：搜索某物品 → 列出所有掉落它的单位及其 rate。

### 3.4 制作规划器（后续 / 独立模块）
> 独立能力，按需接入；不影响数据查看/检索/跳转主路径。
- 支持**递归展开**：目标物品 → 若可合成，展开其材料；材料若又可合成，继续展开，直到基础材料。
- 依赖 **DAG**（防环），可切换「树视图 / 汇总视图」。
- 汇总视图给出每种基础材料的所需总数量。
- 每个材料节点给出「获取途径」：
  - **可再合成**（它本身是产物）→ 链接到对应配方。
  - **可掉落** → 链接到掉落单位 + rate。
  - **既不能合成也没有掉落** → 标记“来源未知/仅事件/商店/其它”，提示用户手动确认。
- 处理**不可制作**物品（`metadata.json` 中 `craftable=false`）：提示「该物品不可合成」。

### 3.5 建筑规划器（后续 / 独立模块）
- 与制作规划器共用材料溯源，但**产品**为建筑/设施（走 `recipes` 中 `type=2`/`productRef:'building'`）。
- 建筑配方的产品 id 空间与物品重叠（详见 03 文档），需明确展示用“建筑名表”。

### 3.6 数据状态 / 关于
- 展示：schema 版本、生成时间、各表计数、源（`src/` 提取）、数据文件 `public/data/metadata.json` 位置。
- 对**语义未定**字段（recipe `metadata`、drop `rate`）给出一致性标注与说明。

## 4. 非目标（本期明确不做）

- 不解析 / 编辑游戏本体（`raw`、`data`、`AGE.EXE`、`install` 等）。
- 不实现游戏内实时关联（不启动游戏、不读存档——存档解析属另一课题）。
- 不联网（**离线优先**；不引入在线 API / 远程资源）。
- 不对未确认语义的字段做“看似确定”的解释（避免误导）。
- **桌面薄壳与规划器本期不做**（桌面版仅作为无法访问 GitHub 的备用分发，规划器为后置独立模块——见 06 里程碑）。

## 5. 非功能需求

| 维度 | 目标 |
|---|---|
| 平台 | **纯浏览器（主）**（GitHub Pages）；**Windows 10/11 桌面**为可选/后置（系统自带 WebView2 Runtime 的薄壳）。 |
| 部署 | 一次构建两产物：静态 `dist/` 上 GitHub Pages（主路径）；`dist/` + 薄壳 → ZIP（**后置**，无安装包）。 |
| 启动 | 冷启动 ≤ 2s；数据为纯静态，无网络、无重活；静态版无任何后端/IPC 依赖。 |
| 体积 | 不捆绑 Chromium；仅携带数据 + 界面资源 +（后置）可选薄壳。 |
| 数据规模 | `items` 923、`buildings` 113、物品配方 356、建筑配方 102、单位 243（带掉落 203）、掉落条目 648 —— 全量加载无压力。 |
| 性能 | 目标数据量下，搜索 < 50ms；规划器展开 < 100ms（JS 内存图）。 |
| 可维护 | 数据经一键提取从 `src/` 再生成到 `public/data/metadata.json`，schema 版本化；前端不写死数据。 |
| 安全 | 不暴露任意文件读；只读 app 数据目录与指定的 metadata 目录。 |
