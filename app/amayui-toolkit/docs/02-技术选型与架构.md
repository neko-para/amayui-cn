# 02 — 技术选型与架构（核心评估）

> 本文件回答一个核心问题：**用什么方案把 React+MUI 的 Web 前端做成「既能发布到 GitHub Pages，又能经 Windows 原生 WebView2 桌面分发」的产品**，并锁定整体架构。
> 环境：Node `v24.14`、npm `11.9`、cargo/rustc `1.95`、dotnet `8.0`——各方案工具链均可行。

## 0. 需求定调（依据用户决定）

1. **不提供安装包**：基于 ZIP 分发（与汉化包一致），桌面版按便携目录打包。
2. **可部署为独立页面到 GitHub Pages**：前端必须在**纯浏览器、无宿主**的环境完整运行。
3. **中文/日文搜索**：物品/建筑/单位名与汉化一致（取自 `src/` ITINIT/PLINIT/EBINIT 的 `日文|中文`）。
4. **规划器为纯输入→输出**：无背包/持有量状态。

> 由 1、2 推出关键架构结论：**产品核心是「静态 Web 应用」，桌面 WebView2 只是可选薄壳**。

## 1. 为什么必须是「静态 Web 应用优先」

- GitHub Pages 只能托管**纯静态文件**，无法运行 Rust/Node/后端或依赖桌面 IPC 的代码。
- 因此**数据、查询、规划都必须在前端完成**（数据作为静态资源运行期 `fetch` 加载），桌面壳不承担业务逻辑。
- 桌面壳只做一件事：把同一份静态产物 `dist/index.html` 载入 WebView2 窗口。这使**浏览器版与桌面版共享 100% 前端代码**。

架构上达到「一次构建，两个产物」：
- **静态版**（GitHub Pages）：`pnpm build:web` → `dist/` → 发布。
- **桌面版**（ZIP）：同一 `dist/` + 一个薄 WebView2 壳（可选）→ 打 ZIP。

## 2. 宿主（桌面壳）方案对比

| 方案 | WebView2 原生 | 前端栈 | 壳实现 | 打包 | 说明 |
|---|---|---|---|---|---|
| **Electron** | ❌ 捆绑 Chromium | ✔ | Node | 大 | **排除**：违背“原生 WebView2”。 |
| **Tauri 2 便携构建** | ✔ | ✔ | Rust（极薄） | ZIP 目录 | **推荐（桌面壳）**：`tauri build --no-bundle` 产出一文件夹，可打 ZIP；体积极小。 |
| **WebView2 + .NET 小宿主** | ✔ | ✔ | C#（WinForms/WPF） | 自包含 exe + 静态资源 → ZIP | 备选：避开 Rust；壳同样极薄。 |

> **关键**：因产品核心是静态应用，**桌面壳本身几乎无逻辑**（仅开窗口 + 加载 `dist/`）。选型风险低，两种壳都足够。推荐 **Tauri 2**（WebView2 原生、最小、便于以后要“打开本地数据/存文件”等原生能力），但若想避开 Rust，一个几十行 C# 的 WebView2 壳也行。

## 3. 推荐整体架构

```
                 ┌──────────────────────────────────────────────────────────────┐
                 │       前端静态应用（React 18 + MUI 5, Vite, TS）               │
                 │   一次构建 = 同一份 dist/                                     │
                 └──────────────────────────────────────────────────────────────┘
                                  │
        ┌─────────────────────────┴─────────────────────────────┐
        │ A. 纯浏览器 / GitHub Pages                              │ B. 桌面 WebView2 壳
        │    无宿主、无 IPC、完整功能                               │    加载同一 dist/（本地）
        │    base:'./' + SPA 单视图（内存历史）                     │    可选 IPC（功能探测）
        └───────────────────────────────────────────────────────┘
```

前端内部：

```
┌──────────────────────── 前端静态应用（WebView2 / 浏览器均可） ─────────────────────┐
│  视图层  MUI 组件（页面/抽屉/表格；不写业务）                                       │
│  状态层  zustand store（dataset, settings/theme, planner）                        │
│  领域层  services/ 纯 TS（search, planner/graph, join）  ← 可单测、与宿主无关      │
│  数据访问  dataset.module.ts（载入 metadata.json → 建索引/图）               │
│  运行时能力  runtime.ts（功能探测：可用 invoke 才启用原生增强，否则降级/隐藏）       │
└──────────────────────────────────────────────────────────────────────────────┘
      ▲ (browser: 无)   (desktop: 可选 invoke)
┌─────┴────────────────────────────────────────────────────────────────────────────┐
│ 桌面薄壳（可选，WebView2）：只开窗口 + 加载 dist/index.html                        │
│ 可选能力：save_text / open_data_dir / reload_data（前端 feature-detect 后启用）    │
└────────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 前端“运行时能力探测”（关键设计）

因无宿主也要能跑、有宿主要能增强，前端通过**功能探测**决定是否调用原生能力：

```ts
// runtime.ts —— 是否存在 Tauri IPC
export const hasNative = typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window;
// 存在桌面壳时才启用「导出」「打开数据目录」，否则：
//   - 浏览器：导出用 Blob/URL.createObjectURL 下载，打开目录隐藏
//   - 纯静态：全部用 web 原生替代
```

由此保证：**同一份前端在 GitHub Pages（无壳）和桌面（有壳）下体验一致**，原生能力仅为增强，不构成依赖。

### 3.2 浏览器替代原生能力表

| 原生能力 | 桌面壳（有 invoke） | 纯浏览器/GitHub Pages（无 invoke） |
|---|---|---|
| 导出规划/清单 | 保存对话框（native） | 下载 Blob（浏览器下载） |
| 打开数据目录 | 资源管理器 | 隐藏该入口 |
| 数据刷新 | `reload_data` | 重新构建/重新 fetch 数据集 |

## 4. 数据流（一次构建，两产物；数据为静态资源，不经 bundler）

1. **提取（app 内，独立）**：`app/amayui-toolkit/scripts/extract-metadata.mjs` 读**工程根 `src/`**（权威源，含 `日文|中文`）→ **直接输出**单一 `app/amayui-toolkit/public/data/metadata.json`。
2. **产物**：Vite 将 `public/` **原样拷贝**到 `dist/`（**不经 bundler 处理**）→ `dist/data/metadata.json`。
3. **发布**：`dist/` 上传 GitHub Pages；**经独立 deploy 分支在 CI 构建并提交**（主分支不提交衍生物，`public/` 与本地调试数据 gitignored）。②（后置）给桌面壳打 ZIP。
4. **运行期**：前端启动时 `fetch('./data/metadata.json')` **异步加载** → 建 `Map` 索引/图 → 查询/跳转。**无后端、无网络、换数据只改 JSON**。

> **数据不进 JS bundle、不走 `import`**：以静态资源走 `fetch`，既符合 GitHub Pages（纯静态），又能让**数据与代码解耦**（改数据只换 JSON）。桌面壳加载 `dist/` 用的是**本地虚拟源**（Tauri `tauri.localhost` 或 .NET `https://app`，而非 `file://`），因此相对路径 `fetch` 可用；纯静态版（http/https）天然支持。

## 5. 桌面薄壳（Tauri 2 便携构建）要点

```bash
pnpm build:web          # 产出 dist/
tauri build --no-bundle # 产出 可执行 + resources 的目录（打 ZIP 分发）
# 即把 天結.amayui-toolkit/ 目录（exe + resources + dist）整个塞进 ZIP
```

- `tauri.conf.json`：`frontendDist: "../dist"`；`resources` 可空（数据已在前端 bundle）。
- 无 NSIS/MSI 安装需求；`bundle.active` 可设 false，仅用 `--no-bundle` 打目录。
- WebView2 运行时：Win10/11 预装；文档注明（可选 evergreen 提示）。

## 6. IPC 设计（可选增强，Tauri 示例）

```rust
#[command]
fn save_text(path: String, content: String) -> Result<(), String> { /* 写用户选路径 */ }
#[command]
fn open_data_dir(dir: String) -> Result<(), String> { /* explorer 打开固定目录 */ }
#[command]
fn reload_data() -> Result<(), String> { /* 通知前端重取数据集 */ }
```
前端只在 `hasNative` 时调用；浏览器下这些功能用 web 替代或隐藏。

## 7. 前端栈细节

| 关注点 | 选型 |
|---|---|
| 框架 | React 18（Vite + TypeScript） |
| UI | MUI v5（`@mui/material` `@mui/icons-material`，`@emotion/react` `@emotion/styled`） |
| 状态 | `zustand`（轻量，含内存历史栈） |
| 视图 | **SPA 单视图**（局部状态驱动，无 URL 路由；`navigate/goBack` 内存历史）；后续如需可分享链接再按 `window.location.hash` 序列化视图 |
| 搜索 | 日/中 **子串匹配 + 规范化**（见 03/04）；可用 Fuse.js 做模糊 |
| 主题 | MUI 亮/暗/跟随系统 |

### 7.1 GitHub Pages 工程要点
- Vite `base: './'`（相对路径，任意子路径都能跑）。
- **SPA 单视图**无 URL 路由 → 无刷新 404 问题；若将来加 URL 路由，用 `HashRouter`/hash 序列化。
- 发布走**独立 deploy 分支**（CI：`pnpm build:data && pnpm build:web` → 提交 `dist/`）。

## 8. 备选（.NET 薄壳）要点

若选 .NET：一个 WinForms 窗口内嵌 `Microsoft.Web.WebView2`，`SetVirtualHostNameToFolderMapping("app", distDir, Allow)` + `Navigate("https://app/index.html")`。前端零改动（仍用运行时探测）。差异仅在壳层，不影响前端与数据管道。

## 9. 决策建议（已按用户决定收敛）

- **D1 宿主**：核心 = 静态 Web 应用（无宿主）。桌面壳选 **Tauri 2 便携构建**（WebView2 原生、最小）；避 Rust 用短 .NET WebView2 壳。
- **D2 数据交付**：**作为静态资源 `public/data/metadata.json`，运行期 `fetch` 异步加载**（不经 bundler `import`）。桌面壳经本地虚拟源加载，相对 fetch 可用。
- **D3 中文/日文搜索**：使用 `src/` ITINIT/PLINIT/EBINIT 的 `日文|中文`，数据层携带 `nameZh`/`titleZh`；搜索走 jp+zh 双索引。
- **D4 规划器**：纯 `输入(目标+数量) → 输出(依赖树+汇总)`，无背包/持有量、无可保存规划状态（导出仅轻量下载）。
