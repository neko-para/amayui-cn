# 扩展路线 C「字形度量」实测：`0x1D0` / `0x1D1` 的真身与处置

> 结论先行：**这两条都不是「GDI 文本度量族」**。路线 C 的前提（"补 `text/layout.ts` 的 `GetTextExtent`
> 等价口径就能落地 `0x1D0`/`0x1D1`"）**不成立** —— `0x1D0` 体里**零 GDI 调用**（它读的是一张整数页表），
> `0x1D1` 体里那条链是**整整 1210 行的 GDI 文本页渲染器**（HDC/HFONT/`GetTextExtentPoint32A`/
> 离屏表面与 DrawItem 区间增删）。
> 两条**仍保持 `deferred`**，但理由**整条改写**（旧理由「GDI 度量未建模 ⇒ 编数」对 `0x1D0` 是错的）。
> 路线 C 真正的 `GetTextExtent` 缺口在别处（见 §7）。
>
> 权威 = `engine/天结_unpacked.exe_utf8.c`（raw 行号即该文件行号）；定位用定义头 grep：
> `Select-String -Path engine\天结_unpacked.exe_utf8.c -Pattern '//----- \(0042D440\)'`。

## 0. 锚点表（先摆事实）

| opcode | argc | handler | 定义头 raw | 体内关键调用（raw） | 输出量纲 |
|---|---|---|---|---|---|

| `0x1D1` | 5 | `sub_420310` | 29353（体 29354-29371） | `sub_4675A0(Font, op1..op5, Engine+84128)` | **不回写任何操作数**（纯副作用：渲染一页） |

`0x1D0` → 675996+4×464 = **677852** = `sub_42D440` ✓（raw 22872）；`0x1D1` → **677856** = `sub_420310` ✓（raw 22873）。

## 1. `0x1D0`：回看页索引表的**纯整数游标导航读出**

### 1.1 handler 体（raw 38099-38110，逐行）

```c
_this[30 * _this[95776] + 95805] = 7;          // 帧状态槽 = 7（"本帧在跑一条 getter"）
v2 = sub_41BF50(_this, 3);                     // 读 op3（int）
sub_459860(_this + 21324, &v5, &v4, v2, 2);    // Font = Engine+21324，末参 = 掩码常量 2
sub_42B4B0((int)_this, 1, v5);                 // 写 op1
return sub_42B4B0((int)_this, 2, v4);          // 写 op2
```

`sub_42B4B0` = 操作数回写。**两路出、一股入、末参常量 2**（= 过滤器掩码，见 §1.3）。

### 1.2 被调 `sub_459860`（raw 70629-70724）—— ★**体内没有任何 GDI/字体调用**

它只碰三个容器（`Font = Engine + 85296` 字节 = `Engine + 21324` dword）：

| 字段 | 字节偏移 | 元素 | 谁写 |
|---|---|---|---|
| `Font[841]`/`Font[842]` | `+3364`/`+3368` | **文本项记录表**，72 B/条 | `0x1D2`→`sub_45EFA0`、语音族、渲染层 `sub_45F090` |
| `Font[845]`/`Font[846]` | `+3380`/`+3384` | **回看页索引表**，8 B/条 = `{窗口号, 起始记录下标}` | `0x70`→`sub_45D660` raw 73181-73191；`0x71`→`sub_45EC60` raw 74267-74276；读档 `sub_45F1B0` raw 74494 |
| `Font[859]`/`Font[860]` | `+3436`/`+3440` | **双游标**（859 = 基准、860 = 当前） | 同上两处 push 时一起置为新条目下标 |

输出就是**页表条目本身**（raw 70720-70721）：

```c
*a2 = *(_DWORD *)(_this[845] + 8 * v5);       // op1 = 窗口号
*a3 = *(_DWORD *)(_this[845] + 8 * v5 + 4);   // op2 = 该页在 72 B 记录表里的起始下标
```

"写入者 = `{win, 记录条数}`"这条**是实证不是推断**：

```c
// sub_45EC60（0x71 的落点）raw 74267-74276
if ( a3 >= 0 ) {                                  // a3 = Engine[97055]（SetTB 门）
  HIDWORD(v22) = (Font[842] - Font[841]) / 72;    // ← 记录表当前条数
  LODWORD(v22) = v3;                              // ← 窗口号
  sub_45D240(Font + 845, &v22);                   // push 进页表
  _this[859] = _this[860] = ((Font[846]-Font[845]) >> 3) - 1;
  _this[v3 + 849] = 1;                            // 该窗"组首"标记（0x1D3 的扫描在组首停）
}
```
`sub_45D660`（0x70 的落点）raw 73181-73191 同一形状（`a7` 恒被 `0x70` 传 0 ⇒ **不过 SetTB 门**）。

### 1.3 导航语义（raw 70630-70724，逐分支）

- 入口 `*a3 = -1; *a2 = -1;` ⇒ **任何失败路径都留 `-1/-1`**（`sub_42D440` 忽略返回值，照样回写）。
- `v5 = Font[860]`（当前游标）；`a4 = op3` 是**带符号的相对步数**：
  - `a4 == 0` ⇒ 直接落到 `LABEL_22`，输出**当前条目**；
  - `a4 > 0` ⇒ 向新走 `a4` 格；`a4 < 0` ⇒ 向旧走 `-a4` 格；
  - 走的过程中：`v6 = pair[i].second`（条目指向的记录下标），
    `if (v6 >= 记录条数) break;`、
    `if (*v11 == Font[846]-4) return 0;`（走到最后一条记录就停）、
    `if ((2 & records[v6].flags) == 0 && v6 != v18) --step;`
    —— 即**只有「掩码位为 0 且与上一条目指向不同记录」的条目才算一格**，掩码位 = `2`。
- 掩码位 2 的实证：`sub_46BE30`（排版，raw 83363-83997）把 `a5` 当记录 flags 往下传（raw 83635/83942），
  且 `if (a5 >= 0)` 才 push（raw 83634/83941）；唯一传 `2` 的地方是 **`sub_46CC60`（raw 84019-84083）**：
  它按该窗已存的行记录逐行 `sub_46CBF0(…, flags = 2)` **重排** + `sub_43D870` **重贴**（raw 84047/84058），
  唯一调用者 = `sub_4040A0`（raw 10032，raw 10044 处）。⇒ bit1 = 「**重排/重贴已有记录**」。
  ⚠**残余不确定**：bit1 与"页计数"的精确对应关系（为什么重排产出的记录要让页导航跳过）
  **未 100% 求证**；本条是 `0x1D0` 落地前必须闭环的第一件事。

### 2.2 `sub_4675A0`（raw 80312-81522，1210 行）—— **判定：文本对象状态机**

参数（raw 80313）：`(Font, a2=窗口号, a3=记录表下标, a4=绘制标志 char, a5=填充色, a6=描边色, a7=Engine+84128)`。

## 4. 判定

### `0x1D0` ⇒ 保持 `deferred`（★但**旧理由整条作废**）

旧理由「体内走 GDI 文本对象 ⇒ 度量口径未建模 ⇒ 编数」**是错的**：`sub_459860` 零 GDI、零字体，
它输出的是**整数台账 id**，不需要任何 `GetTextExtent`。它没有落地，是因为**它读的那张表在 emulator 里不存在**：

1. **表本身不存在**（`Font+3380` + 双游标 `Font+859/+860`），要新建；
2. **写者散在别的子系统**：`0x70` 的落点 `sub_45D660`（raw 73181-73191）与 `0x71` 的落点 `sub_45EC60`
   （raw 74267-74276，且**受 `Engine[97055]` = SetTB 门控**）——都不在 `0x1D0` 自己的 handler 里；
3. **过滤位语义未闭环**：掩码 `2`（bit1）的精确含义只到"回看页重渲染路径 `sub_46CC60` raw 84047 传 2"，
   "为什么页导航要跳过它"未求证（§1.3 末）；而 emulator 的记录表里**没有任何记录会带 bit1**
   （渲染层 push 未建模）⇒ 照抄这个条件只会得到一段**永不触发的死逻辑**；
4. **生命周期与持久化都缺**：清表靠 `0x85`（本身 `deferred`），另有一路 `SaveTextBuf.dat` 存档/读档。

★**只做读出端不做写入端 = 「表永远为空 ⇒ 恒写 `-1/-1` ⇒ 回想列表恒为空」**，这正是
"能跑但口径不对的近似"（本项目的判定纪律里，**静默逻辑错误比 `NotImplementedOp` 硬报错更糟**：
现在的行为是 3 个画面（CONFIG / HISTORY / REPLAYVOICE）**响亮地停下**，而不是静默显示空列表）。

### `0x1D1` ⇒ 保持 `deferred`

依赖 **GDI 文本对象状态机**：HDC(`Font+1108`) + 多支 HFONT(`Font+1096/+1100/+201784/+235068`) +
`GetTextExtentPoint32A`/`GetTextMetricsA` + **离屏表面与 DrawItem 区间的增删**（`sub_4A3890`/`sub_4ABB60`）
+ 全局填充/描边色改写（80629-80634）。emulator 侧**既没有"表面/DrawItem 区间"这一步**（它是直接光栅化），
也**没有窗对象 `Font+4*win+1044` 这个模型**；照抄只能得到一个语义不等价的近似。
⇒ 结论与旧记录一致，但理由从"度量未建模"改写成上面这条。

## 5. 要建的模型清单（下一个 agent 可直接开工）

## 7. 路线 C 该去哪：真正的 `GetTextExtent` 缺口

`set:BlankExtentMode`（`char aSetBlankextent[] = "set:BlankExtentMode"`，raw 4280）在**空白字前进量**
上有 GDI 分路：`== 1` 时改用 `sub_404EE0`（raw **10716-10739**）**逐字 `GetTextExtentPoint32A`**
（含 `Font+201784` 那支字体的临时 SelectObject/还原），否则走纯算术回退。

- 消费点：`sub_4072F0`（`0x205` 数字文本的前进量，raw 12221-12236）+ 字形渲染路径
  （raw 85126、85366、85638、85812、86059、86567、86713、87272、87689、87908、88054、88875、
  89074、89571、89760、90032、…共 20+ 处，形态一致）；
- ★**口径已读全（`tickets/T-0085`）**：门**只作用于空白字**（`0x20` / `0x8140` / 控制字节；绘制期
  还含 `GetGlyphOutline` 失败的无轮廓字）—— `== 1` ⇒ `pen += (全角 ? 量宽的高 : 量宽的宽)`，
  `!= 1` ⇒ **`pen += font_size / (全角 ? 1 : 2)`**（raw 87269-87280 写得最直白；另两支写成
  `pen -= 2*lfWidth` / `pen -= lfWidth`，因 `lfWidth` 为负而等价）。`0x205` 那一支另有一层：
  先 `cy = font_metrics_mode ? Font+0x46104(字号) : -lfHeight`（raw 12221-12225），`== 1` 时整个
  `cy` 被覆盖成"量宽"（raw 12232-12235）。
- ★**`sub_46BE30`（排版例程 raw 83363-83997）里没有这个门**：它逐字 `GetTextExtentPoint32A`
  （raw 83596）或在 `font_metrics_mode != 0` 时用 `gmCellIncX / (3 - v112)`（raw 83769）——
  ⇒ 这个门是**绘制笔位**的门，在重写侧映射到"字形前进量"（`text/layout.ts` 的 `advance`）。
- emulator 现状（2026-09 `tickets/T-0085` 落地）：`text/layout.ts` 的 `advance() = sjisBytes(ch) × size / 2`
  **已经接上门**（`BlankExtent` / `blankAdvance` / `numberCellExtent`；`handlers/msgwin.ts` 的 `emitWin`
  逐次读配置）；**仍缺的是宿主字体度量来源**（GDI `GetTextExtentPoint32A` 的等价物）⇒ `mode == 1`
  时按 `measured: false` **显式回退**成网格并把 `TextFrame.blankExtentFallback` 置真。

⇒ **路线 C 的正确落点是这里**（`advance()` 的空白字分支接 `BlankExtentMode`），**而不是 `0x1D0`/`0x1D1`**。
**随包默认值已核（2026-09）= 0**（`tickets/T-0031/evidence/generated-SYS4REG.ini` 的 `BlankExtentMode=0`）；
且 `mode == 0` 的引擎公式 = `font_size / (全角?1:2)` = emulator 的纯算术 ⇒ **默认配置下逐字等价**
