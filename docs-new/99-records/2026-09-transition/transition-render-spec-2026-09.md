## 1. 结论速览

### 1.1 引擎怎么画

`sub_4B06D0` 是「渲染一帧」流程里的**转场步**（它在帧函数 raw 136796 被调用，前一行 136792-136793 把
`Scene+46508`/`Scene+46516` 清零）。它的骨架：

1. **惰性建 2 个 D3DX effect 接口**（raw 134820-134855）：资源 id 200/201 → `Scene+46480`（Fade）、
   203 → `Scene+46492`（Zoomblur/Slideblur）。质量档 `Scene+46668`（0/1/2，由别的 opcode 设，raw 126555-126561）
   决定用不用它们。
2. **遍历转场记录表**（raw 134856-134860）：`Scene+1048` 是一张 `std::map<int, 96B>`，
   `Scene+1052` = 头结点指针，`begin()` = `head->left`，按 key（= 写入端 `op1`）**升序**遍历
   （next = `sub_4A1C00`，raw 136710）。
3. 每条记录：**锁存窗口起点** `[1]`（raw 134867-134871）→ **类别分派** `[0]`（raw 134883/135803/136014）。
4. 三个类别各自的画法（§3）：
   - **类别 0 = 全屏淡入淡出**（`cross-fade`）：效果对象跑 `Fade`（`Tex0` = `Scene+42600` 的纹理、
     `Tex1` = `Scene+42604` 的纹理）；无效果对象时退化成「全屏画纹理 36，再以 `alpha = t*255` 叠画纹理 37」
     （raw 136178-136262）。
   - **类别 1 = 分块淡入淡出**：按记录的**裁剪矩形 `[9..12]` + 子类型 `[13]`** 与两张「绘制项 key 区间」
     （`[5]/[7]`、`[6]/[8]`）把 item 重画进两张 scratch 层，再淡入淡出（raw 136014-136708）。
   - **类别 2 = 盲帘擦除（12 种子类型 `[13]` ∈ 0..11）**：按**条宽 `[14]`** 算扫描带几何，
     从**源纹理 36 / 37** 各取互补的矩形条画进**目标纹理 `[4]`**（raw 134945-135513）。
   - **类别 3 = 插值模糊（`[13]`=0 SlideBlur / 1 ZoomBlur）**：四个通道 `[16..19] → [20..23]`
     按窗口 `t` 线性插值，喂给 D3DX effect 的 `Angle/Width/Height/Length`（模糊）或
     `CenterU/CenterV/Length`（变焦），`Tex0` = **层 36 的纹理**（raw 135883；★不是 `layer[[4]]`）、渲染目标 = **层 36**，
     画完把层 36 拷回层 `[4]` 并释放（raw 135803-136012 + 136680-136688）。
5. **收尾**（raw 136689-136719）：
   - `Scene+46512 == 1`（立即收尾）→ `sub_4A6E70(dword_55E1BC, [4])`（释放该层的宿主资源）；
   - 记录 `[3]` 归 0（= 死记录）、清 `Scene+46516`（在途标志）、把该层 `+1096` 的缓冲按
     `[13]==1 ? 255 : 0` 填充（raw 136699-136706）；
   - `if (Scene+46512 | Scene+46516) Scene+46508 = 1`（raw 136718-136719）——**帧未收敛，下一帧还要重绘**。

### 1.3 emulator 差哪几步（全部落在渲染器，**写入端不用动**）

1. **窗口模型**：`render4.transitions` 只有静态 24 格；没有「首帧锁存 `[1]` / 按 `clock` 算 `t` / 到点把 `[3]` 清 0」的逐帧推进
   （引擎 raw 134867-134871、134941-134944、135806-135822、136181-136198）。
2. **重绘判据**：`sceneNeedsRender` / `scAnimationsPending` 不含转场窗 ⇒ 转场期间 `present:'needsRender'` 档会**停止合成**；
   引擎的对应物就是 `Scene+46508`（读者 `sub_40BE10` raw 16022）。
3. **绘制**：`presenter.present` 的四路归并里没有转场这一路；没有任何扫描带 / 淡入淡出 / 模糊代码
   （`grep blur` 只命中原生 window blur 事件；`scene/state.ts:106` 的 SlideBlur/ZoomBlur 只是注释）。
4. **前/后帧快照**：引擎靠「清 scratch 层 36/37 → 把该记录的 item key 区间重画进去 → 用它们做条带/淡入淡出」；
   emulator 目前只有 `pixiBackend.frameTick()` 的 `extract.canvas → captureCanvasIntoSlot` 能抓「当前合成帧」。
5. **收尾/清理**：`0x224` 清表已实现；「`[3]` 归 0 = 死记录」与「收尾帧回到中性」没有。
6. **工作量估计**：窗口模型 + 判据 ≈ 0.5 天（纯函数，可直接单测）；
   类别 0（淡入淡出）+ 类别 2（12 种盲帘条带）≈ 1.5-2 天（几何是纯函数，画法用 `cropSprite`/mask）；
   类别 3（模糊）≈ 1-2 天（**emulator 没有模糊实现**，要么加 PIXI filter，要么先做 CPU/跳过的近似并如实记缺口）；
   类别 1（分块淡入淡出）≈ 0.5-1 天（可先按「裁剪矩形内的淡入淡出」近似）。
   守卫 + 快照字段 ≈ 0.5 天。**合计 ≈ 4-6 天**。

## 2. 记录格式全表（24 格逐格语义 + 依据）

### 2.1 容器的真实形状（本轮新查明，修正「Scene+1048 的 96 字节记录表」这一说法）

- `Scene+1048` 是 **`std::map<int, 96B>` 对象**（键 = 写入端 `op1`），不是裸数组：
  `sub_4AAE10(Scene+1048, &key)`（raw 130197-130240）= 「查键；**没有就插入一条全 0 记录**并返回 `&value`」，
  `value` 地址 = 结点 + 16。`sub_4AAAF0(Scene+1048, key)`（raw 130052-130075）= 「不存在则先用
  `sub_49A640` 初始化一条『默认记录』再插入」——三个 0x24F/0x250/0x251 写入端的**第一句都是它**。
- `Scene+1052` = 头结点指针；`begin()` = `head->left`（raw 134856-134859），next = `sub_4A1C00`（raw 136710）。
- **默认记录只初始化 dword `[0..13]`**（`sub_49A640` raw 117059-117077：`[0..3]=0`、`[4]=-1`、
  `[5..8]=0`、`SetRect(+36)` ⇒ `[9..12]=0`、`[13]=0`，末尾 `Scene+46508=1`）。
  **`[14..23]` 不初始化**（栈上残留）——每一类写入端都会把自己要用的格写满，所以消费端读到的格总是有定义的；
  emulator 现在把整条记录默认全 0（`[4]=-1`）是**安全近似**。

## 4. 平面与层序：与 20..29 层、Scene 世界矩阵的关系

1. **层号在这里 = 渲染目标（RenderTarget），不是排序键。** 引擎的「层」是
   `Scene + 4*n + 42456` 的纹理/渲染目标对象（`sub_4A50C0` / `sub_4A2D50` / `sub_4A2C10` 都按这个下标取），
   `Scene+46456` 记录「当前目标」。与 emulator 里 `Item.layer`（排序键）= **同名不同物**：
   实现时不要试图去找「层 36 的对象」，要在 emulator 里新建两张离屏纹理来当 36/37。
2. **20..29 的特殊性**来自另一条路径：`RenderScene` 的世界矩阵只在
   `(层号 - 20) <= 9` 时按「缩放/绕轴旋转/平移」分解乘进 `Scene+46536`，否则直接
   `D3DXMatrixMultiply(Scene+46536, Scene+46536, Scene+46600)`（raw 133403-133440，条件式
   `(unsigned int)(v26[1] - 20) > 9`；`Scene+46532 = 1` 标记「要乘世界矩阵」，用完 133445 清 0）。
   ⇒ **层号 20..29 是「场景层」，与转场的 36/37（scratch 目标）互不相干**；转场不参与世界矩阵。
3. **与 Scene 世界矩阵的乘序**：转场条带走的是 `sub_4A2D50`（屏幕空间四边形 + 纹理 UV），
   期间 `sub_49DFD0` 已经把变换重置为单位矩阵、`Scene+46532 = 0`（不乘世界矩阵）
   ⇒ 条带坐标就是**屏幕像素坐标**，不需要任何矩阵；`[15]` 的矩形也是屏幕坐标（`item.f[9]/f[10]` 直接当 `(int)` 用）。
4. **目标层的尺寸**：写入端建层时按 `Scene+42600` 的 `+1040/+1044/+1048`（宽 / 高 / 格式，raw 133779-133782）
   ⇒ 目标层与屏幕**同尺寸**；类别 3 的 `CenterU/V` 归一化分母也用这个尺寸（raw 135846 / 135850）。
