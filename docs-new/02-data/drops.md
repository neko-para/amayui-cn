# 02-data · 掉落数据（item / rate / 随机池 / 调用链）

> 业务数据域。地址为业务域常量，与引擎机制解耦；仅在有必要处交叉引用 `../03-engine/`。

## 1. 掉落表结构

- ✅ **1000 单位容量的连续数组**：
  - `item[0x53cd7c, 0x53e104)`：掉落物品 id
  - `rate[0x53e104, 0x53f48c)`：掉落概率
  - 各 1000×5 槽；索引 `unitId × 5 + 槽`。
- ✅ `0x53f48c = 0x53e104 + 5*1000`：id=1000 边界 + **下一段起点**；该区段**恒 0、项目未写**（脚本 `COMMITBTL` 中 `X<=Y` 为死判断恒真）。

## 2. rate 语义

- ✅ **`rate` 是概率刻度（0–100），不是单纯数量**：战斗掉落用 `RNG < rate + 0xa3578` 判定（RNG 取随机池值，0–99）。
- ✅ `rate/100` 只在 `UNITECH`（单位加入）作**保底数量**；`rate ≥ 100` 必掉。
- ⚠️ **src 字面量为 16 进制**（如 `random 0x64` = 100）。

## 3. 随机池（0x5697a）

- ✅ **战斗随机池**：1000 项（=0x32×0x14 = 50 行×20 列，值 0–99）。
- ✅ 初始化：`FIELD` 用嵌套循环 + `random 0x64` 指令逐项填充（`random` = `rand()%param2`）。
- ✅ 读档/撤退：`memcpy` 走 `0xeafe5`（1000 项）持久化；计数器 `0x5b8af`（`%0x14`=20）存于 `0xa8b85`。

## 4. 掉落调用链

- ✅ 脚本级调用链：`SYSTEM4 → FIELD → BTL → COMMITBTL → REWARD → ADDITEM`。
