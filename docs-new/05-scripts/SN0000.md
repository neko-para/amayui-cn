## 不变量（拿它做回归断言）

- 页序列：i304（文本块开始）→ show-text → i305（文本块结束）→ i073（设字格）→ wait-for-input → 点击 → i071（清场）
- SN0000 的第一条被汇编 show-text 在 ip = 901（= `src/SN0000.txt:1225`），页面 3 行 58 字，全部落在窗 8
- 开场两道 `wait` 门的驻留 = 脚本 `i238` 的值（`i238 0x157c` ⇒ 5500 ms、`i238 64` ⇒ 100 ms），与 80 000 ms 的慢推窗无关（真实语料实测见 `tickets/T-0024/changes.md` 的 gateWaits 表）

## 坑（踩过一次，别再踩）

- ★`src/SN0000.txt:1209-1223` 是 `/* 原文存档（对照用，不参与汇编） */` 注释块 —— 里面也有 show-text，**不能**拿它当「第一条文案」的锚点（会被注释误导）；判据要用「第一条被汇编的 show-text」或 ip=901
- ★`i1c7`/`i1cc`/`i21a`/`i218`/`i215`/`i216` 都是**会回写操作数**的 getter：当 no-op 跳过时 op1/op2..4 保留上一条指令的旧值，脚本据此做的 `or`+`jcc` 与位置校正都会静默出错
- ★`i220 <handle> 0 13880 …`（80 000 ms 慢推）之后**必须**紧跟 `i242 <handle> 1`：引擎靠 `DrawItem+720` bit0 把这一项排除出池挂起位（`sub_49AA30` raw 117843-117844）⇒ `0x400` 等待门不会被整场慢推钉死（同时也让它不被「跳过」冻结截断，raw 117440-117442）。漏掉 `i242` ⇒ `wait` 会一直卡到平移结束（对照实测见 `tickets/T-0024` 的守卫）
