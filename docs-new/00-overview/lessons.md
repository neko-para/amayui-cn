# 工程纪律（踩过的坑，全部是实测教训）

> 这份清单是**跨子工程**的通行纪律（引擎分析 / emulator 实现 / 文档 / 票据 / 多 agent）。
> 每条都来自一次实测事故；新增一条时**必须**写清"哪一次实测"（出处）。
> 会话级前置（沙箱、技能加载、环境构造）在 `docs-new/03-engine/handoff.md` §1.0。

1. **只按引擎证据改**：改动注释必须给 raw 行号 + 体内真实分支；没有依据的"看起来能跑"的补丁不做。
2. **不静默跳过**：任何不实现/近似都要在 `analysis/opcode-gaps.json` 有一条（`unimplemented`/`deferred`/`engine-internal`/`engine-internal-unjustified`/`implemented`/**`partial`**）并写理由。**`partial`**（2026-09 `tickets/T-0149` 新增）= "已注册且语料级可用，但相对引擎体仍缺某条分支/消费端/写者，或某处是披露的近似"，**必须**带 `missing[{what,ticket,raw}]`（由 `test/opcode-gaps.test.ts` 棘轮守住）。**宁可有据 `deferred`，也不要造假实现。**
3. **★筛体/规格文档里的推断只是线索，不是结论**：本轮 13 处推断被逐行读体推翻，其中 **2 处是"归口对象整条错"**（`0x1c4` 被当成"场景层是否已挂项"，实为**语音总线占线查询**；`0x1d0`/`0x1d1` 被当成"GDI 文本度量族"）。**凡采纳前必须读体**。订正要写回文档（本轮落在 `b3-screening-2026-09.md` §6）。
4. **区分"死读"与"漏读"**：`0x1d3`/`0x1d4`/`0x2f3` 的操作数在引擎里**也是**死读（形参在全函数体不出现）⇒ 这不是 bug，写进白名单的"有据豁免"而不是硬补。
5. **不静默跳过 → 也不许用工具悄悄放过**：`--set emulator.note=a, b` 会把值按 ASCII 逗号拆成**数组**；`capabilities.js --validate` 与守卫测试口径现已对齐（都报"必须是字符串"）。**JSON note 里引用短语用「」，不要用裸 ASCII 引号**（会截断字符串）。
6. **手写的"统计量"必然漂移**：`counts` 曾是手写 ⇒ 实测漂移过一次（声明 `deferred 25/unimplemented 6` vs 实际 `31/0`）且无人发现。现在由 `build-opcode-gaps.mjs` 重算回填，`--check` 漂移即 exit 1。**凡是"由工具维护"的字段，就别手写。**
7. **`--check` 必须真的失败**：早前 `gaps:check` 只打印 ✗ 仍 `exit 0`（假"通过"）。已修。
8. **编辑文件一律用 `edit`/`write` 工具**；不要用 PowerShell `Set-Content`/双引号字符串（会吞反引号、写出 NUL）。**对既有共享文件只用 `edit` 定点替换，不要 `write` 整文件**（并发会丢更新）。**源文件行尾一律 LF**：台账/源码写盘只用常驻工具（`ledger.js` 等会拒收 CRLF），`Set-Content`/`Out-File` 一律不许拿来写源文件。
9. **定位引擎函数先 grep `//----- (004xxxxx)` 定义头**（按邻近常量猜位置已实测读错函数）。
   ★**反编译器在每个函数前先给一行原型声明**（如 raw 410 的 `sub_41A0E0` 原型 vs raw 25215 的定义）⇒ 用
   `indexOf('void __thiscall sub_X')` 切函数体会切到"从**原型**到文件尾"（把后面所有函数都卷进来）。**按 `//----- (地址) -----` 头切**。
10. **判定台账内文看 JSON 原文**，不要看渲染后的 md（md 呈现会截断）。
11. **每批出口判据**：守卫测试 + 文档同步（opcode-table / 三层台账 / 审计 §6 / 修复计划 §2d / 票据）+ `npm run verify` 全绿。
12. **新增 opcode 的四件套**：raw 行号注释 → `analysis/opcodes.json` 的语义/状态 → 台账 disposition（+ 重建两份生成物：`opcode-table.md`、`scripts/asm/opcodes.json`）→ 守卫测试。
13. **写字段前先确认有消费端**：往 `Item`/`MeshObj` 加"只写不读"的字段会被 `check:dead-writes` 拦。**也别往"引擎没有的合成级"硬接**（Scene 级变换就是卡在这里 ⇒ 归 `deferred`）。
14. **改宿主行为两宿主对称**：`headlessScene.ts`（测试/报告）与 `pixiBackend.ts`（GUI）都要改；新缝按先例五处同步（`native.ts` + headless + pixi + `stubNative.ts` + `nativeTap` 白名单）。
15. **★会话被打断（休眠/中断）后，先验证"最后一次编辑真的落盘了"**：`edit`/`write` 走的是"临时目录 + 原子改名"，
    被中断时会在目标文件旁边留下 `<文件名>.<pid>.<uuid>.tmpdir/`。**实测踩过**：一次 `edit` 报告成功但改动只在 tmpdir 里
    （`handoff` 的 §5 残留规模段），文件本身没变 —— 只看工具返回值会以为已经写进去了。
    ⇒ 恢复动作：① `Get-ChildItem -Recurse -Filter '*.tmpdir'`；② 用标志串核对目标文件（本工程踩过的标志串 = `残留规模（先看这个再挑活）`）；
    ③ 若 tmpdir 里的内容 = 目标文件 + 那一次编辑，**重新应用该编辑**（不要直接覆盖，除非逐行严格比对为 0 差异）；④ 清理 tmpdir。
16. **★语料量 ≠ 重要性：先看那批命中是不是在「门后/DEBUG 路径」上**。实测教训：`0x140` 以 **181 处**排在
    `deferred` 榜首、连着两轮被列为"最值得先做的一条"，读体后发现它**全在 DEBUG 路径**（`global 708ad6 == 1`
    才进，该全局全语料唯一写点 = `TITLE.txt:462` 的 DEBUG 菜单）⇒ 正常剧情零影响。
    ⇒ 排优先级时**必须**先 `Select-String` 看实参形态是否高度一致 + 追一下「进这条分支的门是什么」，
    否则会把力气花在只有开发者菜单才会走到的指令上。
17. **★锚点不是注释，是跨文件/跨 agent 的 ABI**（轮 5 实测）：`ticket.json` 的 `evidence[].anchor` 与 `analysis/scripts.json` 的 `layout[].anchor`
    要求**别人正在改的文件**里存在那个字面串。改任何被锚定的文件（**源码注释、机制文档的表格行都算**）之前先跑
    `tickets.js --anchors-in <file>` 与 `scripts.js --anchors-in <file>`；能保留就把旧串留在标题/引用里，不能保留就**在报告里申报**（由台账 owner retarget）。
    ★**不许用「删证据 / 降 status / 删条目」来消红**。（实测收益：`--anchors-in save-slot.ts` 一次列出 17 条锚点 —— 此前只能人工列举「必须保留的 4 个串」；它还当场暴露了两条说明过时的证据。）
18. **★「不在被调函数里」≠「引擎没做」**（轮 5 最贵的一课）：`sub_410160` 的 27 个 callee 确实都不清绘制容器，但清容器是它**自己的行内语句**（raw 19810-19820）。
    ⇒ 结论必须落在**函数体文本**上（含行内循环/内联语句），不能只审调用图。
19. **`--validate` 绿 ≠ 数据层对**：直到轮 5，两个工具都在拿**刚重算过的副本**比 `counts` ⇒ 磁盘上的陈旧**检测不出来**（实测踩过 `partial 18→19`、`modeled-verified 48`）。
    现在改为比磁盘并提示 `--recount`。同理：**生成物（`*.md`）只在结算时由台账 owner build 一次**，别的 agent 不跑 build（会用陈旧输入覆盖别人的结果）。
20. **派子代理的三件套**（详见三个技能的同名节）：① 角色（ANALYSIS-ONLY / IMPLEMENTATION / LEDGER-OWNER）；② **路径白名单**（可写哪些、禁写 `analysis/`·`tickets/`·`docs-new/`）；
    ③ **必保字面串**（锚点）+ 退出判据（`npm run verify` + E4）。★ANALYSIS-ONLY 的 prompt **必须**写明「即使你加载了某技能，也**跳过**它的落库步骤」——
    否则子代理会在「技能要求落库」与「只读分析」之间自行取舍（实测原话如此）。
21. **★esbuild（tsx 的转译器）不接受 JSDoc 里相邻的加粗数字**：`raw **18978**/**18982**` 报
    `Unexpected "**"`，而且**行列号指向下一行** —— 极易误判成代码错（实测为此查了一阵）。
    ⇒ 相邻强调之间**留一个空格**（`raw **18978** / **18982**`），或干脆去掉加粗。
22. **★台账/票面写入口只认"恰好一条"**：改台账必须**按条目边界定位**（`opcode`/`id`/`addr`/`offset` 的精确
    `match`），**永远不要用"下一条匹配"**——实测误翻过一条处置位。工具侧已固化：`ledger.js` 的 `match`
    命中 ≠1 条就**整体拒绝**，`patches[].old` 必须恰好出现 1 次（重复短语用显式 `count`）。
23. ★★**裁决 `analysis/opcode-gaps.json` 的 `missing[]` 必用"三态过滤"**（第 52–54 轮踩出来的，三次都命中不同态）。
    **每一条**先打标（不许留空、不许用沉默掩盖）：
    - ① **可补的真缺口** —— 引擎那条分支的处理对象在 emulator 里**存在**（字段/表/宿主缝/发布载荷），只差接线 ⇒ 实现 + 删条目；
    - ② **结构性不适用** —— 处理对象根本不存在（72B 文本记录向量、GDI 离屏表面、D3D 设备状态/重建、平坦地址）⇒
      把 `what` 重写成「**为什么 + 重开条件**」，**不要假实现**（例：`0x82` 的 `op3 & 1` 记录级过滤 —— 实测 `src/renderer/**` 对 `textItems` 0 引用）；
    - ③ **早已补上但没回台** —— `what` 自述「已实现 / 已删 / 现按 …」⇒ 复核代码/守卫后**删条目**（第 52/53 轮删掉 `0x147`/`0x060`/`0x142`/`0x82` 共 4 条）。
    ★**补充判据**：若"补上"在当前语料/状态机下**不产生任何可观测差异**（写的是恒 0 的格、或没有读者的写 ⇒ 死写闸门会亮），
    那它属于 ② 而不是 ①。实例：`0x071` 的 `Engine[122496] = 0` 三出口 —— 该格在 emulator 里是 `MsgWinState.alt`
    （读者 `src/vm/msgwin.ts:781`、清零点 `:679/:884/:894`），但**从来没有被置 1 的写点** ⇒ 在 `0x71` 里补三次清零
    今天不产生任何行为差异（属"登记性缺口"，等真正会置 1 的那条路径建模后一并接）。
    ★**③ 是机械可查的**：`node .agents/skills/amayui-engine-analysis/scripts/gaps.js --stale` 把"自述已实现/不适用"的
    `missing[]` 连 `opcode`+`raw`+`承接票` 一起列出来（**候选清单**：`已由第 N 轮…` 这类沿革话术也会命中，逐条人判）。
    ★**实现即删条目**：派发 IMPLEMENTATION 子代理时把它写进验收项 —— 子代理无权写 `analysis/`，
    所以它必须回报告里列出待删的 `opcode`+`raw`，由台账 owner 用 `ledger.js --plan` 落库；结算前 owner 跑 `--stale` 兜底。
    已 **3 次**出现"实现了却漏删对应 `missing`"（第 52/64/69 轮），主 agent 每次手工补删。
24. ★★**硬写"量纲/几何口径"的判据会被相邻订正静默打成恒假**（2026-09-26，`tickets/T-0182` 实测）：
    判据若把"满屏幕布"写成 `min(xs) <= 0 && max(xs) >= 1280`，就等于把**那一刻的顶点口径**焊进了判据；
    同月 `T-0155` 按引擎体给 `0x320` 的顶点加了半像素偏移（`x/y -= 0.5`）⇒ 满屏幕布变成
    `(-0.5,-0.5)..(1279.5,719.5)` ⇒ `1279.5 >= 1280` 恒假 ⇒ **"撤幕留帧"整条补偿路径静默失效三天**
    （症状：TITLE → GAMESTART → SN0000 过渡中闪出一帧 TITLE 背景 + 配置界面；两处判据各写一份、没有一个测试跨过它们）。
    ⇒ 三条纪律：① **判据只留一份**（放共享层，宿主侧只做筛选，不许再手写几何）；② 口径写成**比例/交集**
    这类与坐标原点无关的量（`FRAME_HOLD_COVER_RATIO` 口径），而不是"必须 >= 视口宽"；
    ③ **用真语料 E3 把"真实几何"与"判据"接起来**（`test/mesh-vertex-quad.test.ts` 现在直接拿链路里那块幕的
     `rect` 去问判据）——这样任一侧换口径都会红，而不是静默失效。
    ★同族判据还有第二半："几何铺满"≠"此刻真的盖着屏幕"（撤一块已全透明的幕在画面上什么都没改变）——
    两条必须分开判，否则会在 TITLE 入场渐显那里白冻 60 帧。
25. ★★**"改一处、另一处静默失效"：两条各自有据的改动会在同一帧里互相抵消**（2026-09-26，`tickets/T-0103` 段 1 实测）：
    转场子系统里 **D3**（活动转场把区间的项**排除出屏幕 pass**，`scTransitionMarkedHandles`）与
    **D4**（类别 3 的模糊源改取**本帧屏幕**）分开看都对；合起来的效果是"模糊一张**已经没有那块背景**的画面"
    ⇒ 槽里恒黑 ⇒ 用户看到的"横向模糊整段丢失、画面直接切成黑"。
    ⇒ 纪律：改**消费端**（谁读谁）时，必须回看**同一帧里还有谁在改那份数据**（这里是"屏幕合成"这条路被 D3 改过），
    并把它写成**一条**端到端断言（本轮守卫 = `test/transition-render-wiring.test.ts` 的"类别 3 的源必须是区间 A 的离屏副本"）；
    只在各自单测里"都有据"是不够的。
26. ★**debug 实例的渲染页跑的是构建产物，不是 `src/`**（2026-09-26 实测）：`amayui_emulator` 起的实例，
    宿主（node）侧确实用 `--import tsx` 直读 `src/`，但**渲染页加载的是 `dist/renderer.js`**
    （`build-electron.mjs` 的产物）⇒ 改了 `src/renderer/**` 却只重启实例，**跑的还是旧代码**
    （症状：日志里仍是旧文案口径；本轮据此白跑了两轮取证）。
    ⇒ 改渲染侧源码后的验证顺序：`npm run build:electron` → 重启实例 → 再验；`npm run shot`/`record` 自带这一步，
    只有"用插件起实例"这条路易踩。
27. ★★**落库的触发条件是"结论类型"，不是"任务类型"**（2026-09-26，`tickets/T-0103` 轮 17/18 实测，**由用户当面指出**）：
    任务是**修渲染器 bug**（横向模糊丢失 / 黑纱），技能 `amayui-script-analysis` 因此一次都没被加载；但两轮里实际做的是
    读 `src/SN0000.txt:3026-3058`（段 1 的 SlideBlur：槽 `3f5c`、源区间 `f8025`、2500ms）、读 `src/SC0000.txt:1420-1510/1607-1653`、
    并把 `src/SN0000.txt:3036` 这类**行号锚进了票的 evidence** —— 而第三层 `analysis/scripts.json` 里这三条**根本不存在**
    （用户原话：「我发现本次你依然没有编辑 `docs-new/05-scripts`」）⇒ 事后补三条（SN0000 +7 段 / SC0000 +8 段 / TITLE +2 段）。
    ⇒ 纪律：**只要结论里出现「这段脚本在干什么 / 这个槽是什么 / 这里的坑是……」或把 `src/*.txt` 的行号行内串当依据**，
    就必须走第三层的收尾三连，**与当前任务挂哪个技能无关**（检查清单见 `amayui-script-analysis` §2.4）；
    票侧配套：出现脚本层结论 ⇒ `links.analysis` 含 `analysis/scripts.json`，且 `src/*.txt` 的 `evidence` 必须被第三层的
    某条 `layout` 段覆盖（否则是"孤儿证据"：锚点棘轮护着它，却没人知道那一段是什么）。
    ★机制上的根因：分层矩阵只写在**那一个技能**里，而技能按任务类型加载 —— **结论类型的触发条件必须写在能被顺手看到的地方**。
28. ★**"已关闭但有条件缺口"的单在票层是隐形的**（2026-09-26，用户问「`T-0091` 的重开条件要如何发现？这个单已经关掉了」）：
    允许的收口形态是"判据已建模 + 已加守卫 + 缺口已登记"（`T-0091` ② 就是，status=done），
    但**缺口本体与重开条件只写在第二层 capability 的 `note` 散文里**，机器不读 ⇒ `--validate`/`--list`/看板都不会现出来。
    实测基线（`tickets/T-0186` evidence）：145 条 capability 里 **16 条**带「重开条件」（partial 9 / modeled-verified 4 / n/a-known 3），
    而 **181 张票里 0 张**带它；更要命的是只查 `partial|absent` 会**漏掉** `clock-read-transition-window`（status=`modeled-verified`，缺口在 note 子项里）。
    ⇒ 纪律：① `done` 票若带缺口，**必须**用固定措辞写 `重开条件：① … ② …`（条件要可判定：什么语料/什么日志/什么宿主能力）；
    ② 条件优先做成**机械检测**（语料静态棘轮守卫 / 运行期日志 grep），而不是靠人定期回看散文；
    ③ 查法 = 查 note 文本 + `grep -rl '重开条件' tickets/*/ticket.json` + 回链反查（详见 `amayui-ticket-ledger` §3.7，
    机械化的那份工作单 = `tickets/T-0186`）。
29. ★★**"每次读界面猜坐标"必须固化成脚本**（2026-09-26，用户口径：「启动、加载存档等操作不稳定性太高…固化成一个工程上的脚本」）：
    同一件事（reset 到 TITLE / 从 TITLE 读档 / 从 ADV 读档）此前每轮都靠"临时脚本 + 现场量坐标"，
    于是每轮都在同三个坑上翻车，而且**现象都长得像"引擎坏了"**：
    - ★**菜单/侧栏/底部按钮要"两帧点击"**：一次注入 `cursor+press+release` **不激活**（实测点不动）；
      正解 = `move → press → 停 ≥2 帧 → release`；
    - ★**"视觉展开 ≠ 逻辑展开"**（`T-0028`）：ADV 侧栏看着是展开的，热点却还是折叠态 ⇒ 必须先悬停折叠条重登记；
    - ★**首跑失败 ≠ 环境坏**：刚 boot 完的实例第一次点 Load Data 偶发进不去（`T-0185`），失败文案还指向错的方向。
    ⇒ 纪律：**原语与用例分两层**——原语（发命令/两帧点击/等条件/读态/起停）只写一份（`.agents/skills/amayui-remote-debug/scripts/emu.mjs`），
    **用例一条一个文件**（`scripts/ops/*.mjs`）并在 `ops/README.md` 登记（前置/机器可读判据/特有坑）；
    新场景（战斗/工房/地图…）**先登记再动手**，不许拿别的场景的坐标硬上。
    ★边界：这一层**只发命令读结果** —— 渲染页/无头窗/节流是**设备侧**的事，不去起自己的浏览器页、不用 playwright、
    不改玩家数据（宁可把 `no-viewer`/`stalled` 分类报出来并给修法）。
    ★反例（本轮被用户按住的两次）：① 为了"让页面跑起来"去研究 playwright/Electron 自建页 —— 越界了；
    ② 想把「强制带玩家 `cache/SAVE.DAT`」当默认 —— 会把玩家数据耦合进测试、默认布局被无声替换，
    正确做法是给一张**可覆盖的运行期配置表**（侧栏 = charm 表 `global 13b0`，见 `tickets/T-0189`）。
