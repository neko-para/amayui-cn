## 1. 结论速览

| 问题 | 结论 |
|---|---|
| **bit2 是什么** | **`Item.flags` bit2 = 「本绘制项挂了 B 族·周期/循环动画层」**（`ITEM_FLAG_ANIM_LOOP`）。唯一读取点 = 渲染器 `sub_4AEEA0`（raw 133390）：bit2 为 0 ⇒ **整层跳过**；为 1 ⇒ 先把该元素 740B 拷到本地、跑 `sub_49BCC0` 把 B 层 5 条通道叠加到世界矩阵/源矩形，并把 `Scene+46532`（世界矩阵有效位）**强制置 1**。 |
| bit2 是"待绘制"吗 | **不是**。"可见/参与绘制"是 **bit0**（raw 133361 `if ((*result & 1) != 0)` 才画）。bit2 只管"要不要跑动画层"。 |
| bit2 是"已合成/派生缓存失效"吗 | **不是**。渲染器**从不**清 bit2（`sub_49BCC0` 全程只写 `Scene+46508`（dword 11627）= 脏，raw 118131/118219/118230/118340/118361）；它只在 `0x230`（`sub_4AD580` raw 132173）里被清。所以它是**持续状态**（"动画开着"），不是一次性的脏位。 |
| **能否在合理成本内实现** | **能**。消费链全在 **2D 绘制项**路径里（`sub_4AEEA0`→`sub_49BCC0`），没有 3D 设备族依赖；emulator 已有 740B `Item` 模型、逐帧求值器与 Pixi 绘制路径（§5）。**不需要扩子系统**，但有三处必须先动：`KNOWN_DRAW_ITEM_FLAGS`（现在只有 `0b011`，bit2 一置就抛 `UnknownFlagError`）、`Item.flags` 的 bit2、以及 B 层的 5 个求值通道。 |
| 一句话建议 | 三票一起做：**0x230 是关（清 bit2+清周期）、0x231/0x235 是开（置 bit2+配周期）**，消费端落在 `drawitem/eval.ts` + `scene/ops.ts`，守卫断言用"同 handle 同 clock，`0x230` 前后求值不同"。 |
| 与台账的关系 | 台账 299 处 = `i230`(116) + `i231`(25) + `i235`(158)，本轮独立复核**逐条吻合**；同族另有 `i232`(8)/`i233`(5)/`i234`(4) ⇒ **整族 316 处**，共用一个消费端，建议一次做完（否则消费端要分两轮接）。 |
| 台账需订正的两点 | ① 台账写"族共用 `sub_4AD580`"**不准确**：只有 `0x230` 走 `sub_4AD580`；`0x231`→`sub_4AD690`、`0x235`→`sub_4AD900`（raw 32128 / 32218）。共用的是**同一族 setter + 同一个 bit2 消费端**，不是同一个函数。② 台账写"消费端 = 引擎 `+536/+556/+560/+568/+572` 渲染字段"**方向反了**：那 5 个偏移是**数据**（周期/起点），真正的门是 **bit2 本身（raw 133390）**，消费函数是 `sub_49BCC0`（raw 117944-118365）。 |

## 2. 三条 handler 的体解读（逐条带 raw 行区间）

三个 handler 都在 `Engine` 类里，公共套路（三条都一样）：
1. 先写**帧的指令长度槽** `_this[30 * _this[95776] + 95805]`（= `frames[cur] + 0x74`，每次 opcode 一个值）；
2. 依次读操作数（**逆序**：从最大的 op 号往 op1 读，`sub_41BF50`=int、`sub_41C300`=float）；
3. `return` 场景 API 的返回值（脚本层不消费，见 §6）。
4. **三条的 Scene 对象都是 `_this + 80708`**（`_DWORD*` 算术 ⇒ 字节偏移 **Engine+322832**；同一基址的独立证据：raw 19822/19839 `sub_49A300((_DWORD *)(a1 + 322832), …)`）。

长度槽值 = **`2*argc + 1`**（每个操作数占「值 + 类型 tag」2 个 dword，再加指令字）：`0x230` argc=1→3（raw 32110）、`0x231` argc=4→9（raw 32123）、`0x235` argc=5→11（raw 32212）；与台账里 opcode 40 的"长度槽 = 9（argc 4）"一致。**（"长度槽"=指令长度 为推测，依据是这 4 个样本的 2·argc+1 恒等。）**

### 2.1 `0x230`（`sub_4243B0`，raw 32105-32113，argc=1）

```c
32110  _this[30 * _this[95776] + 95805] = 3;          // 长度槽
32111  v2 = sub_41BF50(_this, 1);                     // op1 = int（绘制项 handle）
32112  return sub_4AD580(_this + 80708, v2);          // → Scene
```
- 无分支、无门控（**不检查 bit0**），返回值 = `sub_4AD580` 的返回值（= 循环里最后一次 `sub_4AAD40` 的元素指针，raw 132216）。
- `sub_4AD580`（raw 132151-132217）体：
  - raw 132170 `sub_4AAA50((int)_this, a2)` ⇒ **缺项即建项**（见 §2.4）；
  - raw 132172-132173 `v4 = sub_4AAD40(_this + 258, &a2); *v4 &= ~4u;` ⇒ **清 bit2**（`_this+258` dword = 字节 1032 = 该 Scene 的 740B 元素红黑树）；
  - raw 132174-132215 `do { … *(_DWORD *)(v5+v9-4) = 0; … *(_DWORD *)(result+v5) = 0; v5 += 4; } while (v5 < 564);`
    实际写到的元素偏移（并集）= **540, 544, 548, 552, 556, 560**（v5 = 544,548,552,556,560 各写 `v5-4` 与 `v5`）⇒ 清 **B 层 5 条通道的周期（544/548/552/556/560）+ 贴图循环起点槽 540**；**不动** 524/528/532/536（B 层另外 4 个起点锁存槽）与 564/568/572（格数/列数，A、B 两层共用）。
  - ★**注意：`sub_4AD580` 不置 Scene 脏位**（全场唯一：其它 5 个 setter 都有 `_this[11627] = 1`）——因为「关动画」不改变项集合，引擎每帧重画。

### 2.2 `0x231`（`sub_4243F0`，raw 32115-32129，argc=4）

```c
32123  _this[30 * _this[95776] + 95805] = 9;          // 长度槽
32124  v6 = sub_41BF50(_this, 4);                     // op4 = int
32125  v5 = sub_41BF50(_this, 3);                     // op3 = int
32126  v4 = sub_41BF50(_this, 2);                     // op2 = int
32127  v2 = sub_41BF50(_this, 1);                     // op1 = int（handle）
32128  return sub_4AD690(_this + 80708, v2, v4, v5, v6);
```
- `sub_4AD690(_this, a2=op1, a3=op2, a4=op3, a5=op4)`（raw 132219-132239）：
  `sub_4AAA50` 建项 → raw 132229 `*v6 |= 4u`（**置 bit2**）→ raw 132230 `+540 = 0`（贴图循环起点槽清零 ⇒ 下一帧锁存 now）→ raw 132232 `+560 = op2`（**周期 ms**）→ raw 132234 `+568 = op3`（**总格数**）→ raw 132236 `+572 = op4`（**每行列数**）→ raw 132237 `Scene+46508 = 1`（脏）。
- **语义 = 贴图/贴片「换格」循环动画**（消费者见 §2.5 通道 5）：`frame = ((now - 540) / 560) % 568`、`col = frame % 572`、`row = frame / 572`。
- 无 `flags & 1` 门控 ⇒ **项不存在时会"建一个 bit0=0（不可见）的项"并把动画配上**。

### 2.3 `0x235`（`sub_424630`，raw 32203-32219，argc=5）

```c
32212  _this[30 * _this[95776] + 95805] = 11;         // 长度槽
32213  v5 = sub_41C300(_this, 3);                     // op3 = float
32214  v6 = sub_41C300(_this, 4);                     // op4 = float
32215  v7 = sub_41C300(_this, 5);                     // op5 = float
32216  v4 = sub_41BF50(_this, 2);                     // op2 = int（周期 ms）
32217  v2 = sub_41BF50(_this, 1);                     // op1 = int（handle）
32218  return sub_4AD900(_this + 80708, v2, v4, v5, v6, v7);
```
- `sub_4AD900(_this, a2=op1, a3=op2, a4..a6=op3..op5)`（raw 132316-132343）：
  建项 → raw 132330 `*v7 |= 4u`（置 bit2）→ raw 132331 `+536 = 0`（起点槽清零）→ raw 132335 `+556 = op2`（**周期**）→ raw 132339 `j_D3DXMatrixTranslation(v10 + 656, op3, op4, op5)`（**平移矩阵**）→ raw 132340 置脏。
- **语义 = 平移往复（ping-pong）**：幅度 = `(op3,op4,op5)`（**不除 100**，浮点直用），周期 = op2 ms，三角波（raw 118238-118242）。
- 语料形态（`src/SC0330.txt:6356-6364` 等）：`i235 <handle> 50 0 a 0` … 稍后 `i230 <handle>` ⇒ 开一段 50ms 的纵向抖动、再关掉。

### 2.4 族共用链（读过的三个函数）

| 函数 | raw | 作用 |

## 4. 可见行为缺失分析（不建模 bit2 会怎样）

**全部静默**：不建模不会报错、不会崩，只会"该项不动 / 不换格 / 不闪"，以及"关不掉"。

1. **`i235`（158 处 / 52 文件；缺口台账最大单条）**：本应往复平移的项**完全静止**。
   实例 `src/SC0330.txt:6356-6357-6358`：三个 handle(`f8023/f8025/f8026`) 各 `i235 … 50 0 a 0`（周期 50ms、y 幅度 10）→ `6362-6364` 三个 `i230` 关停。不建模 = 抖动/漂浮看不见；不实现 `0x230` = 抖动**永不停止**（比缺失更糟）。
2. **`i231`（25 处 / 17 文件）**：贴图换格循环**永远停在第一格**（源矩形不滚动）。
   实例 `src/DRAWOBJ.txt:119/130`（`i230 (local-int 9)` ↔ `i231 (local-int 9) 64 …` 互斥切换）、`ALLMAP.txt:1290/1369`、`BTL.txt:1842/3971`、`DRAWCHALL.txt:8`、`DRAWCHP.txt:506`。
3. **`i230`（116 处 / 43 文件）**：只实现"开"不实现"关" ⇒ 动画**卡在开着的状态**，且周期清零缺失 ⇒ 相位基准错（引擎还会清周期，重复开时重新计时）。
4. **`i232`/`i233`/`i234`（8/5/4 处）**：颜色脉冲 / 缩放脉冲 / 匀速旋转缺失（同消费端，一次做完最省）。
5. **间接消费端（最容易漏）**：bit2 命中时 raw 133395 强制 `Scene+46532 = 1`（"世界矩阵有效"）⇒ 读取者 raw 119573 会把 B 层矩阵乘进绘制；在 emulator 里这对应 **`Item.useWorld` 被强制打开**（`pixi/presenter` 用它决定 pivot/缩放/旋转/平移是否参与合成，见 `dead-writes.baseline.json` 的 `_removed.Item.useWorld` 条目）。不建模 ⇒ 这些项的"世界矩阵路径"不被强制开，在 `useWorld=0` 的项上表现为**变换整体不生效**。
6. **不变量（别做反了）**：bit2 **不参与 `wait`/挂起门**。引擎的池挂起位 `Scene+46516` 只在 **A 层（bit1）** 路径置位（raw 117844、133528），`sub_49BCC0` 全程没有写它；`0x230` 之后的项对 `wait` 无贡献。若把 B 层当 pending 接进 `itemAnimationsPending`，会引入引擎没有的**卡帧/死等**（B 层是无限循环，永远不会"结束"）。

## 5. 实现规格

### 5.1 bit2 的推荐字段名与语义

| 项 | 建议 |
|---|---|
| 位名（英文） | **`ITEM_FLAG_ANIM_LOOP`**（= `0x4`），与现有 `ITEM_FLAG_VISIBLE`(1) / `ITEM_FLAG_ANIM_WIN`(2) 并列 |
| 一句话释义（中） | **「本绘制项已挂 B 族周期/循环动画层：渲染前必须求值 5 条周期通道（颜色往复/缩放往复/匀速旋转/平移往复/贴图换格），并把结果叠加到世界矩阵与源矩形；bit2 为 0 时整层跳过。」** |
| 状态容器 | `Item.loops: LoopWin[5]`（下标复用 `W_COLOR/W_SCALE/W_ROT/W_TRANS/W_FLIPBOOK`），每项 `{ start: number; period: number; …extra }`，`period > 0` = 该通道启用（对应引擎 `if (+周期 > 0)`） |
| extra | `W_COLOR→loopTo:number(+576)`；`W_SCALE→loopScale:Vec3(+592)`；`W_ROT→loopAxis:Vec3(+580/584/588)`；`W_TRANS→loopTrans:Vec3(+656)`；`W_FLIPBOOK` 用**现有** `fbFrames(+568)/fbCols(+572)`（共享存储，忠实于引擎） |
| ★硬前置 | `src/vm/native.ts:14` `KNOWN_DRAW_ITEM_FLAGS = 0b011` → **`0b111`**（否则 bit2 一置就 `UnknownFlagError` 硬中断）；同文件注释「bit0 存在 \| bit1 动画」补 bit2 |

### 5.2 三条 opcode 的最小实现（伪码）

所有入口与现有动画窗同构（建项 →（无门控）写模型 → 置脏）：

```ts
// src/renderer/scene/ops.ts

/** `0x230`（sub_4243B0 → sub_4AD580 raw 132151-132217）：建项 → 清 bit2 → 清 540/544/548/552/556/560。★无 bit0 门控。 */
export function scResetDrawItemLoop(s: SceneState, handle: number): SetterOutcome {
  s.dirty = true;                       // ★引擎不置 Scene 脏（sub_4AD580 无 _this[11627]=1）；emulator 需重合成 ⇒ 置
  const { item, created } = scEnsureItem(s, handle);   // = sub_4AAA50（缺项即建，默认 flags=0）
  item.flags &= ~ITEM_FLAG_ANIM_LOOP;                  // raw 132173
  for (const L of item.loops) { L.period = 0; L.start = 0; }  // raw 132174-132215（实际写 540,544…560）
  return created ? 'created-applied' : 'applied';
}

/** `0x231`（sub_4243F0 → sub_4AD690 raw 132219-132239）：op1=handle、op2=周期、op3=总格数、op4=每行列数。★无 bit0 门控。 */
export function scSetFlipbookLoop(s: SceneState, handle: number, period: number, frames: number, cols: number): SetterOutcome {
  s.dirty = true;
  const { item, created } = scEnsureItem(s, handle);
  item.flags |= ITEM_FLAG_ANIM_LOOP;   // raw 132229
  item.loops[W_FLIPBOOK].start = 0;    // raw 132230 (+540)
  item.loops[W_FLIPBOOK].period = period;  // raw 132232 (+560)
  item.fbFrames = frames;              // raw 132234 (+568)  ★与 A 层 0x239 共用格
  item.fbCols = cols;                  // raw 132236 (+572)
  return created ? 'created-applied' : 'applied';
}

/** `0x235`（sub_424630 → sub_4AD900 raw 132316-132343）：op1=handle、op2=周期、op3/4/5=平移 (f32，**不除 100**)。★无 bit0 门控。 */
export function scSetTranslationLoop(s: SceneState, handle: number, period: number, x: number, y: number, z: number): SetterOutcome {
  s.dirty = true;
  const { item, created } = scEnsureItem(s, handle);
  item.flags |= ITEM_FLAG_ANIM_LOOP;   // raw 132330
  item.loops[W_TRANS].start = 0;       // raw 132331 (+536)
  item.loops[W_TRANS].period = period; // raw 132335 (+556)
  item.loops[W_TRANS].trans = { x, y, z }; // raw 132339（D3DXMatrixTranslation +656）
  return created ? 'created-applied' : 'applied';
}
```

- 读操作数：`c.args` 1-based（`op1 = c.args.int(1)`…），int/float 按上表；`0x235` 的 op3/4/5 **是 float 且不缩放**（注意与 `0x21E`/`0x233` 的 `÷100` 不同）。
- 宿主缝（NativeBridge）：需在 `src/vm/native.ts`（接口 + 常量）、`src/vm/nativeTap.ts`（tap 名单）、`src/vm/stubNative.ts`（桩）、`src/renderer/pixiBackend.ts` + `src/renderer/headlessScene.ts`（两宿主转发）各加 3 个方法；派发表在 `src/vm/handlers/gfx-item.ts`（该文件的 opcode 表，现有 `[0x202,…]` / `[0x21e,…]` / `[0x239,…]` 项附近）加 `[0x230,…] [0x231,…] [0x235,…]`。
- **不需要动渲染层的引擎侧"接口"**（无 D3D 设备对象、无新增纹理路径）：`+592/+656` 是纯 4×4 缩放/平移矩阵，emulator 已有的 `scaleWork/transWork` 语义完全覆盖。

### 5.4 守卫测试方案（可写成断言的不变量）

新增 `app/amayui-emulator/test/draw-item-loop-anim.test.ts`（命名与现有 `draw-item-anim-window.test.ts`/`draw-item-scale.test.ts` 一致）：

1. **开关对称（最强断言）**：`i235 h 50 0 10 0` 后某 clock 求值 ≠ 中性；紧接着 `i230 h` 后**同 clock** 求值 == 中性，且 `(it.flags & ITEM_FLAG_ANIM_LOOP) === 0`。⇒ 同时证明"bit2 被读"和"0x230 真的关"。
2. **三角波数值**：`period=50, amp=10`，`start` 锁存于 clock0：`clock0 → 0`；`clock0+12 → 4.8`（`2·12/50·10`）；`clock0+25 → 10`（顶点）；`clock0+50 → 0`（回零）。
3. **起点锁存副作用**：第一次求值前 `loops[W_TRANS].start === 0`，求值后 `=== clock`（等价 raw 118236-118237 的锁存；`0x235` 每次都把它清 0 ⇒ 重开即重新计时）。
4. **换格循环**：`i231 h 100 16 4`，clock0+250 ⇒ `frame=2`、`col=2,row=0` ⇒ `src.x === srcX + 2*srcW`；clock0+1650 ⇒ `frame=16%16=0` ⇒ 回第一格（**证明是循环，不是 A 层的一次性+保持**）。
5. **零回归**：未设 bit2、只用 A 层窗的项，`itemRenderPlacement/itemSrcRect` 与改动前逐项相等（跑现有 `draw-item-*.test.ts` / `anim-window-done.test.ts` 必须仍绿）。
6. **不卡帧**：`itemAnimationsPending(it,…) === false`（B 层永不进 pending）；跑 `wait-gate-timer.test.ts` 不得变化。
7. **flag 白名单**：置 bit2 的项过 `assertFlags('drawitem', …)` 不抛（= `KNOWN_DRAW_ITEM_FLAGS` 已扩到 `0b111`）。
8. **建项语义**：对一个从未 `draw-texture` 过的 handle 调 `0x231/0x235` ⇒ 返回 `'created-applied'`、项 `flags & 1 === 0`（不可见、不画），不抛异常。

**要避免的死写陷阱**（`npm run check:dead-writes`，`src/tools/deadWrites.ts`；口径：`Item`/`MeshObj` 字段**有写无读**即红，且 `scSnapshot/snapshotToText/debugDrawItems/debugItemState/slotTable` 这些诊断函数被**剔除**后再统计）：

- 新字段只在 `setters.ts` 写、只在 `snapshot`/`debugItemState` 里读 ⇒ **仍判死写**。必须在 `eval.ts`（渲染消费端）里被读。
- 实现 `0x230` 时若另开一个 `loopEnabled: boolean` 而不读 `flags & 4` ⇒ `flags` 的写入变成"没消费者"，且 bit2 语义没有落地。
- `loops[i].start` 若只写不用（相位公式里没用它）⇒ 死写。
- **最隐蔽的一个**：`0x231` 若只写模型而不在 `itemSrcRect`/B 层求值里加"循环模式"分支，字段全有人读（A 层读），但**画面毫无变化** —— 静态闸门抓不到，只能靠 §5.4 的第 4 条断言。
- 不要把 B 层结果写回 `Item.from`（引擎把颜色脉冲结果写进**调用方局部**，raw 118129；写回模型会污染 A 层基线色）。
