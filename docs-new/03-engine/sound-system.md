# 03-engine · 声音子系统（设备 / 三模块 / 音量路由 / ADV 语音联动）

> 真源：`engine/天结_unpacked.exe_utf8.c`（行号见每节「证据」）。本文只讲**引擎自身的音频播放能力**（跨脚本的机制），
> 单条 opcode 的语义在 [`./opcode-table.md`](./opcode-table.md)（本文件 §7 给音频族的摘要表），逐函数结论在数据层 `analysis/functions.json`。
> 触发点：2026-09 排查「目前被跳过的指令里哪些是音频相关」时把整条音频链读了一遍（当时被跳过的音频指令 = `0xB5` / `0x2F6` / `0x2F8`）。

## 1. 拓扑：一个 DirectSound 设备 + 三个逻辑模块

引擎的音频**不是**一个模块，而是「1 个设备对象 + 3 个各管一件事的模块」叠在 `Engine` 里（全是内嵌子对象，不是指针）：

| 对象 | 位置（int 下标 / 字节） | 类（vftable） | 管什么 | 通道 |
|---|---|---|---|---|
| Sound 设备 | `Engine[4666]` / `Engine+18664` | `Sound___vftable_`（构造 `sub_4B5B50` raw 138331） | DirectSound 接口、15 条通道、每通道缓冲/音量/临界区、3 种解码器、流式喂数据线程 | **0..9 = SE，12..14 = 语音**，10/11 未分配 |
| SE 模块 | `Engine[20719]` / `Engine+82876` | `SE___vftable_`（`sub_4B4F10` raw 137622） | 10 条**音效**通道的「装/播/停/延迟播」 | 逻辑 0..9 → 设备 0..9 |
| Voice 模块 | `Engine[21032]` / `Engine+84128` | `Voice___vftable_`（构造 `sub_4BB700` raw 142443） | 3 条**语音**通道的「装/播/排队/延迟/音量因子」 | 逻辑 0..2 → 设备 12..14 |
| Music 模块 | `Engine[174454]` / `Engine+697816` | `Music___vftable_`（`sub_489F20` raw 106343） | BGM：播放/暂停/停止/淡入淡出/开关，多槽播放器 | 自己的播放器对象（不走上面 15 条通道） |

三模块**共用同一个设备**：`sub_4BB810(模块, hWnd, Engine+18664, Engine+680092)`（raw 14939 / 14943、23688 / 23692）把
`模块[258] = 设备对象地址`、`模块[259] = 资源库(FileDB)`、`模块[260] = hWnd` 填好；
模块自己的 `[261]` = 该类声音的**总开关**（`Engine+83920` = SE 开关、`Engine+85172` = 语音开关，raw 14940-14946 / 23691-23695）。

> ⚠ 两处「258」不是同一层：**模块[258] = 设备对象地址**，**设备[258] = IDirectSound 接口**。读反编译时容易串。

## 2. Sound 设备（`Engine+18664`）：15 条通道 + 3 种解码器

### 2.1 每通道字段（`ch` 为设备通道号 0..14）

| 字节偏移 | int 下标 | 含义 | 证据 |
|---|---|---|---|
| `+1032` / `+4·ch+1620` | `[405+ch]` | 该通道的 **SoundBuffer**（== 当前绑定的声音对象；0 = 空） | raw 138605、139065-139081 |
| `+4·ch+1308` | `[327+ch]` | **通道音量**（0..10000 线性；`sub_4B68E0` 写，`sub_4B6210(设备, ch, 设备[327+ch])` 用它重新下发） | raw 139048、138970 |
| `+4·ch+1500` | `[375+ch]` | **通道 pan（左右平衡）**（`sub_4B6940` 写并钳制 ±10000；`sub_4B6350`→`sub_4B7110` = **SetPan**，0 = 中央） | raw 139080、139415 |
| `+4·ch+1560` | `[390+ch]` | **每通道音量因子**（0..10000；`-1` = 不缩放）—— 角色语音音量（CV 设定页）走这里 | raw 138711-138718 |
| `+4·ch+1380` | `[345+ch]` | 该通道**跳过**（静音）标记 | raw 138705 |
| `+1368` | `[342]` | **主音量**（10000 基准，`sub_4B68A0` 写） | raw 139034、138712 |
| `+1376` | `[344]` | 设备**不可用/已拆除**（真时所有音频调用立即返回） | raw 138597、138701 |
| `+6·ch+1680` | `[420+6ch]` | 每通道**临界区**（24B × 15） | raw 138902、138319 |
| `+4·ch+2040` | `[510+ch]` | 每通道**引用计数**（Interlocked） | raw 138905、138322 |
| `+4·ch+5760` | `[1440/4+ch]` | **待定 seek（毫秒）**，起播时先定位再清零 | raw 138614-138618 |
| `+4·ch+2912` | `[728/4+ch]`? | （未建模，`sub_4B6570` 里读 `_this[ch+327]` 之外还有 `+4·ch+…` 若干，见 `unmodeled`） | — |

音量真正下发到 DirectSound 的是 `sub_4B6210(设备, ch, 音量)`（raw 138693）：

```
v7 = 音量 * 设备[342](主音量) / 10000;
if (设备[390+ch] >= 0) v7 = v7 * 设备[390+ch] / 10000;      // 每通道音量因子（角色语音音量 = 10000 即 100%）
if (v7) 参数 = (log(v7)*k1 - k2) * k3;  else 参数 = 最小值;   // 对数衰减曲线
sub_4B70B0(缓冲, 参数);                                     // IDirectSoundBuffer::SetVolume
```

即**音量相乘**：参数音量（通常就是 `[327+ch]`）× 主音量 × `[390+ch]` 每通道音量因子，最后走对数曲线 → `SetVolume`。
★**pan 是另一条路径**：`sub_4B6350(设备, ch, pan)` → `sub_4B7110` → `IDirectSoundBuffer::SetPan`（值域 ±10000，0 = 中央），与音量互不影响。

### 2.3 播放/停止/流式喂数据

- `sub_4B73E0(缓冲, 循环标志)`（raw 139555）= **起播**：`+9296 = 循环标志`、`+9312 = 1(播放中)`、`+9308/+9316` 复位、
  需要时 `SetCurrentPosition(0)`（失败报 `ERROR dsbPlay:頭出しに失敗しました`）、`Play(0,0,1)`。
- `sub_4B6B60(缓冲)`（raw 139152）= **停止**（`+9304 = 1`、`+9312 = 0`）；
  `sub_4B6C30(缓冲, 索引)`（raw 139194）= **流式喂数据**：解码器取块 → `Lock/Unlock` 写入 DS 流缓冲；
  解码器取空时看 `+9296`：**非 0 = 循环**（解码器复位、`+9328` 循环计数 +1），**0 = 补静音收尾**（`+9304 = 2`）。★
  `+9296` 就是各"播放"指令传进来的循环标志 —— 这是区分 `0xB5`（播一次）与 `0xBA`（循环播）的唯一依据。
- 线程：`sub_4B5AA0`（raw 138309）用 `WaitForMultipleObjects(0x3D=61, …)` 等每通道 4 个事件、逐个 `sub_4B6C30` 泵数据。
- 定位：`sub_4B5A30(缓冲, 毫秒)`（raw 138282）按 `时长 × 毫秒 / 1000` 换算字节偏移。

## 3. SE 模块（音效，`Engine+82876`）

- 10 条通道（`ch < 10` 硬上限）。每通道「已装载的 WAV 资源值」存 `模块[1212+ch]`（raw 137654），
  停止/复位时清 `模块[303+ch]`、`模块[262+ch]`（raw 137681-137682）。
- **装载**：`sub_4B4F60(模块, ch, 音效 id)`（raw 137630）→ 从资源库取值 → `sub_4B6570` 建缓冲绑通道 → 记 id；
  失败抛 `WAVファイル %s の読み込みに失敗しました`（raw 137649）。
- **起播**：`sub_4B5020(模块, ch, 循环标志)`（raw 137661）→ 设备在 **且** `模块[261]`(SE 开关) 开 → `sub_4B6020(设备, ch, 循环标志)`
  （raw 138591：通道 > 0xE 报 `dsPlaySound(%d)`、通道无缓冲报 `dsPlay(%d)`、先应用待定 seek、释放在播的循环缓冲、再 `sub_4B73E0`）。
- **停止/释放**：`sub_4B5050(模块, ch)`（raw 137673）→ `sub_4B6390(设备, ch)` 释放缓冲 + 清通道字段。
- **延迟播放**：`sub_4B5170(模块, ch, 循环标志, 延迟毫秒)`（raw 137720）把 `[ch+262]=1(已武装)`、`[ch+272]=0(起始时刻)`、
  `[ch+282]=延迟`、`[ch+292]=循环标志`、`[302]=1(有待播)`；每帧 `sub_4B5230(模块, 当前时刻)`（raw 137763）到期就调 `sub_4B5020` 起播。
- **复位**：`sub_4B51E0`（raw 137743，清 10 通道 + `[302]`）；设备重建后 **重装**：`sub_4B5090`（raw 137687，按 `[1212+ch]` 逐个重载）。
- **总开关**：`模块[261]` = `Engine[83920]`，由 `0xBB` → `sub_408D90`（raw 13545）切换，写配置 `sound:SE`，**关时**把 0..9 通道全 `sub_4B60C0` 停掉。

## 4. Voice 模块（语音，`Engine+84128`）

模块构造 `sub_4BB700`（raw 142443）清零 `[258..264]`、`[280..288]`；每通道（`ch` = 0..2）字段：

| 字段 | 含义（按读写点归纳） | 证据 |
|---|---|---|
| `[262+ch]` / `[265+ch]` | 通道/请求「已武装」 | raw 137555、142567 |
| `[268+ch]` | 起始时刻（0 = 未开始） | raw 142568、142639 |
| `[271+ch]` | **延迟毫秒** | raw 142565、142640 |
| `[274+ch]` | **语音 id** | raw 142566、142664 |
| `[277+ch]` | 请求附带值（低 2 位当状态用：`& 3 == 3` 视为空闲） | raw 142569、142603 |
| `[280+ch]` | 复位时清零 | raw 142554 |
| `[283+ch]` | 状态位（bit0 / bit16 二态切换） | raw 142555、33620-33637、29871-29888 |
| `[286+ch]` | 状态位 + `0x10000` = **有音量因子值** | raw 33774、142690 |
| `[289+ch]` | 音量因子（`0x302` 写；`2710`=10000=100%） | raw 33775、142691 |
| （对应设备侧） | `设备[390+ch+12]` = 音量因子；`设备[375+ch+12]` = pan（`0x2F8` 写） | raw 138711、139080 |
| `[261]` | **语音总开关** = `Engine[85172]` | raw 14946 |

- **起播**：`sub_4BB840(模块, ch, 语音 id, 循环标志, 音量)`（raw 142488）→ 资源库取 VOICE 资源 → `sub_4B6570` 绑 **设备通道 `ch+12`** →
  按 `模块[261]`(语音开关) 决定是否真播 → `sub_4B6020(设备, ch+12, 循环标志)`；失败抛 `VOICEファイル %s の読み込みに失敗しました`（raw 142512）。
- **复位单通道**：`sub_4BB9F0(模块, ch)`（raw 142546）= `sub_4B6390(设备, ch+12)` + 清 `[ch+280/262/265/277]`。
- **排队/延迟**：`sub_4BBA40(模块, id, 附带值, 延迟, ch)`（raw 142563）；每帧 `sub_4BBAB0(模块, 当前时刻)`（raw 142585）到期后
  按 `[283+ch]`/`[286+ch]` 的状态位决定丢弃还是 `sub_4BB840(模块, ch, [274+ch], [277+ch]&1, 设备[387+ch])` 起播。
- **音量因子（角色语音音量）**：`sub_4BBC30(模块, ch, 语音音量)`（raw 142681）：`设备[402+ch] = ([286+ch] & 0x10000) ? [289+ch] : -1`，再 `sub_4B6210(设备, ch+12, 音量)` —— 于是最终音量 = 通道音量 × `[390+ch]` 因子 × 主音量。`0x302` 的 op2 就是这个因子（`CONFIGCV.txt:396-402`：先 `mov (local-ptr 1) 2710`(=10000=100%) 再查角色表，然后 `i302 0 (local-ptr 1)` —— CV 设定页按角色调音量）。
- **占线查询**：`sub_404CB0(模块)`（raw 10584）= 「3 条语音通道里有没有正忙的」——`模块[258]` 为空直接 0；否则
  `(模块[277+ch] & 3) == 3 || !sub_4B6130(设备, ch+12)` 一路跳过，找到「状态非 3 **且** 设备通道在播」就返回 1。
- **总开关**：`模块[261]` = `Engine[85172]`，由 `sub_408E20`（raw 13573）切换，写配置 `sound:Voice`，关时停 12..14 通道。

## 5. Music 模块（BGM，`Engine+697816`）

- 播放器**多槽**：当前槽 `模块[258]`，槽对象 `模块[269+槽]`（raw 106200-106221）。
- `sub_489C20(模块, 曲 id, 循环)`（raw 106225）= 播放（同 id 同循环则不动）；`sub_489F80(模块, 曲 id, 循环)`（raw 106352）= 直接播；
  `sub_489C00`（raw 106216）= 暂停/停播放器；`sub_489B50` = 停止；
  淡出推进 `sub_489E50(模块, 步长)`（raw 106323：`[262] += [263]*(步长+1)`，到 100 收尾）；`sub_489D10(模块, 音量, 步长)` = 设置淡变目标。
- 模式字段：`Engine[174712]`（当前模式值）、`Engine[174713]`（曲 id，`0xC0` 读 / `0xC3` 写）、`Engine[174715]`。
- **BGM 开关**：配置 `sound:Music`（`0xBC` → `sub_408CF0` raw 13515）：开/关时把 `sound:Music` 的值 **±3** 后写回、停当前 BGM、恢复曲 id 重播。
- 用户音量：`sub_489B80`（由 `sound:Volume1` 路由，raw 13747）。
- ★**曲号 ≠ 统一文件 id（2026-09 订正）**：`play-bgm`/`0xB7`/`0xB9`/`0xBF` 的操作数是**曲号**，
  播放器 `PCM`（`MusicBase` 派生，`sub_48D970` raw 108570-108578；走**设备通道 11**）用它查
  「曲号 → 文件 id」表：`sub_48DB80`（raw 108694）里 `v9 = 曲号 - 2`，再取 `*(table + 4*v9)`
  （`table = PCM+1304`，`+1308` = 表尾）交给 `sub_4559C0` 取字节（raw 108738-108748）。
- **PCM 的两张表（2026-09 读体确证）**：`Engine[698900]` = `Music`（`Engine+697816`，ctor `sub_489970` raw 106127-106132）
  的 `[271]` 槽 = **PCM 对象**（vtable `0x5291FC`，三份镜像槽位一致）：

  | 字段 | 表 | 语义 |
  |---|---|---|
  | `PCM+1304`/`+1308` | 扁平表 `vector<int>` | **曲号 − 2 → 统一文件 id**（`sub_48DB80` raw 108738-108740） |
  | `PCM+1320`/`+1324` | 分组表 `vector<vector<int>>` | 扩展包曲子：组号 **1-based**、**组内下标 0 是占位槽**，条目从下标 1 起 |

  - 装载：索引装载末尾（raw 22143-22144）用 `sub_48A0D0` 从 **SYS4INI 尾部**读两张 count 前缀表，
    第二张灌进 PCM 的 `+1304`（`+1320` 保持空 —— 分组表完全由扩展包在运行期建立）。
  - 解析（vtable `+8` = `sub_48DB80`）：扁平曲号 `id = +1304[曲号 − 2]`；**包内曲号**（高字节非 0）
    走分组表 —— 组 = `(id >> 24) − 1`（0-based）、下标 = **`id & 0xFFFFFF` 直接用**（要求 ≥ 1 且 < 组长、
    槽非 0；`sub_48A080`/`sub_48A040` 同一口径：取条目与数条目都从下标 1 起算）。越界/占位槽一律
    `return 0` = 「没有这首曲子」。
  - 登记（0x1D6/0x1D7/0x1D8，见 §7）：`i1d6` 追加扁平表（返回**新曲号**）、`i1d7` 建/重置组
    （`sub_48AA60`：组数不足就补齐并把每组补一个占位 0）、`i1d8` 把统一文件 id 记进组
    （`sub_48A1B0`：追加 ⇒ `(组号<<24)|(新长度−1)`；组内 >1 时从下标 1 起填第一个 0 槽 ⇒ 返回槽下标）。
    扩展包就是靠这三条把 `包号<<24|包内编号` 的文件 id 挂到某个曲号上。
  **本作这张表等价于文件名 `BGM%03d.OGG`** —— 语料侧数据 `src/MUINIT.txt` 里每条曲目就是
  `{A = 文件 id, B = 曲号, 曲名}`，其中 **33/36** 条满足 `FileDB[A].名字 == BGM<B>.OGG`
  （例外是 OP/ED 影片：`B=2/51/52` 指向 `OP.BIN`/`ED.BIN`/`ED2.BIN`）；34 个剧本实际用到的曲号
  **全部**能按 `BGM<曲号>.OGG` 命中。★教训：把曲号当统一 id 会**静音错曲**——
  `TITLE.txt:14 play-bgm 1f`（曲号 31 = 标题曲 `BGM031.OGG`）曾被解析成 id 31 = `BGM041.OGG`（回想界面的曲子）。
  SE 与语音**不是**这样：它们直接把操作数当统一文件 id（`play-sound-effect 2e` → id 46 = `SE004.WAV`；
  `play-voice 0x162` → id 354 = `FIA3203.OGG`，实测均为连续编号）。

## 6. 音量与开关：`sound:Volume0..4` 的路由

主循环初始化（raw 14947-14977、23696-23721）与 `0xC6`/`0xC5`（set/get）走同一张表：

| 配置键 / `0xC6` 的 op1 | 作用 | 引擎路径 | 证据 |
|---|---|---|---|
| `sound:Volume0` (0) | **主音量**（设备 `[342]` + 全量路由） | `sub_4B68A0(设备, v)`（raw 139028）/ `sub_4092C0` | raw 14949-14951 |
| `sound:Volume1` (1) | **BGM/Music** | `sub_409290` → `sub_4071D0(this,v,1)` + `sub_489B80(Music,v)` | raw 13744-13748 |
| `sound:Volume2` (2) | **SE**（设备通道 0..9） | `sub_408260`/`sub_476380` → `sub_4071D0(this,v,2)` + 逐通道 `sub_4B68E0(设备, i, v)` | raw 13049-13058、90830-90841 |
| `sound:Volume3` (3) | **语音**（设备通道 12..14） | `sub_4082A0`/`sub_4763D0` → `sub_4071D0(this,v,3)` + 逐通道 `sub_4B68E0(设备, i+12, v)` | raw 13061-13070、90852-90863 |
| `sound:Volume4` (4) | **影片音量** | `sub_4071D0(this,v,4)` + `Engine[490000]`；`set:DependMovie` 决定影片是否跟随该类别 | raw 29960-29968、12150-12155 |

- `sub_4071D0(this, 音量, 类别)`（raw 12143）是**分类路由**：遍历 `Engine+94672` 起的声音对象表，按对象上的类别掩码
  （`0x10000/0x20000/0x40000/0x80000` → 类别 0/1/2/3）把音量下发；影片对象 `Engine[94671]` 另按 `set:DependMovie` 走 `sub_486970`。
- **开关**：`sound:SE`（SE 模块 `[261]`）、`sound:Voice`（语音模块 `[261]`）、`sound:Music`（Music 模块，`0xBC` 的三种模式值）、
  `sound:Movie`（`sub_408EB0` 读）。`sound:UseDirect` 参与 `0xBD` 的返回（1 = 走 DirectSound，2 = 兜底）。
- 相关 opcode：`0xC6` 设音量、`0xC5` 读音量、`0xC7` 读开关、`0xBB` SE 开关、`0xBC` BGM 开关、`0xBD`/`0xBE`/`0xC0` 读状态。

## 8. 语料惯用法（读脚本时能直接认出的模式）

- **音效一句**：`play-sound-effect <id> <ch>` 装载 → `i0b5 <ch>` 起播（播一次）；循环音用 `i0ba <ch>`；停用 `i0b6 <ch>`。
  实例：`src/SP2563.txt:409-410` = `play-sound-effect 2e 1` + `i0b5 1`。
- **语音页收尾**：`i2f6 <ch>`（复位通道）→ `i2f8 <ch> 0`（**把该通道 pan 复位到中央**；全库 op2 恒为 0）。
  实例：`src/SP2563.txt:17025` + `:17028`。
- **全局静音三路语音**：`src/SYSTEM4.txt:476-480` 的子程序 `label_00001ec8` = `i2f8 0 0 / i2f8 1 0 / i2f8 2 0 / ret`，
  由 `SYSTEM4.txt:11` 与 `:320` 调用（启动早期与某个状态切换时把三路语音音量清零）。
- **BGM 预览**：`CONFIG1.txt:2465 i0b7 29`（在设置界面里直接播 BGM 0x29）；停止用 `i0b7 0`（30 处，散在场景收尾）。
- **设置页反馈音**：`CONFIG2.txt:732-733` = `play-sound-effect 39a4 1` + `i0b5 1`（装到通道 1 后起播）；全页共 11 处 `i0b5`（其余 `i0b5 2` 直接触发通道 2 上已装载的音效）。
- **ADV 每页的语音收尾**：`i2f6 <ch>` + `i2f8 <ch> 0` 在全库有 8.6 万/1.4 万处，是出现频率最高的音频惯用法（`play-voice` 1.4 万处紧随其后）。

## 9. ADV 文本 ↔ 语音联动（引擎的"延迟语音"机制）

1. **文本项记录带语音**：Font 的文本项记录表（`Font+3364`，72B/条；见 `0x1D2`）里
   `+40` 的 flags 含 `0x40000000` 表示"这条文本带语音"，`+32` = 语音通道槽、`+20` = 语音 id、`+24` = 循环标志、`+28` = 音量。
   `0x2F4`/`0xC4`/`0x1BD` 除了起播，还会用 `sub_45EEA0(Font, 0, id, 循环, 槽, 音量)` 往记录表补一条（raw 29908、30062、33654）。
2. **显示该文本时才真正起播**：ADV 显示路径（raw 76888-76907）读记录的 `+32`/`+20`：
   - 若 `sub_404CB0(Voice)`（语音通道忙）**且** `v182[槽] > 0`（该槽已排过至少一条）⇒ 入队 `sub_409E10(Engine + 28·槽 + 699252, id)`；
   - 否则立即 `sub_4BB840(Voice, 槽, id, +24, +28)`。
3. **队列每帧冲刷**：raw 19967-19999 —— 3 条槽各一条 28B 的环形队列（`head/tail/游标`），
   当 `!sub_404CB0(Voice)`（没有通道忙碌）时取一条起播，第 5 参（pan）取 `Engine[5053+槽]`。
4. **ADV 激活位期间只寄存**：`Engine[174801] & 0x8000000` 置位时，`0x2F4`/`0xC4`/`0x1BD` 不立即起播，只把
   （id, 循环标志）写进 `Engine[122505+ch]` / `Engine[122508+ch]`（ch = 0..2；`0xC4`/`0x1BD` 固定 ch = 0）；
   该位清除时（raw 20146-20159 消息关闭路径、24966-24979）逐 ch 冲刷 `sub_4BB840(Voice, ch, id, 循环标志, Engine[5053+ch])`（第 5 参 = pan）。
5. **`Engine[122501]`**：`0x2F4`/`0xC4`/`0x1BD` 末尾按语音开关置 1、`0x2F6` 置成 `sub_404CB0` 的返回值，
   读者见 raw 13708、28560（"有语音在响/已登记"状态的判据）。

> 这四步合起来才是「语音跟着文本走」：**记录 → 显示时起播或入队 → 每帧排水 → ADV 位期间挂号**。
> 任何一步缺失都**不报错**：最坏表现只是"语音与文本错位/同时响/被吞"。

## 11. 实现所需的建模清单与方案评估（摘要）

完整评估见 **[`app/amayui-emulator/docs/13-audio-plan.md`](../../app/amayui-emulator/docs/13-audio-plan.md)**。要点：

- **数据**：全库音频 13968 个 / **1.54 GB**，全是 **RIFF PCM16 WAV**（SE/少量语音）+ **Ogg Vorbis**（BGM/大部分语音），
  **没有任何 `AOGG`**（引擎第三个解码器在本作没有用例）；id 就是 `SYS4INI` 统一文件 id，`FileSource.readById(id)` 已能取字节。
- **要建模的三层**：① 资源取字节通道（已有 `readById`，只需补 IPC 或自定义协议）；② AudioEngine（10 条 SE + 3 条语音 + BGM，含音量/pan/循环/延迟/仲裁）；
  ③ 与帧循环/ADV 激活位的挂钩（延迟播每帧泵、ADV 位期间寄存与冲刷）。
- **不需要引入任何新库**：Chromium 的 `decodeAudioData`/`<audio>` 覆盖这两种格式，混音用 Web Audio 原生节点；
  唯一建议新增的是 **自定义协议 + Range**（Electron 内置能力）用于 BGM 流式。
- **状态字段没有 VM 可见效果**：没有任何 opcode 能读回 `设备[327/342/375/390+ch]`、`Engine[5053+ch]`、`Engine[122501]`
  （`0xC5`/`0xC7` 读的是配置注册表）⇒「只做状态不做声音」没有意义。
- **工作量**：S0 管道 + S1 SE + S2 语音 + S3 BGM + S4 验证 ≈ **4.5–7 人日**（最小「UI 有声音」集 3–4 人日；
  若要「语音跟着文本走」需先建模文本项记录表，+1–2 人日）。
