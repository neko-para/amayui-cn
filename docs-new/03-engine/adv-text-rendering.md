## 0. 一句话结论

AGE 的文本是**「GDI 把整串（或逐字）画进"每窗一张的离屏表面"，再按行一块块贴到画面」**：

```
脚本 show-text/display-furigana
   → sub_46BE30 逐字量宽排版（逐字 push 24B 字记录 + 按换行 push 120B 文本记录；注音配对）
   → 生成时就把「该窗全部文本」画进 该窗私有离屏表面 surfaces[20+win]
   → 每帧由主循环泵 sub_45BE20 把「下一行」贴出去（= 逐行显现，不是逐字重画）
   → 合成：DrawMode=1 走 Scene 的 DrawItem；DrawMode=0 走 dd surface blit
```

⇒ **引擎里"逐字显示"的观感来自"逐行/逐字块被一块块贴出"，而不是"每帧重画整行前 N 字"**；
也**不存在**"每字一个 quad / 字形纹理 atlas"。文字被合成进**每窗一张的表面/纹理**。

## 2. 两条绘制路径（`set:DrawMode`）

`Engine + 667856`（= `Engine[166964]`，俗称 DrawMode）：

| 值 | 路径 | 文本绘制 |
|---|---|---|
| **0** | DirectDraw / GDI | `TextOutA` **整串一次**画进该窗私有 dd 表面的 DC；描边 = 5 次整串；开 AA 时改为 lock 表面内存软件贴字形 |
| **1** | Direct3D / D3DX（**自研，不是 `ID3DXFont`**） | **逐字** `GetGlyphOutline` + 软件合成进 Scene 的该窗纹理 |

- 写入：raw 23572-23574（启动读配置 `set:DrawMode`）→ 31364-31378（opcode `0x200` = `ComSetDrawMode`；脚本 0 次使用）→ 35271（设备 Reset 后重读）。
- **随包 `SYS4REG.INI` 无 `[set]` 段** ⇒ `GetConfig("set:DrawMode")` 返回 0（`sub_4957F0` raw 113008：缺键写 0 并返回 0）
  ⇒ **本工程实测路径 = DirectDraw/GDI**。
- 两条路径**都没有字形纹理 atlas**：D3DX 路径只有内存字形位图缓存（hashtable `Font+3444`、位图 `+3524`/`+3528`(1/4 强度)、计数 `+19908`、`GLYPHMETRICS +19912+20*i`），
  且被合成进"每窗一张表面"（`sub_49ED60` 取尺寸 + `sub_4A3890` LockTexture + `sub_46D9F0` 逐像素写 + `sub_4A3910` UnlockRect）。

## 3. 从脚本到像素的完整链路

### 3.1 入队与排版：`sub_46BE30(Font, win, 本文, 注音, flag)`（raw 83363-83997）

> ★**`display-furigana`(0x196) 的 op2（本文词）也是正文**：`sub_46BE30` 的第 3 参是"要铺排的字符串"、
> 第 4 参是它的注音（raw 83487/83507 `ArgList=a3; lpString=a4`）。真实剧本用它把词从句子中间切开
> （SC0330.txt:2501-2503 等 **6341 处**同型）⇒ 只记注音、不追加 op2 的症状就是**"汉字丢失"**。
>
> ★**换行方向恒为横向**：`sub_46BE30` 里**没有** `Font+235108` 的任何引用
> （`grep 235108` 的 16 个读点全在绘制函数里），换行判据恒为 `penX > win+36`。

- 入口分派：`0x6E show-text`（`sub_41EB20` raw 28330，`注音=0`）、`0x196 display-furigana`（`sub_41FC20` raw 29081/29088，`注音=op3`）、`0x7D`（整数→十六进制串）。`0x71`/`0x72` 也传 `Engine[97055]`（= `Font+235128`? 否：`Engine+388220`）当"消息 ID"。
- **换行判据**（raw 83565-83730）：

```text
while (*p):
  (ch, len) = 解 1/2 字节（SJIS）
  GetTextExtentPoint32A(+1108 /*测量 IC*/, ch, len, &size)   # 83596 像素宽
  ovf = sub_475CF0(win, 前一行记录.x + size.cx, 前一行记录.y + size.cy)
  #   sub_475CF0(90427): bit0 = x > win+36 ; bit1 = y > win+40
  if ovf & 1:   # 超右边界 ⇒ 换行
      push 120B 文本记录(sub_45E870)          # ★按**换行**压（24B 记录是逐字压的，见 §3.3.1）
      有注音 ⇒ 再 push 一条并把 24B 记录的 +0 置 1（标成ルビ）   # 83693
      行首复位；p += len
  elif ovf & 2: # 超下边界
      error("警告：文字がウインドウ内に収まりません")           # 83722
      break
```

- **没有禁则处理**（行首/行尾禁则表全文件不存在），**没有 `0x0A` 显式换行处理**；溢出即硬断。
- **注音配对**：24B **字**记录 `+0` = 种类（`0`=本文 / `1`=ルビ），`+20` = **组 ID**（本文与它的注音同组）。
  对齐时（`sub_4572A0` raw 68886-68951 / `sub_4576C0` raw 69147-69232）只累计 `+0==0` 且同组记录的 x 取 min/max 当"本文实际宽度"，再把注音叠上去。
  注音串按比例缩短（raw 83682：`2 * (rubyLen * baseUsed / baseTotal / 2)`）。
- **字宽是"字号的一半 × 字节数"**：`CreateFontIndirectA` 时强制 `lfWidth = lfHeight / 2`（raw 71055-71060、24063-24068）。
  GDI 对 DBCS 字体的 `lfWidth` 按**半角**宽度解释 ⇒ **全角字 = 2×lfWidth = 1em，半角字 = 0.5em**（等宽网格）。
  这正是 `sub_455ED0` 能直接用 `strlen(串) * lfWidth` 算半宽带的原因（raw 68065/68070）。

#### 3.3.1 为什么是"一个字"而不是"一行"（2026-09 订正）

早先把 24B 记录当成**行记录**（于是"一步 = 一行"），据此把重写侧的显现预算算成
`行数 × MessageSpeed` —— 结果**整段快了"每行字数"倍（~14×）**，设置里的「显示速度」滑条在
emulator 里几乎看不出效果（用户实测"文字出现的速度几乎没有变"）。实证（`sub_46BE30`，raw 83363-83997）：
**推送 24B 记录的那一行就在"逐字循环"里面**：

```c
if ( **(BYTE **)ArgList )                       // 83571：还有字符
  do {
    v24 = *v111;                                // 83576：当前字节
    if ((unsigned __int8)v24 >= 0x20u && ...)   // 83578-83592：解**一个**字符
        String[0] = v24;                        //   单字节
    else { *(_WORD *)String = *(_WORD *)v111; v112 = 2; }   //   或双字节
    String[1] = 0;                              // 83593
    GetTextExtentPoint32A(hdc, String, strlen(String), &psizl);   // 83596：量**这一个字**的宽
    v25 = psizl.cx + *v23;                      // 83597：本字右边界
    v27 = sub_475CF0(win, v25, v93);            // 83601：越界判据（bit0 右 / bit1 下）
    if (v27 & 1) { …换行：push 120B 文本记录(sub_45E870, 83655)… }   // 83607
    …
    sub_455ED0(_this, v5 + 20, x, y, String, Font+1360, Font+1364, Font+1372, 0, 1);  // 83832：画这一个字
    v122[0] = 0; v122[1] = v75; v122[2] = …; v122[5] = win[284];
    sub_45D120((_DWORD *)(v77 + 44), v122);     // 83918：push 一条 24B 记录（★就在这个逐字循环里）
  } while ( *v111 );                            // 83920：下一个字符
```

- `String` 是**单个字**（`String[1] = 0`；双字节时 `*(_WORD *)String = *(_WORD *)v111`），
  `strlen(String)` / `GetTextExtentPoint32A` 都按它量宽；
- `120B 文本记录`（`sub_45E870`，83655）才是**按换行**压的；24B 记录与它**不是**一回事；
- 注音标记 `[+0] = 1`（`*(win+48 - 24) = 1`）是给**某个字**打标，`sub_45BE20` 的 `while (rec[0])`
  只是把跟在这个字后面的注音记录一起贴掉；
- ⇒ **一步 = 一个字**、节拍 = `MessageSpeed` ⇒ 整段耗时 = **字数 × MessageSpeed**。
  `INITREGMES.txt:6 i1b5 19` = 25ms/字（脚本自己写的默认），随包 INI 的 `MessageSpeed=5` = 5ms/字，
  滑条 `100 - 值` ⇒ 1..99ms/字（一页 40 字 = 40ms..4s，旋钮手感正常）。

**"逐字/逐行"的真正驱动**（第二层能力，指令枚举不出来）：

| 环节 | 证据 |
|---|---|
| 主循环每帧 **只派发 1 条脚本指令** | `sub_411900` raw 20161-20165（`Engine[675996 + op]` 派发表，`ip += 4*操作数个数`）；`effect_flags & 0x8000000` 时进入 |
| 另一条泵：`sub_409400`（raw 13780-13970）逐窗 `while (!sub_45BE20(Font, win)) ;` 自旋 | 13847/13907/13920/13944/13962 |

### 3.4 合成到画面

| 路径 | 方式 | 证据 |
|---|---|---|
| `DrawMode=1` | 文本窗的每行/每注音字都是 **Scene 的 DrawItem**（`Scene+1032` map，key = id = 层序）；帧末 `sub_4B4040(Scene)` 按 id 四路归并刷出 → EndScene → Present | 136821-136942；136838 |
| `DrawMode=0` | 文本画进**私有 dd 表面**后由 `sub_45BE20` **逐行 blit 到 dd 表面 0**（`win+4`，构造置 0 且从不改写）；`sub_43D870` 即 `ddCpySpriteSurfaceFast` | 72427-72437；90444；48907 |

- GDI 的 DC 必须 `ReleaseDC` 解锁后表面才能被后端使用 ⇒ **文字一定在 Present 之前进入表面**，不可能"Present 后补画"（配对证据：68088→68129、86374→86379、89124→89129）。
- **背景/边框不是纹理**：dd 路径用 `ddFillSurface` 填底色；D3D 路径用 DrawItem 的颜色/alpha 字段。窗体的"边框图"由脚本用普通 `draw-texture` 画（`0x82` = `sub_466000` 重绘该窗全部图元）。
- **淡入**：不存在"把文字颜色朝背景插值"的代码。dd 路径靠"整窗画在离屏表面 → 逐行贴出"；D3D 路径靠每行 DrawItem 的**颜色动画窗**，时长 = `MessageSpeed * MessageFade / 100` ms（5×250/100 = 12）。

**静默症状（两种反向错法都会出现）**：
1. 渲染侧**每次重绘实时读**全局样式 ⇒ 后写的窗把先前排好的窗染成自己的色

2. 把"写全局样式"当成"给所有已排版的窗换色"立刻重绘 ⇒ 同样的错画面。
两种都不报错、不崩，只是颜色错 —— 因此必须**在入队时把样式钉住**（重写侧 = `MsgSlot.fontStyle`）。

## 7. 与 emulator 现状的差距（本节是产物状态，不是分析依据）

**本次分析顺带查实的既有错误**：

1. **`message:MesWinAlpha` 误绑**：`engineConfig.ts` 把 `message:meswinalpha` 绑到字段 `21668`，
   而 `21668×4 = 86672 = Font+1376 = message:MessageSpeed` —— **两个键绑到同一字段**，后写者胜（= 8）。
   实际 `MesWinAlpha` **不进任何持久字段**，只由 `0x131`/`0x141` 按名读写。
2. **`0x7F` 的注释错**：它读的是 `_this[21668]` = **`message:MessageSpeed`**（不是"消息窗 α"）。
   实现（读字段）是对的，注释与 `0x131` 的说明把它写成了 α。
3. **`0x74` 的语义错**：它是 **`SetMessageSpeed`**（写 `Engine[21668]`），不是"放大百分比"；
   `0x2EE` 写的 `Font+235128` 才是 `message:MessageFade`。
