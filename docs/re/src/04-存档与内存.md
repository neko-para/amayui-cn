# 存档与内存扫描（src）

> 级别：**已确认**（存档容器实测）/ **部分结论**（内存扫描未命中，有解释）。

---

## 1. 存档 ≠ BIN 快照（已确认）

- `SAVE113.DAT`（`%localappdata%\Eushully\...\SAVE`）是 **`S4SD460B`** 容器（3.5MB），非原始 BIN 快照。
- 在其中搜索 DWORD 序列 `2 f 2 2 1 1 1 1 7 a a a`（对应索引 `52a0b5~52a0c0`）：**原始 / 带类型标签 / 653 个 LZSS 节解压后 全部未命中**。
- 而这些值确在 `data/EBINIT.txt`（静态数据表）。
- 推论：存档是**结构化动态状态流**，**不持久化静态数据表**（静态表由启动时从 BIN 载入）；「整个 BIN 快照」假设**不成立**。

---

## 2. 进程内存扫描（部分结论）

- 进程 33340（`install/AGE.EXE`，运行中，WorkingSet ~270MB）。
- 扫描器（OpenProcess+VirtualQueryEx+ReadProcessMemory）合法并读到 `"SYS4450"`（脚本已载入，@`0x1AF9A8`）。
- 但 DWORD 序列 `2 f 2 2 1 1 1 1 7 a a a` 在内存：**连续 48 字节 / 8 字节槽(值+meta 两种排布) / WORD / raw 全部未命中**。
- 推论：要么这些 EBINIT 数据表全局值在当前状态**尚未写入**（游戏未执行到该段），要么全局 int 数组**不是 `基址+index×4` 平铺**。

---

## 3. 核心障碍：`script 索引 → 实际内存地址` 映射（未解，靠引擎）

- 脚本里的 `(global-int 0x53f48c)` 是 **VM 抽象索引**，不是真实地址；真实地址 = `全局整型数组基址 + index×4`，**基址是引擎运行时分配的**。
- 静态分析（`03-掉落数据.md`）在**索引空间**自洽（数据写与消费用同一索引），足够**读写掉落表数据**；但**运行时断点 / 解析存档 / 引擎 hook** 都需要真实基址。
- 只有**引擎**能给出基址/布局（或运行时观测）。→ 见 `docs/re/engine/03-opcode分发与解释器.md` §5-4。
