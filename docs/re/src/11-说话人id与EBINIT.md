# 说话人 id ↔ EBINIT（CNINIT 缺席时补名）

> 级别：**已确认**（EBINIT 值字段 + CNINIT 说话人表交叉实证）。
> 产出工具：`scripts/annotate-speaker.js`（为 src 下每个 SC/SP 文本页插入 `// FROM: <id> <名称>` 注释）。
> 本文档承接 `docs/AGE脚本语言与物品数据结构.md` §7（说话人 id ↔ EBINIT 对照）。

---

## 1. EBINIT 单位记录结构要点

- 每条单位记录：id 值字段 `mov (global-int 5298e5+<记录序>) <id×10>`、名字槽 `set-string (global-string 17ab7+<记录序>)`、称号槽紧随其后；追加包单位写在 `$1$–$5$EBINIT`，地址沿用基址。
- **记录序 + 1 = 说话人 id（3f37）**；追加包记录同样适用（如 0x81 的 id 写入在 `$1$EBINIT` 的 `529965` = 5298e5+128）。
- ⚠️ 注意 id **值字段**与 CNINIT id 并非处处一致（伊欧露/米凯优、罗兹利奴/莉秀恩兹利互换；岚燐结骑值 0x33 vs 说话 0x34；フィア＝イブラム值 0x170 vs CNINIT 0x1a）。**说话人归属以实际使用的 id + 记录序为准，CNINIT 为显示名权威。**

## 3. CNINIT 0x132 重复（疑似配置错误）

- CNINIT 0x132 同时登记 ティエネー（14ae0e）与 錯縛の水精（14ae14）；0x138 无条目，但它是实际使用的说话人 id（SC6580），数值上介于 0x132 与 0x14a 之间。
- 两者称号均为「精霊／水精種」、条目结构相同（仅名字+显示名）→ 重复极难察觉。
- EBINIT 值字段给 錯縛の水精 写 0x132（与 CNINIT 相同），但该字段已知 ≠ 说话人 id，不构成反驳。
- 判断：錯縛の水精 的 CNINIT 条目疑应为 0x138（待剧情/图鉴复核）；0x132 实际从未作为说话人出现，故该错误平时不可见。

## 4. 工具

- `scripts/annotate-speaker.js`：为 src 下每个 SC/SP 文本页插入 `// FROM: <id> <名称>` / `// FROM: none`；名称优先级 CNINIT（含追加包）→ `NAME_OVERRIDES`（EBINIT 核实）；`--refresh` 替换已有注释；assemble 预处理丢弃 `//` 行注释，不影响编译产物。
