# 地图地板数据（MPINIT）解析 — 地图大小参数与 copy-local-array 填值

> 分析对象：**地图地板数据**，存放于 `data/*MPINIT.txt`（base + `$1$–$5$`，共 6 个文件）。
> 与 `docs/re/src/09-地图内单位.md`（STINIT 单位摆放 + STINIT2 场景/地点）配套：STINIT 定义「地图启动/单位摆放」，
> **MPINIT 定义「地图地板」**（网格地形）。
> 产出：确认「地图大小参数」= `5cd85`（列数）/ `5cd86`（行数），以及每个地图地板块 `copy-local-array` 的填值形式与可选值。

---

## 0. 结论速览

- **地图 id = (`b228` 地点 id, `b229` 地点内序号) 联合比较**（`eq (local-int 0) (global-int b228) X` + `eq (local-int 1) (global-int b229) Y`，`and` 后 `jcc`）。信息来自 STINIT2 场景记录的 `loc` 槽（`0x14e4e1`）与 `seq` 槽（`0x14e8c9`）。✅ 已确认。
- **地图大小参数**：块头两行
  - `mov (global-int 5cd85) <V1>` → **列数（cols）**
  - `mov (global-int 5cd86) <V2>` → **行数（rows）**
  - 网格为 `V1(列) × V2(行)`，单位/特殊点位以 1-based `(列,行)` 落在此网格上。✅ 已确认。
- **地板数据布局（已确认）**：每个地图块写出
  - **`2×行数` 条** `copy-local-array`（每条 = 一行地板，起点 `0x5bd46`，**步长恒 `0x41`=65**）；
  - 每条数组 **`2×列数` 个元素**。
  - 即地板以**逻辑网格的 2× 分辨率**存储：数据网格 = `(2×列) × (2×行)`。
  - 每个逻辑格子对应 **2×2 子块**，其**左上角（偶数-偶数下标）恒为 `0`**，其余 3 个子块携带地形码。
- **填值 / 可选值**：全部地图都含**基础集 `{0, 1, 2}`**；**可选地形码** `{d, a, 3, e, 4, 8, b, c, f, 10..13, 19, 1b, 1d, 1e, 20, 22..24, 26, 27}`，其中 `d`（0xd）最常出现。

**决定性判据（城砦迹地 8行7列）**：`(0x50, 0x1)` 块中 `5cd85 = 7`、`5cd86 = 8`；且该图特殊点位坐标（`output/stinit-special-points.csv` 地图号 `321`）**列 ∈ [1, 7]、行 ∈ [1, 8]**——正是「7 列 × 8 行」。⇒ **`5cd85` = 列数，`5cd86` = 行数**。（若反过来把 `5cd85` 当行，则网格成 7 行 8 列，与锚点 8行7列及点位坐标范围矛盾。）

> ⚠️ 关于 `(b228,229) → 地图名` 的赋值：STINIT2 场景记录的 `(loc, seq)` 采用「**归属于下方场景名**」规则（见 `docs/re/src/09-地图内单位.md` §1.3③），直接按地址槽号读会**整体偏一位**（seq 一致偏高 1）。以锚点为准：`堆積した砦路樹` 实为 `(loc=2, seq=1)`（非直接读槽所得 `(2,2)`）、`崩れた調査区域` 为 `(2,2)`。MPINIT 块本身按 `(b228, b229)` 直接定位，无需再偏移。

## 2. `copy-local-array` 地板块的形态（已确认）

每个地图块（以 `eq ... b228 X` / `eq ... b229 Y` 开头，`jcc` 后进入）的结构：

```text
mov (global-int 5cd85) <cols>       ; 列数
mov (global-int 5cd86) <rows>       ; 行数
copy-local-array (global-int 5bd46) [ 2*cols 个元素 ]
copy-local-array (global-int 5bd87) [ 2*cols 个元素 ]   ; 0x5bd87 = 0x5bd46 + 0x41
copy-local-array (global-int 5bdc8) [ ... ]
...
; 共 2*rows 条，最后一条地址 = 0x5bd46 + (2*rows-1)*0x41
```

**不变量（全量实证：130 个子网格 = 111 个地图守卫，其中 2 个复合守卫拆成多子网格）**：

| 量 | 值 | 证据 |
|---|---|---|
| 首数组基址 | 恒 `0x5bd46` | 130/130 |
| 行间步长 | 恒 `0x41`（=65） | 全量 3820 条数组、3690 个相邻对全相同 |
| 数组条数 | = `2 × 行数(5cd86)` | 130/130 |
| 每数组元素数 | = `2 × 列数(5cd85)` | 130/130 |

> 说明：`0x41`（65）是「每行地板」的固定内存步长；`copy-local-array` 把字面数组写入**从 `0x5bd46` 起、每条 `+0x41` 的全局数组**中。条数只写 `2×行`，故行内实际码长 = `2×列`，其余槽位留空/为 `0`。

**逻辑格子 ⇒ 楼板子块**（以 `数据[r][c]`、均 0-based 计）：逻辑格 `(列, 行)`（1-based）→
- 子块覆盖 `数据[2*(行-1)..2*(行-1)+1][2*(列-1)..2*(列-1)+1]`（2×2）；
- **左上角 `数据[2*(行-1)][2*(列-1)]` 恒为 `0`**（已抽查 城砦迹地/迷宫1F/砦路樹/崩れた調査区域，全部满足）；
- 其余 3 个子块携带地形码。

## 5. 验证方法 / 结论分级

- **已确认（数据实证）**：`5cd85`=列数、`5cd86`=行数（城砦迹地 8行7列 + 锚点全命中）；`(b228,b229)`=地点+序号联合地图 id；地板数组起点 `0x5bd46`、步长 `0x41`、条数 `2×行`、每条约 `2×列`。
- **推测**：地形码 `0/1/2/3/d/a/e/…` 的具体视觉/功能含义（墙 vs 地面 vs 特定材质）——需对照地图 tileset 资源表或引擎读地板数组的函数分支确认（下一步可交叉验证 `AGE.EXE` 读 `0x5bd46`/`5cd8x` 的存取逻辑）。
- **待定**：`(b228,b229) → 地图名` 的精确赋值受 STINIT2「归属下方场景」规则影响，MPINIT 块本身无需偏移，但若要「地点→地图清单」需遵循 `docs/re/src/09-地图内单位.md` §1.3。

## 6. 复现

```text
node scripts/export-mpinit-maps.js [--raw]
  --raw 用 data/，缺省用 src/（src 与 data 该文件代码部分一致）。
  产出：output/mpinit-map-summary.csv（每子网格一行：文件/地点id/序号/子网格/列数/行数/数组条数/每数组长/首址/步长/独立值数/取值集合）。
  校验：130 个子网格全部满足「条数=2×行 / 每条=2×列 / 首址0x5bd46 / 步长0x41」。
```

核心解析逻辑（按块切分并统计）：

```text
按 "eq (local-int 0) (global-int b228) X" 找块头 → 配对该块 "eq (local-int 1) (global-int b229) Y"
→ 读块内每一组 "mov (global-int 5cd85) C" / "mov (global-int 5cd86) R"（复合块可能多组）
→ 收集该组后的 "copy-local-array (global-int <addr>) [ ... ]"
→ 校验：条数 = 2*R、每条元素数 = 2*C、首址 = 0x5bd46、步长 = 0x41。
```
