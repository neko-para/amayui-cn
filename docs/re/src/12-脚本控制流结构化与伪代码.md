# src 脚本控制流结构化还原（将字节码反汇编转为结构伪代码）

> 级别：**方案 + 工具已实现**（`scripts/re/structured_cfg.js`，在 `src/*.txt` 上实测；结论属「工程实现」而非引擎/数据实证）。
> 目标：把 AGE 引擎的**反汇编脚本**（`src/*.txt`，含大量 `jmp`/`jcc`/`label_*`）还原成**可直接阅读的业务逻辑伪代码**（`if`/`else if`/`while`、缩进制表、无括号风格），便于后续**查找分析业务逻辑**。

---

## 1. 背景与输入

AGE 脚本是一套**字节码**，经 `age-asm.exe -d` 反汇编成 `src/*.txt`。字节码格式见 `engine/00-脚本字节码格式与工具链.md`；opcode 语义见 `engine/06-opcode到handler映射表.md`；`jcc` 语义见 `src/02-jcc语义.md`。

- 指令 = `mnemonic 操作数…`，操作数为 **typed 操作数**（`(local-int N)` / `(global-int XXXX)` / `label_XXXXXXXX` / 立即数 / `"字符串"`）。
- **`jcc` 是两目标条件跳转**（opcode 0xA0，关键）：
  ```
  jcc cond A B
      cond != 0 且 A != 0xFFFFFFFF   -> goto A
      cond != 0 且 A == 0xFFFFFFFF   -> fall-through（不跳）
      cond == 0 且 B != 0xFFFFFFFF   -> goto B
      cond == 0 且 B == 0xFFFFFFFF   -> fall-through
  ```
  `0xFFFFFFFF` = 「该分支不跳 / 落到下句」占位符。
- **`jmp L`**：无条件跳转。**`call L`**：脚本内子程序调用（`ret` 返回）。**`call-script`**：调另一个脚本。
- **`label_XXXXXXXX`** = 跳转/子程序入口锚点，`XXXXXXXX` 为字节偏移（十六进制）。

`src/*.txt` 同时含**汉化语法**（`"原文|译文"`、`@"译文"`、`/*…*/`、`// 输入原文` 注释、`end-text-line` 等）。控制行与 `data/*.txt` 基线逐字节一致；结构化脚本会**忽略文本行的翻译标注**，只取指令流。

## 2. 业界常用方法（Web 调研摘要）

把汇总裁面图还原成结构化程序是反编译器里的 **“structuring / control-flow structuring”** 问题，主流做法：

1. **基本块 + 控制流图（CFG）**：按「跳转/分支目标」与「分支指令之后」切分基本块，形成有向图（节点=基本块，边=控制流）。这是后续一切的基础。
2. **支配树 / 后支配树**：计算支配关系以定位**循环头**、**汇合点（join，后支配者）**。常用 **Cooper–Harvey–Kennedy 的“简单快速支配算法”**（近线性，适合大图），或 Lengauer–Tarjan。见 [CS Rice，A Simple Fast Dominance Algorithm](https://www.cs.rice.edu/~keith/EMBED/dom.pdf)；[rustc 支配实现](https://android.googlesource.com/toolchain/rustc/+/d59a28787b7ba06edbd1e4528a42b66d67dc6a19/compiler/rustc_data_structures/src/graph/dominators/mod.rs)。
3. **自然循环（natural loops）**：回边（`u→v` 且 `v` 支配 `u`）决定循环；区间分析（interval analysis）识别嵌套。见 [Tarjan 关联论文/区间分析](https://fenix.tecnico.ulisboa.pt/downloadFile/563345090416738/Thesis.pdf)。
4. **结构化算法（structuring）**：把 CFG 配成 `if/if-else/while/do-while/switch` 模板。代表：
   - **Schema-based（模式匹配）**：反复匹配控制流模式并合并为结构化节点。见 [decompilation.wiki：Schema-based Structuring](https://decompilation.wiki/fundamentals/structuring/schema-based/schema-based/) 与 [Structuring Overview](https://decompilation.wiki/fundamentals/structuring/overview/)。
   - **Gotoless / 模式无关结构化**：`No More Gotos`（Schwartz 等，NDSS 2015），用模式无关变换 + 语义保持改写，处理不可约图。见 [decompilation.wiki：Gotoless Structuring](https://decompilation.wiki/fundamentals/structuring/gotoless/)。
   - **Cifuentes 的结构化**（UQBT/反编译器经典）：按区间/区域递归分类生成语句树。见 [Structuring decompiled graphs（Cifuentes）](https://www.knihovny.cz/SummonRecord/FETCH-LOGICAL-c1565-9a0c6d9aadc6e5257e72f1aee1c9bbf493c8f613213367de4aed3c465cd8af7b3)。
   - **可约图 + 结构定理**：Böhm–Jacopini 定理说明一切可约流图可只用 `if/while` 表达（goto 消除）。见 [Böhm & Jacopini 定理（CBM.v4）](http://www.cs.ru.nl/~henk/CBM.v4.pdf)。
   - 综合史/难点：`30 Years of Decompilation and the Unsolved Structuring Problem`（mahaloz.re）。见 [Part 1](https://mahaloz.re/dec-history-pt1)。
5. **现代反编译器**（IDA Hex-Rays 微码、Ghidra P-Code、RetDec、Snowman）都在做类似的「CFG → 结构化 AST」，并处理不可约图/`goto` 兜底。

**对本工程**：AGE 字节码是编译器输出，CFG 几乎总是**可约**的，因此区间/支配类结构化算法能命中绝大部分 `if/while`；仅少数跳转到「远汇合」的代码会落到 `goto` 兜底。

## 3. 工具实现（`scripts/re/structured_cfg.js`）

纯 Node（ESM，`"type":"module"`），**零第三方依赖**；输出**确定性**（同一输入、同样运行结果一致）。核心是三段：**CFG 构造 → 支配/循环识别 → 递归结构化**。

### 3.1 解析
`parse(text)` 逐行读取，跳过头部（`==Binary…==`、`signature`、`local_vars`、`====`），用**括号/引号感知的 tokenizer** 把每行切成 `[mnemonic, arg0, arg1…]`；把 `label_XXXXXXXX` 锚定到「其后第一条指令」的**指令下标**，供跳转解析。

### 3.2 基本块 + CFG
`buildBlocks(sc)`：
- **leader（块首）**：第 0 条指令；**所有跳转目标**（`jmp/jcc/call` 的 `label_*`）；以及**每条控制指令之后**的一条（`jmp/jcc/call/exit/exit-script/ret/call-script`）。
- 把指令流切成基本块；每条块记录 `insts`、`succs`（后继）、`preds`（前驱）、`follow`（fall-through）、`branches`（jcc 的真/假目标）。
- **CFG 边**：
  - `jmp L` → `L` 块。
  - `jcc cond A B` → 真/假目标（`0xFFFFFFFF` 视为 fall-through = 下一块）。
  - `call L` → fall-through（返回地址）块；`L` 记为**子程序根**。
  - `exit` / `exit-script` / `ret` → 终结（无后继）。

### 3.3 支配 / 后支配 / 循环
`computeDominators` 用 **BigInt 位集**实现 Cooper–Harvey–Kennedy 迭代（每节点一位，交集即按位 `&`），对最大 4545 基本块的脚本仍毫秒级。`computePostdominators` 在**反向图**上加虚拟 `EXIT`，用于求**汇合点**（`ipdom`，即后支配者）。`findNaturalLoops` 用回边（`v` 支配 `u` 即 `u→v` 为回边）构造**自然循环**。

### 3.4 递归结构化（`structAnalyse`）
从过程入口递归 `emit(entry, exits)`，按当前块终结指令分派：

| 终结指令 | 结构 |
|---|---|
| 直落（普通指令） | 输出语句序列，继续下一块 |
| `jcc cond A B` | 检测 `if / if-else`：以 `ipdom`（后支配者）为**汇合点**，若一条分支是汇合点 → 单 `if`（真/假分支体）；两条分支都回到汇合点 → `if/else`；若一条分支终结（`ret`/`exit`）且无汇合 → 早退；都不满足 → `goto` 兜底。若 `jcc` **紧前一条指令**恰好是「给被测变量赋值」的数据指令，则**折叠**进条件（见下） |
| `jmp L` | 目标为未输出循环头 → 循环入口（落入 while）；目标只有单前驱 → 扁平化为顺序；否则 `goto L` |
| `call L` | **同脚本子程序调用**（见 §3.7）：渲染为 `call label_L()`，`L` 单独成过程 |
| `ret` / `exit` | `ret` / `exit`（过程终结） |
| 循环头 | 条件若为**单条赋值折叠**则 → `while <var> = <expr>`（每轮重算）；否则 → `while true { <条件计算>; if not <被测变量> break; 体 }`（保底，重算+保留副作用） |

**符号转写（数据指令）**：已知数据指令写为 `dst = …`。`eq d a b→d = a == b`、`add d a b→d = a + b`、`mov d s→d = s`、`and d a b→d = a & b`（位与）；位运算（engine 已核对 `sub_42F8B0`/`sub_42F920`/`sub_42FB40`）：`bit-set d b→d |= (1 << b)`、`bit-reset d b→d &= ~(1 << b)`、`check-bit d s b→d = ((1 << b) & s) != 0`。**实参个数与预期不符的指令**（如意外出现的三参数 `mov`）**原样保留**并记录（`[record]` 汇总输出）。

**条件折叠（保留副作用）**：只有 `jcc` **紧前一条**指令是对被测变量的赋值时才折叠，且**只折叠这一条**；其余中间赋值（如 `eq li[0]…/ne li[1]…`）仍保留为独立语句，故**不丢副作用**。负向（`if not var`）折叠后写成 `if <var> = <expr>, not <var>`；正向写成 `if <var> = <expr>`。

### 3.5 操作数命名

- **前缀 = 类型单词首字母**：`local-int→li`、`local-ptr→lp`、`local-string→ls`、`global-int→gi`、`global-ptr→gp`、`global-string→gs`（`float`/`float-ptr` 类推 `lf/lfp`、`gf/gfp`）。
- **索引/地址一律十六进制（小写，不带 `0x`，贴合源码）**：`(local-int a)→li[a]`、`(local-int 10)→li[10]`（=槽 0x10，非十进制 16）、`(global-int 1af3)→gi[1af3]`。
- 立即数保留原拼写；`0xFFFFFFFF` 改写为 `-1`；字符串操作数保留 `"…"`。

### 3.6 输出风格（符号化、部分折叠、无括号、无冒号）
```text
;; $1$AMINIT.txt
;; local_vars = ["4","1","1","1","1","1"]
;; --- procedure root=bb_0 (entry) ---
gi[14cacc] = 11
li[0] = gi[1af3] == 1
li[1] = gi[1c7d] != 1
if li[2] = li[0] & li[1]
    gi[b1fa] = 3
label_000000d4:
gi[14cacd] = 12
li[0] = gi[170d] == 1
li[1] = gi[1c7d] != 1
if li[2] = li[0] & li[1]
    gi[b1fb] = 3
label_0000016c:
exit
```
- **符号化**：数据指令写为 `dst = …`（`eq li[0] gi[1af3] 1` → `li[0] = gi[1af3] == 1`；`mov gi[14cacc] 11` → `gi[14cacc] = 11`）。
- **条件折叠（仅紧前一条）**：`and li[2] li[0] li[1]` 是 `jcc` 前最后一条、且写入被测变量 `li[2]` → 折叠为 `if li[2] = li[0] & li[1]`，同时 `li[0]/li[1]` 的赋值**仍保留**（不丢副作用）。
- **无冒号、无大括号**；`if not …` 折叠为 `if <var> = <expr>, not <var>`。
- **标签（label）保留策略（引用完整）**：**过程/函数入口**用 `label` 作过程名（`;; --- procedure root=… (label_…) ---`，即 `call` 目标=真正的 proc）。除此外，`label_XXX:` **只保留被真正引用**的锚点——引用来自 `goto`、或作为保留指令的 label 操作数（`call label_X`、遗留的 `jmp`/`jcc label`）。**未被任何东西引用的 label 被去掉**（如 REACH 里的 `label_00005938`）。引用集合是**全局的**（跨过程），因此跨过程/跨块的引用也能对上锚点。对于**被引用但未就地成锚的块**（不可约/回退分支把其分支目标块漏掉的情况，如 `call label_000031e4` 而其块未被结构化可达），在文件末尾以**stub 段** `;; --- referenced targets not reachable in structure (stubs) ---` 补出 `label_X:` + 该块指令，**保证每条 `call`/`jcc` 引用都有可见目标**。
- **4 空格缩进**制表；`else` 独立成行；`else if` 折叠；未结构化部分用 `goto label` / `label:` 兜底。
- **注释**：多行 `/* 原文存档… */` 与行 `// …` 被正确剔除（有状态扫描，不再漏进指令流）。
- **意外指令**（实参个数与预期不符）**原样保留**并在运行结束以 `[record]` 汇总（含示例与所在文件）。

### 3.7 `call`（本地 label）的语义（engine 侧已核对）

- **`call-script <id>`（0x3）**：调**另一脚本**，把整个 `ScriptContext` 帧入栈（40 帧上限），见 `engine/08-脚本上下文与调用栈.md`。
- **`call <label>`（0x8F → `sub_420560`）**：**同脚本内子程序调用**，**不换帧**。行为：
  1. 把「本指令之后的下一条指令位置」压入**当前帧自己的返回地址栈**：`return_addr = (ip − str_table)>>2 + 3`；栈为 `_this[256*cur + 97193]`（每帧 256 槽），栈指针 `_this[cur + 97153]`（每帧一个）。
  2. `ip = str_table + 4*label` —— 跳到目标 label。
  3. 若参数为 `-1`（0xFFFFFFFF）则把刚压的返回地址弹出（视为空调用）。
- **`ret`（0x5 → `sub_41A9B0`）**：`--sp`，弹出返回地址 `stack[256*cur + 97193 + sp]`，`ip = str_table + 4*该地址` 跳回；不为 `-1` 时另经 `_this[107437]` 读取一个返回/出参槽到 `_this[174801]`。
- 因此 **`call`+`ret` 是脚本内的 `gosub` 式函数调用**（可嵌套，同一脚本内不新建 VM 帧）；这与 `call-script`（跨脚本、frames[40] 入栈）是**两套并行**机制。工具据此把每个 `call` 目标拆成独立「过程」段并按 `label` 命名。

## 4. 用法

```bash
# 单文件打印到 stdout
node scripts/re/structured_cfg.js "src/$1$AMINIT.txt"

# 批量：对 src/*.txt 全部生成结构化版本到目录（确定性、可重复跑）
node scripts/re/structured_cfg.js --dir src --out .tmp/struct

# 一键驱动：src/*.txt -> src-reflow/<同名>.txt（并发，默认跳过 SC/SP）
node scripts/re/structured-cfg-reflow.js                   # 默认 src -> src-reflow，跳过 SC/SP
node scripts/re/structured-cfg-reflow.js src src-reflow .txt
node scripts/re/structured-cfg-reflow.js src src-reflow .txt --sc-sp   # 包含 SC/SP
node scripts/re/structured-cfg-reflow.js src src-reflow .txt --jobs 8  # 覆盖并发度
cd scripts && npm run struct-reflow -- src src-reflow .txt --sc-sp

# 导出 CFG（graphviz DOT / JSON）便于可视化检查
node scripts/re/structured_cfg.js "src/$1$BTANINIT.txt" --dot /tmp/x.dot --json /tmp/x.json

# 调试：结构诊断
STRUCT_DEBUG=1 node scripts/re/structured_cfg.js "src/$1$BTANINIT.txt"
```

要点：**输出确定性** —— 同一 `src/*.txt` 每次运行得到完全相同的结构化文本，可直接作为后续「在原始脚本上补 if/else、制表排版」的参考基线。

## 5. 已知限制 / 后续

- **`and`/`or` 语义**：AGE 的 `and`(0x56)/`or`(0x57) 实为**位运算**（`&`/`|`），但多数用于把 `eq/ne/…` 产生的 **0/1 标志**链起来。现按位运算符号化（`li[3] = li[1] & li[2]`），语义忠实；阅读时若遇位掩码（如 `li[x] = gi[..] & 10000`）注意其是 `& 10000`。
- **循环**：条件为**单条赋值**时折叠成 `while <var> = <expr>`（每轮重算）；多步条件则 `while true { <重算>; if not <var> break; … }` 保底。`do-while`（测试在底）用 `do { 体 } while <var>`。
- **条件折叠粒度**：只折叠 `jcc` **紧前一条**赋值（且是已知数据指令）；若是多级中间量（如 `and li[7]=li[5]&li[6]`，`li[5]/li[6]` 为中间值），中间的 `li[5]/li[6]` 赋值仍保留（不全部链式内联）。
- **意外指令**：实参个数与预期不符（如三参数 `mov`）**原样保留**并以 `[record]` 汇总；本工程实测后此类由**注释未剥离**导致的「伪多参」已随注释修复消失（当前 0 条）。
- **switch**：`eq v, c_i + jcc` 构成的**分发梯**识别为 `if/else if` 链（`else` 里再 `if`），未单独生成 `switch`；可读、但不紧凑。
- **不可约 / 远跳转**：降到 `goto` + `label` 兜底（AGE 极少见）。
- **子程序**：按 `call`+`ret` 划分（同脚本 gosub，见 §3.7）；若调用目标同时被主流程落达则并入主流程（暂以内联对待）。
- 如需更强，可参考 `src/02-jcc语义.md` Todo：补全 50 条两分支 `jcc(cond,label,label)` 清单作校验。
