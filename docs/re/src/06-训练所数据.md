## 1. 单位块结构（已确认）

DRINIT 以**训练者单位**为单位分块（**非被训练对象**——训练者**消耗**满足条件的单位）。块头：

```
eq (local-int 0) (global-int f8c44) 32      ← 训练者单位 id（0x32 = 流燐结骑）
jcc (local-int 0) ffffffff label_00001ac0
```

- `0x32` 是**训练者单位 id**，1-based（对应 EBINIT 单位名表 `0x17ab6 + 单位id`）：`0x32=流燐結騎`、`0x33=溶燐結騎`、`0x34=嵐燐結騎`、`0x35=華燐結騎`、`0x37=霊虚二舞イ人ノ傀`、`0x38=愛ヲ模リ咲ヒメル傀`。这 6 个单位是**训练者**，它们的种族/性别在 **EBINIT**（见 `07-单位种族与性别字段.md`）。
- 块内随后是**若干条「训练配方」**，每条描述**需要消耗什么单位**、以及训练奖励：

```
set-string (global-string 1d491) "★１以上の冷却属性　×５|★１以上的冷却属性　×５"
mov (global-int 6c5596) a              ← meta 数值 1
mov (global-int 6c565e) 5              ← meta 数值 2
mov (global-int 6c578a) 3
mov (global-int 6c6086) 14d
```

- 一条训练内容 = 1 个 set-string（**描述文案**，`日文|中文`）+ 跟随若干个 `mov (global-int K) V`（**meta 数值**）。
- **块结束**：`label_00001ac0`（下个单位的 `eq`）。

## 2. TID 与「K − TID」列模型（已确认，本次核心）

设 **`TID_BASE = 0x1d490`**：

- **`TID = 描述串地址 − 0x1d490`** —— 训练配方在该训练者课程内的**槽位序号**。
  - base 文件：TID `1..0x36`(54 条)；追加 `$3$`：续 TID `0x37..0x50`(unit 32..35) / `0x37..0x3c`(unit 37..38)。
- **关键事实**：**每个训练者块都从 `0x1d490` 重新起算描述串地址**（六个块的描述串都从 `0x1d491` 开始）。所以 `TID` 是**块内槽**，不是全局 id。`(训练者id, TID)` 才能唯一定位一条训练配方。
- **每条训练配方的元数据** `mov (global-int K) V`：按 **`列 = K − TID`** 归位。
  - `K` 以 `global-int` 地址编码为 `某字段基址 + TID`，故**同一字段在不同训练者/不同文件中的 mov 具有相同的 `K − TID`**（实测 `0x6c5596(K)-1(TID) = 0x6c55cc(K)-0x37(TID)` = `0x6c5595`）。
  ⇒ **「K − TID」正是字段 id**：同列 = 同字段；某条训练配方没用该字段则该格留空。

**「K − TID」的一致性由算法保证且已实证**：跨 base/追加、跨单位、跨字段全部吻合；全量 440 行、118 个不同字段偏移、**0 冲突**。

> ⚠️ **修订（REACH 实证）**：「K − TID 恒为字段 id」**只对单槽字段成立**。训练配方的**效果**奖励里有两类是**多槽数组**（引擎按 `K = 数组基址 + TID×槽宽 + 槽` 对齐），K−TID 会随 TID 漂移，**不能**用 K−TID 当字段 id——否则同一语义奖励会散到多列：
> - **耐性奖励** `6c5851[配方×8+槽]`（槽 0..7）：每配方给一种「X 耐性」（`X` 与消耗属性一致）。
> - **能力值奖励** `6c5b71[配方×13+槽]`（槽 0..12）：每配方给一项「能力值+N」。
> 二者均由 REACH `label_0000974c` 读取并拼成效果文案。导出脚本已按「数组基址+槽」拆列。

## 3. 覆盖 / 合并统计（已确认）

| 指标 | 值 |
|---|---|
| 文件 | `DRINIT.txt` + `$3$DRINIT.txt`（`$1$`/`$2$`/`$4$`/`$5$` 为空） |
| 单位 | 6 个（0x32 流燐结骑 / 0x33 溶燐结骑 / 0x34 岚燐结骑 / 0x35 华燐结骑 / 0x37 灵虚双舞之人傀 / 0x38 仿爱绽放之人傀） |
| 训练内容总数 | **440 行** |
| 单位×内容 | 0x32..0x35 各 80 条（TID 1..0x50）；0x37/0x38 各 60 条（TID 1..0x3c） |
| 字段列 | **118 个**（`字段K-TID=…`，十六进制升序） |
| 每单位 TID 连贯 | base 文件 1..0x36 → 追加 `$3$` 从 0x37 续 |

**合并口径**：按 `(unitId, TID)` 排序，把 base 与追加文件里的同一单位课程拼接成连贯序列；**「来源」列**单独标出该条来自 `DRINIT.txt` / `$3$DRINIT.txt`。base 与追加的 TID **不重叠**（base 到 0x36，追加从 0x37 起），故不产生重复行。

## 5. 导出

- 脚本：`scripts/export-drinit-training-records.js`（`--raw` 用 `data/` 原文；缺省用 `src/`，文案取 `日文|中文`）。
- 产物：`output/drinit-training-records.csv`。
- 列：`来源, 单位id, 单位名, TID, 文案(日), 文案(中), 训练名串地址, 单槽字段…, 耐性-<属性>…, 加成-<能力值>…, 属性(解码)`。
  - **单槽字段**（8 列）：表头直接展示 offset，已确认语义的 7 个再附语义名（`6c55f9 前置要求`、`6c565d 数量`、`6c56c1 类型 - 种族`、`6c5725 类型 - 性别`、`6c5789 类型 - 属性`、`6c57ed 等级`、`6c6085 效果 - 技能`）。
  - **多槽效果字段**（见 §2 修订）：效果-耐性按 7 列 `耐性-<属性>`（物理/地脈/冷却/火炎/電撃/神聖/暗黒，無属未用不出列）；效果-能力值按 13 列 `加成-<能力值>`（命中…ＦＳ）。**列以数组基址+槽对齐，不再看 K−TID**。
  - **文案全站汉化**：set-string 共 324 条（DRINIT.txt），无 `|` 的 22 条**未汉化**（多为 `★５　×１`、`★１以上　×３` 等少数纯数字文案），其余 `日文|中文` 皆有；CSV 的「文案(中)」对未汉化项留空，**与 `src/` 一致**（非脚本丢数据）。
  - 表内数值一律**十六进制原值**（保留 src 字面量，未转十进制），便于与 src / 物品 id 对照。
