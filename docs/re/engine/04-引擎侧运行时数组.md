# 引擎侧运行时数组 `0x53f48c` / `0x928a7`（engine）

> 级别：**已确认**（运行态 dump 实证 + `COMMITBTL` 实读）/ **仍未解**（`0x928a7` 的 Y 取值语义）。
> 它们与掉落门控的语义/使用见 `docs/re/src/03-掉落数据.md`（跨域桥接，主归属 src）。
> 运行态 dump 工具：`scripts/re/extract_global_data.ps1`。

---

## 1. 它们是「数组区段基址」，不是单个量（已确认自 COMMITBTL 脚本）

`COMMITBTL.txt` 第 253-258 行实读：
```
253: item = global_int[0x53CD7C + b*5 + slot]
255: X    = global_int[0x53F48C + b*5 + slot]   ; b、slot 为运行时值
256: Y    = global_int[0x928A7 + c]              ; c = global_int[0x52AC6C][b]
257: 1e   = (X <= Y) ;  258: 1f = (item>0) AND (X<=Y)  → 候选门
```
⇒ **`0x53f48c`、`0x928a7` 本身是"数组区段基址 index"，其值 X/Y 在偏移 `+b*5`/`+c` 处**。因此在空闲/战斗 dump 里把这三处当作"单值"读到的都是 0 —— 这是预期，不代表无数据。

---

## 2. 运行态 dump 实测（三次对比，已确认）

用 `scripts/re/extract_global_data.ps1` 分别导出：空闲 → 战斗存档 → 掉落瞬间（COMMITBTL 附近，物品已掉），差异如下：

- **`global_int_base`/`key` 三次完全一致**（对象稳定）：`int=0x41007700`、`key=0x221D01E6`（带壳进程 `AGE.EXE`）。
- **掉落表（`0x53CD7C..0x53F48C`）三次零变更** → item/rate 表是**启动时从 `EBINIT` 载入的静态数据**（`03-掉落数据.md` §3 的判断坐实）。
- **游戏状态标志**大量变动（空闲 vs 战斗 vs 掉落瞬间各差 ~1.2–1.4 万索引），与掉落无关。

### 关键：Y 数组在掉落瞬间被填充
- **Y 数组 `[0x928A7 .. ~0x9345F]`（= `0x928a7 + c`）在掉落瞬间出现 224 个非零 per-unit 值**（如 `0x92D2A:12`、`0x92D6B:38`、`0x92D89:17`、`0x92D8A:27`…）。空闲/战斗时该区全为 0，掉落时才写入 ⇒ **这是引擎运行时维护、脚本/数据/存档都无法静态定出的那部分**。
- **X 数组 `[0x53F48C + b*5]` 与 `0x546E04` 区仍是 0** → **`0x53f48c` 区段按 0 处理**（见 §3）。

---

## 3. **`0x53f48c` 区段：恒 0 / 通用逻辑 / 本项目未使用（本次澄清，已确认）**

- `0x53f48c = 0x53e104 + 5×1000`，即 rate 数组的 **id=1000 边界**，也是 **rate 之后下一段（0x53f48c..）的起点**。
- 该区段 `[0x53f48c, ...)` **在脚本/数据层无任何赋值逻辑**；三次运行态 dump 该区**恒 0**。
- ⇒ **怀疑是 AGE 引擎逐游戏复用的「通用掉落判定」区**（可能其它产品写过值），**本项目从未写入/使用**。`COMMITBTL` L255-257 的 `X <= Y`（`X = 0x53f48c[b*5]`）因此**恒真，是死判断**，真正的掉落判定是 `RNG < rate + 0xa3578`（见 `src/03-掉落数据.md` §3a）。
- `0x928a7`（Y）虽在掉落瞬间被填充，但鉴于 `X=0` 恒真，**Y 不左右掉落结果**；其填充更可能是战斗状态统计，与掉落门控无关。

---

## 4. 仍未解（继续）

- **`0x928a7`（Y）的确切取值语义**：看起来是"每单位运行度量"（战斗/单位属性/随机/计数？），但已确认其不参与本项目掉落判定（因 X 恒 0）。它究竟统计什么，仍需引擎侧 xref。
- **`0x53f48c` 的"通用逻辑"归属**：在引擎里找通用掉落判定对 `0x53f48c` 区的读/写，确认它是否为其它产品/通用路径遗留（本项目从未触发）。
- 两条出路：
  1. **引擎 xref**：在 `.lst`/IDA 对这两个**真实地址**（`global_int_base + 0x53f48c*4`、`+0x928a7*4`）做 xref，找读写它们的引擎函数。
  2. **掉落瞬间 hook**：在写 `0x53F48C+b*5` / `0x928A7+c` 的指令处下断，抓 `b/c/slot` + X/Y + item，验证 X 是否始终为 0。
