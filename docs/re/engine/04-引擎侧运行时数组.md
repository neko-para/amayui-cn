# 引擎侧运行时数组 `0x53f48c` / `0x928a7`（engine）

> 级别：**未解（引擎侧归属）**。这里只记录「为何归属引擎」与引擎侧待查点；
> 它们在掉落门控中的**语义/使用**见 `docs/re/src/03-掉落数据.md`（跨域桥接，主归属 src）。

---

## 1. 两者在数据/脚本层无静态写入（已确认）

- `0x53f48c` 与 `0x928a7` 在 `data/`、`src/`（游戏逻辑脚本）里**都无静态写入**，只有 `COMMITBTL` 脚本第 255/256 行**读取**：
  ```
  lookup-array-2d (local-ptr 3) (global-int 53f48c) (local-int b) 5 (local-int 0)  ; X = 53f48c[b*5+0]
  lookup-array    (local-ptr 4) (global-int 928a7) (local-int c)                   ; Y = 928a7[c]
  lte (local-int 1e) (local-ptr 3) (local-ptr 4)                                   ; X <= Y ?
  and ... (item>0) AND (X<=Y)   → 作为「掉落是否触发的门控」
  ```
- 结合 `docs/re/src/03-掉落数据.md` §3：`0x53f48c = 0x53e104 + 5*1000` 是 rate 数组的 **id=1000 边界**（自身无数据）；`0x928a7` 是另一个每单位运行时量。

## 2. 引擎侧判定（到引擎里找）

- 它们由**引擎在运行时维护**，用来判定「本次是否掉落」——脚本/数据/存档都定不出。⇒ 掉落「**是否触发**」的最终权威在**引擎**；`rate/100` 只做保底数量记账。
- **待查**：
  - 用 `global_int` 数组基址（见 `03-opcode分发与解释器.md` §5-4）算出 `0x53f48c`/`0x928a7` 的**真实地址**；
  - 在 `.lst`/IDA 里对这两个地址做 **xref**，找写它们的引擎函数；
  - 从写它的 opcode handler 反编译体，定它以何值填入（随机？单位属性？事件旗？）。
