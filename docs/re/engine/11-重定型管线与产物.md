# 重定型管线与产物（retarget pipeline）

> 级别：**已实现 / 可运行**（libclang + brew libclang dylib，纯文件驱动，无 IDA）。
> 一键入口：`scripts/re/retarget.py`；输入 `engine/天结_unpacked.exe_utf8.c` → 输出 `engine/engine.cpp`。
> 前置：`09-clang解析与重定型基座.md`（prep/prelude 让 clang 解析）、`10-成员函数识别.md`（成员检测）。
> 相关脚本：`retarget.py`、`detect_members.py`、`retype.py`、`semantic_names.json`。

---

## 1. 目标

从 Hex-Rays 反编译源 `engine/天结_unpacked.exe_utf8.c`，**一步**生成「字段已恢复 + 成员函数化 + 语义命名」的
C++ 视图 `engine/engine.cpp`，且**保留地址后缀**便于对回汇编。

## 2. 管线（`retarget.py` 各阶段）

```
engine/天结_unpacked.exe_utf8.c
  │
  ├─ (1) 成员检测  detect_members.detect_names(tu)     // 基准(高偏移 this 访问) + 调用图双向传播
  ├─ (2) 字段标记  `_this[K]`(常数命中 Engine 顶层字段) -> `this->field`
  ├─ (3) 签名替换  RET __thiscall sub_<addr>(_DWORD *_this, ...)
  │                -> RET Engine::<sem>_<addr>(_DWORD *_this, ...)      // 保留 _this 形参、去 __thiscall
  ├─ (4) 调用点改写  sub_M(recv, a1, ...) -> this->M(a1, ...) / recv->M(a1, ...)
  │                 // 接收者=首实参；recv 根为 _this 则 this->；否则显式 recv->
  └─ 全局兜底   `sub_<6hex>` -> <sem>_<addr>（已知语义）| 保持 sub_<addr>（未知）
               `member(_this, ...` -> `this->member(...`（安全正则，仅裸 member、首实参 _this；排除 ::member/原型）
  │
  ▼
engine/engine.cpp
```

- 单次 `clang.cindex` parse；编辑为「字节偏移 + 去重 + 遇重叠保留外层」；幂等、可重跑。
- 字段模型来自 `engine/engine.hpp` 的 `static_assert` 锁定偏移（`ENGINE_TOP`）。

## 4. 产物（当前）

- **`engine/engine.cpp`**（`retarget.py` 生成，~5.6 MB）：
  - 成员函数定义 `Engine::<name>_<addr>`（~1379 个，含语义化/未定名两类）；字段标记：`this->cur_script`(765)、`this->key`(106)、`this->frames[...]`(**581**)…
  - **帧字段化已生效**：`_this[30*this->cur_script + K]` → `this->frames[this->cur_script].field`（命中 `FRAME_FIELD` 的 11 个字段；未确认偏移如 0x34/0x40.. 保持 `_this[30*cur + K]` 原样）。
  - 成员调用改为 `this-><name>(...)`；已知函数 `sub_<addr>` 残留 0；未知成员保留 `Engine::sub_<addr>`。
  - 新命名的语义名：`op_lea_42CBA0`(lea/0x63)、`op_memcpy_42D150`(memcpy/0x1B0)、`op_random_42CA50`(random/0x60)、`operandAddress_42AEA0`、`writePointerOperand_418B90`。
- **`docs/re/engine/member_functions.detected.txt`**：`detect_members.py` 识别的 **1239** 个成员函数名（已更新，函数体恢复后从 959 提升）。
- 中间/支撑脚本：`hexrays_prep.py`（`this`→`_this`）、`sanitize_symbols.py`（mangled 符号清理）、`hxclang_prelude.h`（clang 预置）、`retype.py`（字段模型/解析）、`detect_members.py`（成员检测，含可复用的 `detect_names(tu)`）。

## 5. 现状边界（未做）

- `_this` 形参**仍保留**（`Engine::sub_XXX(_DWORD *_this, ...)`）；尚未移除（下一步）。
- 帧内字段（`_this[30*cur+C]` → `this->frames[this->cur_script].field`）**已实现**（`retarget.py` 末尾按 `retype.FRAME_FIELD` 正则改写；命中 11 个已确认帧字段，未确认偏移如 0x34/0x40.. 保持原样）。
- 无 `class Engine { … }` 声明头 → `engine.cpp` 尚不能独立编译（需补成员函数原型 + 字段声明）。
- 语义表目前约 30 条（已知访问器/核心/算术簇/脚本上下文），覆盖面可继续扩。

## 6. 用法

```bash
VENV=pyenv/bin/python
# Windows 需指定 libclang：set LIB_CLANG=C:\Program Files\LLVM\bin\libclang.dll （retarget.py 里 ci.Config.set_library_file 优先读 LIB_CLANG）
# 一键生成 engine/engine.cpp
$VENV scripts/re/retarget.py engine/天结_unpacked.exe_utf8.c -o engine/engine.cpp
# 单独重扫成员
$VENV scripts/re/detect_members.py engine/天结_unpacked.exe_utf8.c --out docs/re/engine/member_functions.detected.txt
```
