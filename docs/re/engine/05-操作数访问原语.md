# 操作数访问原语 `sub_41BF50`（引擎）

> 级别：**已确认**（`engine/天结_unpacked.exe_utf8.c` 反编译实证 + `engine/defs.h` 的 `__ROL4__`/`__ROR4__` 语义）。
> 分析对象：`engine/天结_unpacked.exe_utf8.c` 第 26555 行的 `sub_41BF50`；孪生浮点版 `sub_41C300`（第 26654 行）。
> 前置：见 [`03-opcode分发与解释器.md`](./03-opcode分发与解释器.md) §1 —— 每个 opcode handler 的骨架都是「`sub_41BF50(this,N)` 读第 N 个操作数 → 运算 → `sub_42B4B0(this,1,val)` 写回」。

---

## 1. 总结：这是「从 typed 操作数里读一个整数」的分发器

`sub_41BF50(this, N)` 把**第 N 个操作数**（一个 8 字节 typed arg = `type u32` + `raw_data u32`）按 **type** 分支，取回一个**整数**。它不是「variant 的某一种值」，而是**对所有可能操作数类型的一级分派**——正好对应 `age-shared.h` 里 `Argument.type` 的取值域（`0..0xD`、`0x8003`、`0x8009` 等）。

- 返回 `int`；每个 opcode handler 用它取左/右/索引操作数。
- **孪生版 `sub_41C300`**（25545 行错位，实为 26654）同构但返回 `double`，用 `atof`、直接返回 `float`；两者共用同一套数组基址与混淆 key。
- 于是引擎用**两个平行 accessor**：`sub_41BF50`=读 int，`sub_41C300`=读 float。

---

## 2. 入口：定位第 N 个操作数 + 取 type

```c
v2 = 8 * N + this[30 * this[95776] + 95782];   // dword 下标 → argN.raw 的地址
dword_55D0F0 = v2;                              // 全局副作用：记录当前 arg 地址（供调试/异常用）
v3 = *(_DWORD *)(v2 - 4);                       // ← 类型标签 argN.type
```

**数组/上下文下标换算**（`this` 为 `int*`，字节偏移 = `4×下标`）：

| this 下标 | 字节偏移 | 含义 |
|---|---|---|
| `this[95776]` | 383104 | `cur_script`（当前脚本上下文下标） |
| `this[30*cur + 95782]` | 120×cur + 383128 | **当前指令指针 IP**（指向 opcode） |
| `this[97059]` | 388236 | **解混淆 key**（异或+循环移位） |

**指令布局**（每 arg 8 字节）：`[opcode u32][arg1: type u32][arg1: raw u32][arg2: type][arg2: raw]…`。
故 `argN` 的 `raw` 在 `IP + 8*N`，`type` 在 `IP + 8*N - 4`。`v2` 即 `IP + 8*N`，`v3` 即 `argN.type`。

> ⚠️ 注意：03 文档 §4 主循环里「IP 在 `120*cur_script + 383128`」与此处完全一致，只是 `sub_41BF50` 把它**当作操作数基址**用（加 `8*N` 得到第 N 个 arg）。

## 3. 分支骨架

```c
if (v3 > 32771)                      // type > 0x8003
{
    if (v3 != 32777) goto LABEL_25;  // 非 0x8009 → 抛 Command::Type_Exception
    /* === type == 0x8009：局部整型数组批量（读首元素）=== */
}
else
{
    if (v3 != 32771)                 // 非 0x8003
    {
        switch (v3)                  // 0..13 常规类型
        { ... }
    }
    /* === type == 0x8003：全局整型数组批量（读首元素）=== */
}
return 0;
```

## 4. 常规类型 switch（type = 0..13）

| type | 语义 | 取值表达式 | 说明 |
|---|---|---|---|
| 0 | 立即 int | `*(int*)v2` | raw 即值 |
| 1 | 立即 float | `(int)*(float*)v2` | float 位模式转 int |
| 2 | 字符串→int | `atoi(this[30*cur+95781] + 4*raw)` | 当前脚本字符串表 |
| 3 | global-int | `DEC( *(this[95744] + 4*raw) )` | |
| 4 | global-float | `(int)*(float*)(this[95746] + 4*raw)` | |
| 5 | global-string | `atoi( str@this[95748] + 28*raw )` | 7-dword SSO 结构 |
| 6 | global-ptr | `DEC( **(DWORD**)(this[95750] + 4*raw) )` | 双重解引用 |
| 7 | global-float-ptr | `(int)**(float**)(this[95752] + 4*raw)` | |
| 9 | local-int | `DEC( *(this[30*cur+95789] + 4*raw) )` | |
| 10 | local-float | `(int)*(float*)(this[30*cur+95790] + 4*raw)` | |
| 11 | local-string | `atoi( str@this[30*cur+95791] + 28*raw )` | |
| 12 | local-ptr | `DEC( **(DWORD**)(this[30*cur+95792] + 4*raw) )` | |
| 13 | local-float-ptr | `(int)**(float**)(this[30*cur+95793] + 4*raw)` | |
| 其他 | — | 落到 `LABEL_25` | 抛 `Command::Type_Exception` |

**`DEC(x)` = 解混淆读整数**（见 §5）。
**字符串类型（case 2/5/11）**：`raw` 是字符串表索引；string 是 7-dword（28 字节）结构体，`*(str + 20) < 0x10` 判「内联小字符串（≤15 字符）」还是「指针指向堆」，再 `atoi`。

**每脚本局部基址**：`95781`(字符串表)、`95789`(local-int)、`95790`(local-float)、`95791`(local-string)、`95792`(local-ptr)、`95793`(local-float-ptr)，均按 `30*cur_script + 下标`（= `120*cur` 页）访问。
**全局基址**：`95744`(global-int)、`95746`(global-float)、`95748`(global-string)、`95750`(global-ptr)、`95752`(global-float-ptr)。

## 5. 整型解混淆 `DEC`（异或 + 循环移位）

```c
#define DEC(x)  __ROR4__( this[97059] ^ __ROL4__((x), 11), 25 )
```

- `this[97059]` = 全局解混淆 key（字节 388236）。
- 依 `engine/defs.h`：`__ROL4__(v,n) = ROL(v,n)`；`__ROR4__(v,n) = ROL(v,-n)`。因 `ROR4(v,25) = ROL4(v,7)`，故 `DEC(x) = ROL4( key ^ ROL4(x,11), 7 )`。
- **结论**：**所有全局/局部整型（case 3/9）与整型数组元素（0x8003/0x8009）最终都归一到这条 `key ^ ROL ^ ROR` 线上**。这是「从 variant 提取整数」的核心去混淆路径。
- 反混淆逆向（供后续写回 `sub_42B4B0` 对照）：若 `r = DEC(x)`，则 `x = ROL4( ROL4(r, -7) ^ key, -11 )`（即逆序把三次运算都反掉）。

## 6. 两个特殊类型：整型数组批量（读首元素）

两分支结构相同，仅「从哪个槽取数组描述符」不同：

- **`32777` (0x8009) = 局部整型数组**：
  ```c
  v13 = DEC( *(DWORD*)(this[30*cur+95789] + 4*raw) );   // 从局部-int 槽读出「数组描述符引用」
  if (v13) {
      v12 = (DWORD*)*v13;                                // begin
      if ( (v13[1] - *v13) >> 2 )                        // (end - begin)/4 = 元素数 > 0
          return DEC(*v12);                              // 返回首元素
  }
  ```
  即把局部 int 槽里存的引用当作 `{begin,end}` 描述符（`*v13`=begin，`v13[1]`=end），数组非空则返回**首个解码后元素**。

- **`32771` (0x8003) = 全局整型数组**：结构同上，只是改用全局槽 `this[95744]`。

- 两者共性：**只取首个元素**；引用为空或数组为空（`(end-begin)>>2 == 0`）时落到 `return 0`。

> 这就是 `age-shared.h` 注释里 `0x8003`/`0x8009` 那种「数组批量」参数类型的落地方式。

## 7. `LABEL_25`：类型不匹配抛异常

```c
LABEL_25:
    pExceptionObject = *(int*)( this[30*cur+95782] + 8*N - 4 );   // 即 argN.type 本身
    _CxxThrowException(&pExceptionObject, &_TI1_AVCommand_Type_Exception__);
```
把非法的 type 值作为参数抛 `Command::Type_Exception`。

## 8. 孪生浮点版 `sub_41C300`（26654 行）

与 `sub_41BF50` **同构**，返回 `double`，差异仅：
- case 1/4/7/10/13 直接返回 `*(float*)…`（不做位模式转换）；
- case 2 用 `atof`（case 5/11 亦 `atof`）；
- 全局副作用写到 `dword_55D0F4`（而非 `55D0F0`）。
- 数组分支读整型后 `(double)(int)…`。

结论：opcode handler 按需调用「`sub_41BF50`（int accessor）」或「`sub_41C300`（float accessor）」之一，二者共用所有基址/key。

## 9. 写回原语 `sub_42B4B0` / `sub_42BA00`（读的镜像，`int`/`float`）

`engine/天结_unpacked.exe_utf8.c`：
- `sub_42B4B0(int this, int N, int a3)`（36965 行）—— **把整数值 `a3` 写入第 N 个操作数的目标**。
- `sub_42BA00(_DWORD *this, int N, float a3)`（37132 行）—— 同构的**浮点写**。

调用形态即用户所见：`return sub_42B4B0((int)this, 1, v2);` → 把 `v2` 写进**参数 1** 指向的目标（参数 1 = 目的，参数 2/3 = 左/右操作数，与算术簇 §03 一致）。

### 9.1 入口（与读对称）

```c
v4 = (int *)(8 * N + *(_DWORD *)(this + 120 * *(_DWORD *)(this + 383104) + 383128));  // = IP + 8*N
dword_55D534 = (int)v4;          // 全局副作用：记录 arg raw 地址
v5 = *(v4 - 1);                  // type
```
与 `sub_41BF50` 完全一致：`v4` = argN.raw 地址，`v5` = argN.type。

### 9.2 分支骨架（写侧，**比读侧少**两个字符串类型）

```c
if (v5 > 32771) { if (v5 != 32777) goto LABEL_22;  /* 0x8009 局部整型数组写 */ }
else {
    if (v5 != 32771) {
        switch (v5) { case 3: /*global-int*/ case 4: case 6: case 7: case 9: case 10: case 12: default: goto LABEL_22; }
    }
    /* 0x8003 全局整型数组写 */
}
return result;
```

> ⚠️ **写侧 switch 只覆盖 3/4/6/7/9/10/12**（+ 两个数组类型），**不含读侧的 0/1/2/5/11/13**：
> - **0/1**（立即 int/float）：立即数是常量，不可写 → 落 `LABEL_22` 抛 `Command::Type_Exception`。
> - **2/5/11**（local/global 字符串）：整数写进字符串无意义（应是字符串写原语，不在本文档域）→ 抛异常。
> - **13**（local-float-ptr）：整数写进 float-ptr 无意义 → 抛异常；**float 写原语 `sub_42BA00` 才提供 case 13**（见 §9.4）。

### 9.3 各 case 写入（与读侧 `DEC` 镜像）

`ENC(a) = __ROL4__( key ^ __ROR4__(a, 7), 21 )`，**与读侧 `DEC(x)=__ROR4__(key ^ __ROL4__(x,11), 25)` 恰为逆运算**（验证：`ENC(DEC(x)) = ROL4(ROL4(x,11),21) = x`）。`key = *(this + 388236)`。

| type | 语义 | 写入表达式 |
|---|---|---|
| 3 | global-int | `gint_base[raw] = ENC(a3)`（base=this+382976=95744） |
| 4 | global-float | `*(float*)(gfloat_base[raw]) = (float)a3`（不编码；base=this+382984=95746） |
| 6 | global-ptr | `P = gptr_base[raw]`（base=this+383000=95750）；`*P = ENC(a3)` |
| 7 | global-float-ptr | `P = gfptr_base[raw]`（base=this+383008=95752）；`*P = (float)a3` |
| 9 | local-int | `lint_base[raw] = ENC(a3)`（base=this+120*cur+383156 = 30*cur+95789） |
| 10 | local-float | `*(float*)(lfloat_base[raw]) = (float)a3`（base=120*cur+383160 = 30*cur+95790） |
| 12 | local-ptr | `P = lptr_base[raw]`（base=this+120*cur+383168 = 30*cur+95792）；`*P = ENC(a3)` |

**对称性确认**：读侧 case 6/7/12 是 `**(base+4*raw)`（= `*P`），写侧是 `*(base+4*raw)` 取出 `P` 后 `*P = …`（读/写都作用于 `*P`，`P = base[raw]`）——完全镜像。string/float 写走**不经 ENC**、直接 `(float)a3`。

> 注意 float 写（`sub_42BA00`）对 3/9/6/12 也**用同一 `ENC` 公式**（`COERCE_FLOAT(__ROL4__(key ^ __ROR4__(LODWORD(a3),7),21))`），说明 `ENC` 对 **int 槽的位模式**无差别编码——与读侧 `DEC` 对称。

### 9.4 两个数组类型的写（0x8003 全局 / 0x8009 局部）

读侧返回数组**元素[0]**，写侧则「**确保元素[0] 被写入**」：

```c
v11 = *(localint_base + 4*raw);                  // 从局部-int 槽读出数组描述符「引用」
v9  = (int*)DEC(v11);                            // 解码为数组描述符 {begin,end,cap(0x10=4 dword)}
if (!v9) {                                       // 引用为空 → 新建 0x10 字节结构并回写
    v9 = operator new(0x10u);                    // {begin=0,end=0,cap=0}
    *(localint_base + 4*raw) = ENC(v9);          // 把新描述符的「编码值」存回槽，跨指令持久
    sub_45D240(per_script_container + 383236, &raw_index);   // 登记到每脚本容器
}
if (((v9[1] - *v9) & 0xFFFFFFFC) == 0)           // end-begin 的「÷4 元素数=0」→ 空数组
    goto LABEL_17;                               // sub_40C780(v9, &ENC(a3)) == push_back
else {                                           // 非空 → 直接写元素[0]
    result = *v9;                                // begin
    if (!((v9[1]-*v9)>>2)) std::_Xout_of_range();// 防御：真为空 → 越界
    *(_DWORD*)result = ENC(a3);                  // begin[0] = 编码值
}
```

- **`LABEL_17`**：`a3 = ENC(a3); return sub_40C780(v9, &a3);` —— `sub_40C780` ≈ `std::vector::push_back`（空数组时追加，使其成为 1 元素数组）。
- 两条路径殊途同归：**空 → push_back(使元素[0]=值)；非空 → begin[0]=值**。
- 0x8009 用**每脚本**容器（`this + 120*cur + 383236`）；0x8003 用**全局**容器（`this + 383072`）。
- `0x8003` 与 `0x8009` 差异仅「读描述符的槽」：0x8003 全局（`base=this+382976`）、0x8009 局部（`base=120*cur+383156`）。

### 9.5 孪生浮点写 `sub_42BA00`

与 `sub_42B4B0` 同构、返回 `int`、`a3` 为 `float`。switch 覆盖 **3/4/6/7/9/10/12/13**，**比 int 写多出 case 13（local-float-ptr）**；浮点型（4/7/10/13）直接写，int 型（3/6/9/12）也走 `ENC` 后按 float 位模式写。全局副作用写 `dword_55D540/538/53C`。

### 9.6 结论：读/写原语四处占位

- 引擎用 **4 个操作数访问原语**：读 int `sub_41BF50`、读 float `sub_41C300`、写 int `sub_42B4B0`、写 float `sub_42BA00`。
- 读侧 `DEC`、写侧 `ENC` 互为逆运算（`key` 相同）：凡 int 槽（global/local int、ptr、数组元素）读写都过这条混淆；float 槽直接存/取。
- opcode handler = `vL = read(this,2); vR = read(this,3); write(this,1, op(vL,vR))`（见 03 文档算术簇）。
