# 单位掉落物解析（天結いキャッスルマイスター）

> 结论基于：对 `data/EBINIT.txt` 全量逆向，并用 `metadata/items.json`（§物品建筑配方.md 产物）反查掉落物品名。
> 产出脚本：`scripts/extract-unit-drops.js`；产物在 `metadata/unit-drops.json`。

## 1. 单位块分界（先切单位，再找掉落）

`EBINIT.txt` 由 **243 个怪物/敌人单位块** 组成，每块以一个**相邻 set-string 对**开头：

```text
set-string (global-string 17b..17e) "单位名"      ← 名字（地址 0x17a00..0x17eff）
set-string (global-string 17f..181) "阵营/种族/说明" ← 副标题（地址 0x17f00..0x181ff）
mov ...                                              ← 之后是属性/掉落/技能指针
```

条件：**名字串地址 < 副标题串地址**，且二者是连续两条 `set-string`。

- **名字串**：`0x17a00 .. 0x17eff`（`17b/17c/17d/17e`…）
- **副标题串**：`0x17f00 .. 0x181ff`（`17f/180/181`…）

> ⚠️ 可玩角色名册（`src` 同 `data` 里 `L9~L2164`，即 アヴァロ/フィア/イオル…，名字串 `17a` + 副标题 `17e`）是**玩家单位**，没有掉落表，不参与本解析。判别时只按「名字 17a-17e + 副标题 17f-181」这一对取敌人单位，自然排除角色名册。

## 2. 掉落表的结构（关键规律）

每个单位块末尾附近有一段**掉落表**：若干条**交错**的 `mov`，两两配对为 `(rate, item)`：

```text
mov (global-int 53eXXX) <rate>   ← 掉落率/权重（rate 地址）
mov (global-int 53dXXX) <itemId> ← 掉落物品 id（item 地址）
```

判据（脚本里 `extractDrops`）：

| 判据 | 规则 |
|---|---|
| **item 地址** | 页基 `0x53d000` 固定，**页内偏移随单位漂移**（如 `0x53d038`…`0x53d858`…`0x53dc26`）→ `(addr & 0xffff000) === 0x53d000` |
| **rate 地址** | 页基 `0x53e000` 固定，同样页内漂移（`0x53e3c0`…`0x53ebe0`…`0x53ede8`）→ `(addr & 0xffff000) === 0x53e000` |
| **配对** | 每条 **rate 紧跟其 item**（rate 在前、item 在后），且相邻两对的 rate 地址、item 地址各 **+1**（双游程） |
| **边界** | 游程后紧跟一条 `51xx/52xx` 数据指针行 |

- 掉落条目数**可变**：多为 3~5 条，也有 1 条（BOSS 专属掉落）与 2 条（普通杂兵）。
- `itemId` 与 §物品建筑配方.md 的物品 id 同源：用它反查 `items.json` 即得掉落名。

### ❌ 常见误判
- **`4xxx` 尾不是必要判据**：多数尾是 `45xx/4xxx`，但也有 `396x/397x/393e/394x`、`16xx/1761`（BOSS 单体掉落），所以不能只认 `4xxx`。
- **item 前缀不是 `53d1xx`**：页内偏移随单位漂移，只应锁定页基 `0x53d000`。例如 `這竜リムドラギル` 的 item 在 `53d858~53d85b`，并非 `53d1xx`。

## 4. 产出（`metadata/`，`node scripts/extract-unit-drops.js` 生成）

`unit-drops.json`：

```jsonc
{
  "count": 203,                     // 含掉落表的单位数
  "units": [
    {
      "unitId": 97132,              // 名字串地址（十进制；0x17b6c = 狂える男）
      "name": "狂える男",
      "title": "中毒症状で暴れる者",   // 副标题 / 阵营种族
      "nameLine": 5047,             // 名字串在 EBINIT.txt 中的行号
      "drops": [
        { "itemId": 333, "itemRaw": "14d", "rate": 5,  "rateRaw": "5",  "name": "金のメダル" },
        { "itemId": 207, "itemRaw": "cf",  "rate": 10, "rateRaw": "a",  "name": "勇壮の水・小" },
        , ...
      ]
    }, ...
  ]
}
```

- `itemId` / `itemRaw`：掉落物品 id（hex 原值）。`name` 由 `metadata/items.json` 反查，取不到为 `null`（本次 203 单位全部有名字）。
- `rate` / `rateRaw`：掉落率（`53eXXX` 值，hex 原值）。语义待定（见 §5）。

## 5. 统计与边界

- 单位块数 = **243**（敌人/怪物），含掉落表 = **203**，不含 = **40**（多为无掉落的剧情/纯敌人）。
- 全文件 `53dXXX` item mov 行 = **648 条**，输出捕捉 **648 条**，**0 缺失、0 重复**。
- 掉落条目数分布：1条:67 单位 / 2条:4 / 3条:15 / 4条:57 / 5条:60。
- 去重后掉落物品 ≈ **252 种**。
- 单体（1 条掉落）多为 BOSS/独特单位，率恒为 `100`（其专属/必掉物品）。

### 待办 / 未定
- **`rate` 语义未定**：当前 `53eXXX` 值域多为 `5..64`（即 100），看起来像**掉落率/权重**。需对 `AGE.EXE` 读该数组的函数做交叉验证，或对照游戏内实际掉落才能定论（同 §物品建筑配方.md 的 metadata 处理思路）。
- **`title`（副标题）** vs 单位名：部分副标题重复（如同一阵营「インフルース王国軍」），仅作展示用，不影响掉落归属。
- 后续可扩充：把 203 个带掉落单位整理成「单位名 → 掉落清单」表，并标注 BOSS 专属掉落；或合并到 `keywords-单位名称.md` 联动。

## 6. 脚本说明

- 入口：`node scripts/extract-unit-drops.js`（写 `metadata/unit-drops.json`）。
- 分块：`unitHeaders`（相邻 `name`+`sub` set-string 对）。
- 掉落：`extractDrops`（扫描 `rate@53e + item@53d` 双 +1 游程）。
- 依赖：`scripts/config.js`（`ROOT_DIR`、`data/`）、`data/EBINIT.txt`、`metadata/items.json`。
