# 物品 / 建筑 / 配方数据解析（天結いキャッスルマイスター）

> 结论基于：对 `raw`/`data` 全量反汇编文本的逆向，并用 Fandom 配方 wiki（`res/recipes/Fandom.mht`）交叉验证。
> 产出脚本：`scripts/extract-recipes.js`；产物在 `metadata/`。

## 1. 关键编码（本次解析的核心两把钥匙）

### 1.1 物品 id = 名字串地址 − `0x18e40`
每个物品在 `ITINIT.txt`（base + `$n$ITINIT`）里有一条 `set-string (global-string <addr>) "名称"`。
- **物品 id = `名称串地址 − 0x18e40`**。
- 例：青銅の導鍵 @`18e41` → id **1**；水色の木の実 @`18f09` → id **0xc9=201**；パール鋼 @`19049` → id **0x209=521**。
- 说明：disasm 里的值全为 **hex**（`209` = `0x209` = 521，不是十进制 209）；配方里的产品/材料值就是这个“串地址派生 id”。

### 1.2 建筑/设施 id = 名称串地址 − `0x1f5ba`（来源 PLINIT）
建筑/设施名在 `PLINIT.txt`（base + `$n$PLINIT`）里，同样用 `set-string (global-string <addr>) "名称"`。
- **建筑 id = `名称串地址 − 0x1f5ba`**。
- 例：アヴァロの工房 @`1f5bb` → id **1**；訓練場 @`1f5db` → id **33**。
- 吸收时排除以 `【` 开头的说明串（`【施設：…】` 是描述，不是名字）。

## 2. ALINIT = 配方表（物品 + 建筑，同一张表按“标记值”分行）

`ALINIT.txt`（base + `$n$ALINIT`）用 `mov (global-int <addr>) <value>` 写配方。每行结构：

```
行标记(值=1|2)   →  产品(id)  →  若干元数据(6b*)  →  {材料id, 数量}*
```

| 标记值 | 含义 | 产品 id 用哪张名表 |
|---|---|---|
| `1` | 物品合成配方 | 物品名表（`0x18e40`） |
| `2` | 建筑/设施配方 | 建筑名表（`0x1f5ba`，PLINIT） |

判据（脚本里 `isMarkerAt`）：
- 标记 = 值 `1` 或 `2`、地址前缀 `6ba7`/`6ba9`/`6baa`、且下一 mov 是产品数组（`6bab`/`6bad`/`6bae`）。
- 材料 = 行内所有 `6c*` mov，按出现顺序两两配对 `{材料id, 数量}`（顺序保留）。
- 元数据 = 产品之后、首个 `6c*` 之前的那批 `6b*` 字段。

## 5. 已知边界 / 待办

- **物品与建筑 id 空间有重叠**：如 id 51 在物品表=城砦拡張図面Ⅰ、在建筑表=小さな家（黄）。`recipe-buildings.json` 的 `product` 统一用建筑名表（PLINIT）。若需区分，可另加 `productItem` / `productBuilding` 两字段。
- **每行元数据（`metadata`）语义未定**：取值特征如下，部分可初步判断但需对 `AGE.EXE` 读这些数组的函数做交叉验证：
  - `6bafxx`：≈10000–11000，非物品名槽，像“代价/等级”或技能 id。
  - `6bb3xx`/`6bb6xx`：多为 1（布尔）。
  - `6bbaxx`：恒为 `32`(50)，像上限/等级乘数。
  - `6be5xx`：bb9=素手/bba=竜鰐刀/…，解析为**装备物品 id**，像“关联/可进化”物品。
  - `6bf9xx`：235c/235d/235e… 按行递增，像**技能/能力 id**。
- **id≤58 覆盖**：`recipe-items.json` 已覆盖全部可合成物品；`4,26,28,29,30,34,45-50` 经核实为不可制作（4=已知空缺槽；28/29/30=材料；26/34/45–50 在 ALINIT 无产品行）。
- **建筑配方产品名**：全部 71 条在 PLINIT 中都能解析到名字（无空）；若某建筑在 PLINIT 无对应条目则留 `null`。

## 6. 脚本说明

- 入口：`node scripts/extract-recipes.js`（写 `metadata/items.json` / `buildings.json` / `recipe-items.json` / `recipe-buildings.json`）。
- 判定逻辑见 `scripts/extract-recipes.js` 各 `collect*` / `parseAlinit` 函数；`BASE=0x18e40`（物品）、建筑基 `0x1f5ba`。
- 依赖：`config.js`（`ROOT_DIR`、`data/`）。
