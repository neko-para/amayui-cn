### 8.2 ADV 拉丁字形宽度：macOS 异常 = 系统字体 fallback（Windows 实测正常，2026-08-21 验证）

**现象（macOS 历史记录）**：28px（bold）下渲染「ADV设定」，ADV（3 个拉丁字符）实测宽度 **57.63px（bold）/ 56.06px（regular）**，而「设定」（2 汉字）56.00px——**ADV 与两汉字等宽甚至更宽**。与既有经验（20px 时 ADV=37px < 设定=40px，窄 3px，曾专门插入 3px 间隔补齐）**相反**。

**测量数据（macOS + headless Chrome）**：

| 项目 | 宽度 |
|---|---|
| PIL 读 WenQuanYi.ttf 度量（28px）「ADV」 | 52.00px |
| PIL 读 WenQuanYi.ttf 度量（28px）「设定」 | 56.00px |
| 浏览器渲染（28px, regular）「ADV」 | 56.06px |
| 浏览器渲染（28px, regular）「设定」 | 56.00px |
| 浏览器渲染（28px, bold）「ADV」 | 57.63px |
| 浏览器渲染（28px, bold）「设定」 | 56.00px |
| 浏览器渲染 SVG `<text>`「ADV设定」（28px bold） | 113.63px |

**分析**：PIL 字体度量 ADV 应窄 4px，但浏览器渲染中 ADV≈汉字宽；bold 仅撑宽拉丁字符（+1.57px）汉字不变；20px 与 28px 的 ADV/字符比例非线性（0.618em vs 0.667em）。**怀疑浏览器对 WenQuanYi 的拉丁字形渲染发生 fallback（回退到系统西文字体），与操作系统字体环境相关**。

**Windows 实测（2026-08-21，本仓库 Windows 环境，headless Chrome）**：**异常不复现**——ADV 正常窄于汉字，macOS 现象确认为 WenQuanYi 拉丁字形 fallback 到系统西文字体所致，与字体文件本身无关。

### 9.3 教训：headless Chrome 对系统字体的拉丁 fallback

- 现象：无 @font-face 时 headless 渲染「Sarasa Gothic SC」的**拉丁/罗马数字**会 fallback
  （汉字正常），SVG `<text>` 与 HTML 均受影响；宽度/字形与用户浏览器不一致；
- 判定：对比字形（headless 渲染 vs PIL 读字体文件）差异 >50% 即为 fallback；宽度巧合接近
  （20px ADV fallback 41.38 vs 真实 42.00）可能掩盖问题；
- 修复：渲染页**必须加 @font-face 引用本地 TTF**（路径相对渲染页 `../../../res/fonts/...`），
  headless 与浏览器一致（`document.fonts.check` = true）。
