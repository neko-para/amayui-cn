# 地图内单位构成解析（天結いキャッスルマイスター）

> 结论基于：对 `src/STINIT.txt`（$n$ 追加包同）逆向，并用 `src/STINIT2.txt`（关卡名）、`src/EBINIT.txt`（单位名）交叉验证。
> 产出脚本：`scripts/annotate-stinit-maps.js`（关卡名）、`scripts/annotate-stinit-units.js`（单位名）；均在 `src/*STINIT.txt` 行尾追加 `//` 注释。

## 1. 两块关键编码（本次解析的两把钥匙）

### 1.1 关卡 id / 关卡名（STINIT → STINIT2）
每个关卡（地图）在 `STINIT.txt` 以如下块开头：

```text
eq (local-int 0) (global-int b222) <mapNo>
jcc (local-int 0) ffffffff label_...
jmp label_...
```

`eq` 的**第三个参数 `mapNo` 就是地图编号**。
- **关卡名 = STINIT2 中 `set-string (global-string <addr>) ` 的字符串，其中 `addr = 0x121e2 + mapNo`。**
- 例：`mapNo=1` → `0x121e3` = `遺跡地下の調査区域`；`mapNo=b` → `0x121ed` = `堆積した砦路樹`；`mapNo=51` → `0x12233` = `廃妖の谷底`。
- ⚠️ 注意基址是 **`0x121e2`**（非 `0x121e3`）：名表以 `mapNo=1 → 0x121e3`（第 1 关 `遺跡地下の調査区域`）为起点，全表 655/655 命中。
- 名表来源为**全部 `src/*STINIT2.txt`**（base + `$n$`，地址空间一致，按 `set-string` 合并）。名值形如 `日文|中文`。
- 关卡名地址表稀疏（`STINIT2` 中按 `0x121e2+mapNo` 稀疏分布），但基址正确时**所有**关卡均能命中。

### 1.2 单位 id / 单位名（STINIT → EBINIT）
每个关卡块内是若干个“单位槽”，每个槽以如下锚点结束：

```text
mov (global-int 14dc<低字节>) <v>  ×N     ← 计数器列（前部，数量随遭遇而异）
mov (global-int 14dd<0x40+i>) <unitId>    ← 单位 id（寄存器随 i 递增）【注释行】
mov (global-int 14dd<0x40+i+0x1E>) <level>← 单位等级
mov (global-int 14dd<0x40+i+0x3C>) <v>     ← 未知（观测量）
mov (global-int 14dd<0x40+i+0x5A>) 1       ← 未知（多为 1）
copy-local-array (global-int 14dXXX) [...] ← 锚点
```

- **单位名 = EBINIT 中 `set-string (global-string <addr>)`，其中 `addr = 0x17ab6 + unitId`。**
- 例：`unitId=fa` → `0x17bb0` = `迷い入った小鬼`；`unitId=38f` → 歪侍女；`unitId=2d1` → 掘削の彫像。
- 名表来源为**全部 `src/*EBINIT.txt`**（`set-string` 按地址合并，`日文|中文`）。

## 2. 单位槽的定位（采用的简洁方法）

- **每个关卡的单位都是从 `mov (global-int 14dd41)` 开始放置**；单位 id 寄存器落在**闭区间 `0x41..0x5d`**（部分遭遇可能跳号、不连续）。
- **判定**：**所有 `mov (global-int 14ddXX)`（`XX ∈ [0x41,0x5d]`）且 `0x17ab6+unitId` 能反查到单位名，即为单位**，逐一标注。实测全工程 **1791** 个。
- 上界 `0x5d` **恰好排除伴随/率/等级字段**（单位 0x41 的 `+0x1E` 伴随在 0x5f，落入 `0x5e..0x7b`；其小值也可能命中名字，是误标源）。故区间外（`<0x41` 计数器、`>0x5d` 伴随）一律不标。
- ⚠️ **弃用“后 3 行 +0x1E/+0x3C/+0x5A”结构判据**：间距过宽，会把计数器也错标为单位（如 `14dd27=1` 恰命中 `アヴァロ` 名地址被误标为 `アヴァロ`）。该判据只会产生误标，已放弃。
- （可作交叉校验但非判定）`copy-local-array (global-int 14dXXX)` 的“向前第 4 行”锚点：只覆盖部分槽，不完整。

## 3. 单位槽字段（部分已知 / 待定）

### 3.1 单位 id 行**前部**计数器列的偏移规律（本次记录）

对全量 **1791 条**已标注单位 id 行做“前 4 行偏移”统计：偏移**大体有序、数量有限、具固定间距 `+0x1E`**。

- **`14dc` 计数器列（主导）**：相对 id 行低字节的偏移构成**步长 0x1E 的等差序列**——
  `+5a / +78 / +96 / +b4 / +d2 / +f0`（等价于 `id低字节 + {0x10, 0x2e, 0x4c, 0x6a, 0x88, 0xa6}`）。出现次数 408–1727，是前 4 行的主体。
- **`14dd` 伴随字段**：`+1e / +3c / +5a / +78`（等差 0x1E），后续 `+a7 / +c5 / +e3`（近 0x1E）。即“后 3 行伴随”在块尾被前 4 行窗口截入。
- **杂散偏移（非规律）**：`d8/d9/da/de/df/d7` 页各仅 1–6 次，偏移零散、间隔不规则——多为**跨遭遇/块边界**处窗口偶尔扫到的非单位体 mov，不属于单位槽固定结构。

> 结论：**单位槽前的“计数器列”也是一个规则等差（步长 +0x1E）**，只是列数随遭遇而异（前 4 行窗口抓到的是最靠近的那几列）。它可进一步作为“单位 id 行结构”的更强约束。

### 3.2 槽内字段表

| 槽内偏移（相对单位 id 寄存器） | 含义 | 状态 |
|---|---|---|
| `+0x00`（本槽寄存器） | 单位 id | 已确认（反查 EBINIT 名） |
| `+0x1E`（本槽后） | **单位等级** | ✅ 已确认（用多个有明显特征的关卡校验；例 `14dd60=2d` 即该关 `迷い入った小鬼` 等级 45） |
| `+0x3C`（本槽后） | 未知（观测量，出现多值） | 待定 |
| `+0x5A`（本槽后） | 未知（多恒为 1） | 待定 |
| 前部 `14dc` 计数器列 | 未知（相对 id 低字节等差 +0x1E） | 结构已确认、语义待定 |

> 注意：`+0x1E` 等是相对槽首（单位 id 寄存器）的十六进制偏移；实际寄存器地址为 `14dd<0x40+i+0x1E>`，如单位 id 在 `14dd42`，其等级字段在 `14dd60`。

### 3.3 验证：`[K-0xF0, K]` 内所有行偏移是否均为 0x1E 倍数（本次记录，**方法待复核**）

**假设**：每条已标注单位行 K，其前方寄存器落在 `[K-0xF0, K]` 内的所有行，与 K 的寄存器差均为 0x1E 的倍数（即这些行 = `K-0xF0 + n·0x1E`）。

**实测（`K = 全寄存器值`，如 0x14dd41；窗口按 `K-R ∈ (0, 0xF0]` 向上收集）**：
- 1791 条标注行中，**仅 127 条**完全满足（窗口内所有行差都是 0x1E 倍数）；**1664 条**存在非 0x1E 倍数的行。
- 出现过的偏移里确有一批 **0x1E 倍数列**（`0x3c/0x5a/0x78/0x96/0xb4/0xd2/0xf0`），但**同时存在大量非倍数**：
  - **“列+1”字段**：`0x3d/0x5b/0x79/0x97/0xb5/0xd3`；
  - **相邻单位寄存器（±1）**：`0x01/0x02/…`（单位寄存器彼此 +1，非 0x1E 间距）。

> ⚠️ **结论待复核**：该“全为 0x1E 倍数”之说只在**寄存器列子集**上成立，不是窗口内全部行。
> 但**怀疑本次验证方法本身有问题**（`K` 与窗口口径、是否含“列+1/相邻单位”行、0x1E 步进的真实范围等），
> 故本条为**暂定结论**，待用更贴合结构的方法（如仅按“寄存器列”或按槽结构定位、明确排除中间字段）重新校验后再修正。

## 5. 统计 / 边界

- 关卡名：`src/*STINIT.txt`（base + `$1$–$5$`）共 **655 处** `eq ... b222`，按 `0x121e2+mapNo` 全部命中（0 缺失）。
- 单位名：**以“寄存器闭区间 `14dd41..14dd5d` 且解析成功”** 标注，合计 **1791 处**（分文件 base 1205 / $3$ 247 / $2$ 125 / $1$ 92 / $5$ 83 / $4$ 39）；幂等；并清理区间外的历史误标（`<0x41` 计数器、`>0x5d` 伴随/率字段）。
- **边界/待复核**：
  - 上界 `0x5d` 是为排除伴随/率字段（`0x5e..0x7b`，其小值可命中名字）而设；若有单位 id 寄存器确实落在 `0x5e..0x7b`，则会被漏标——需按“是否为单位槽（有 +0x1E/+0x3C/+0x5A 伴随且 id 为实际单位）”再判定。
  - `+0x1E`（等级）已确认；`+0x3C`、`+0x5A` 语义未定；**前部 `14dc` 计数器列的结构已确认（等差 +0x1E）但语义未定**，均需对读取函数交叉验证。
- 关卡名与单位名均取自 `src/*STINIT2.txt`、`src/*EBINIT.txt` 的 `日文|中文`，与汉化一致；未汉化项（`|` 后半为空或同值）回退为日文名。

## 6. 脚本说明

| 脚本 | 说明 |
|---|---|
| `scripts/annotate-stinit-maps.js` | 识别 `eq (local-int 0) (global-int b222) <mapNo>`，行尾注释 `// 关卡名`；基址 `NAME_BASE=0x121e2`；剥旧注释再追加（幂等）；支持 `--dry-run`。 |
| `scripts/annotate-stinit-units.js` | 标注 `mov 14ddXX`（`XX∈[0x41,0x5d]` 且 `0x17ab6+unitId` 可解析）为单位 id，注释单位 id 行；基址 `UNIT_BASE=0x17ab6`；幂等，并清理区间外误标（`mov 14ddXX // …` 且 XX 落区间外）；支持 `--dry-run`。 |

> 均只读工程 `src/`，注释为行尾 `//`（不改行号），可供 `assemble` 编译（注释被忽略）。
